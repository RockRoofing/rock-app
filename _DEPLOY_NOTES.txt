WHY IT WASN'T SENDING
  The most likely cause: the design emails used a different "from" address env var
  (NOTIFY_FROM_EMAIL) than the rest of the app. Every other working email uses
  FORMS_FROM_EMAIL - the address whose domain is verified in Resend. If NOTIFY_FROM_EMAIL
  was unset or pointed at an unverified domain, Resend rejects every send. This package
  switches the design emails to use FORMS_FROM_EMAIL first, exactly like the working
  Portal-login email.

HOW TO CONFIRM (do this first after deploying)
  Log in as an admin and visit:
     https://app.rockroofing.co.uk/api/design-email-test?to=YOUR_EMAIL@rockroofing.co.uk
  It returns a small JSON showing:
     - hasResendKey: true/false   (is RESEND_API_KEY set?)
     - which FROM address it used
     - sent: true/false, and the exact error if it failed
  This tells us definitively whether email works and, if not, why (e.g. "domain not
  verified", "invalid from"). Send me that JSON if it still fails.
