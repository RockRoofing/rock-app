WHY THE AFA DISAGREED WITH THE TRACKER
---------------------------------------
This page computed it as contractValue + instructedVars and nothing else - a
FOURTH implementation of a rule that already lives in dashboard.js. It ignored
both the sent application and the manual override, so it was always going to
differ.

It now uses the same order as the Retention Tracker, importing the same shared
computeApplicationSummary rather than working it out again:

  latest SENT application  ->  manual override  ->  project details

The card's sub-line names the source, so you can see which applies at a glance.

THE THREE CARDS
---------------
  AFA
    Now the ANTICIPATED FINAL ACCOUNT: measured contract sum plus variations at
    final value. What the job is expected to finish at.

  Application total inc. retention   (was "Invoiced Inc. Retention")
    Cumulative gross certified on the latest sent application - measured to date
    plus variations to date plus materials on site. Gross of MCD, including
    retention. What has been applied for, not what has been invoiced.

  Remaining to apply for             (was "Remaining to Invoice")
    AFA less the application total. Gross. What is left of the final account
    still to be certified.

These are genuinely different things and the old card conflated them. On a job
with 520,000 measured contract sum and 60,000 of final variations, certified to
437,000: AFA reads 580,000, application total 437,000, remaining to apply for
143,000. Before, the AFA card would have shown the certified figure.

WHAT TO CHECK
-------------
Open the project you spotted the mismatch on. The AFA on this page and the Gross
AFA on the Retention Tracker should now be the same number, and both should name
the same source underneath.
