pkg405 - projects added via Add Project were invisible to two dashboards
========================================================================

Deploy after pkg404.

CHANGED FILES (replace)
-----------------------
  pages/crm.js
  lib/crmMilestones.js
  lib/crmValueChanges.js

NEW FILES: none.


YOUR TWO CATCHES - BOTH RIGHT, BOTH THE SAME ROOT CAUSE
--------------------------------------------------------
createProject wrote exactly one history entry:

    { type: 'note', text: 'Project created' }

No stage entry. No value entry. Everything the dashboards derive comes from history, so:

  TENDERS RECEIVED   needs a move INTO Received. A project MOVED there records one and
                     works. A project CREATED there has no move to find, so it never
                     appeared. Exactly as you described.

  PROJECTS PRICED    needs a value entry. A price typed into the Add Project form was
                     stored on the deal but never recorded as having been SET, so only
                     later EDITS were ever counted.

FIXED: creating a project now writes the stage it was created into, and - where a price
was entered - the value being set from zero. Both in the same shape a later edit produces,
so the derivations treat them identically. No special cases downstream.

Tested:
    created AT Received, £180k    -> Tenders Received: yes. Projects Priced: yes.
                                     Deals Researched: NO - it was never researched.
    created at Project In, no value -> Deals Researched: yes. Priced: no. Received: no.


A BUG THIS FIX INTRODUCED, CAUGHT ON THE BENCH
-----------------------------------------------
Creating a project straight into MC Secured with a value wrote BOTH entries at the same
instant. The "has this money already been counted" guard compares against the last value
logged - and with the stage entry sorted first it had nothing to compare against, so the
same £250,000 was counted twice. £500k reported for a £250k job.

Value entries now sort before stage entries when the timestamps are equal. Re-tested:
every combination of creation stage and value now produces exactly ONE entry.


YOUR THIRD QUESTION - past data for Projects Priced
----------------------------------------------------
No, and there is nowhere to get it. The import carries each deal's CURRENT value and
nothing about when it was set - there is no first-value date in the export.

The only historical source is the Pipedrive-era archive the webhook recorded, which you
seeded into crm:value-changes. That covers the period the webhook was running and nothing
before it. Anything earlier is not recoverable.


AND YOUR FIRST QUESTION - Deals Researched and status
-------------------------------------------------------
Yes: open, won AND lost are all counted. There is no status filter anywhere in that path -
not in the derivation, not on the dashboard, not on the scorecard card.

That is deliberate and I believe correct: a deal researched in May and lost in July was
still researched in May. The research happened. Say the word if you want it otherwise.
