1. DESCRIPTIONS NOW SAY APPLICATION, NOT INVOICED
--------------------------------------------------
Retention Owed hover:
  "Retention still held: APPLIED FOR, gross less MCD with retention included,
   x retention %, LESS any half already claimed back through an application's
   Retention section. Falls back to invoiced only where a project has no
   application."

2. ACCOUNT REMAINING WORKS OFF THE APPLICATION
-----------------------------------------------
It was Final Account minus INVOICED, which answers a different question.
Invoicing lags the application by weeks, so a project that had applied for
everything still read as having value left to claim purely because the invoice
had not gone out.

Now Final Account minus APPLIED FOR, falling back to invoiced only where there
is no application - the same rule the retention figures use. Both the column
header and the "Remaining to Claim" card tooltip updated to match.

3. THE OUTSTANDING CARD NETS OFF 612
-------------------------------------
Retention Owed is what the applications say is held. Account 612 is where a
release lands when it is actually paid. A half already received is not still
outstanding.

Card is now: total Retention Owed less total 612 Released, Live and Defects
Liability only. Floored at zero per project, so a row where 612 exceeds owed
cannot pull the total down.

  J244 Waungron   live      owed 12,455   612     0  -> 12,455
  J197 Hollis     defects   owed  8,200   612 4,100  ->  4,100
  J147 Lancaster  defects   owed  3,400   612 3,400  ->      0
  J092 Old job    complete  excluded from both
  card                      was 24,055    now 16,555

Bookkeeping embeds this register with ?embed=1, and the embed hides the whole

It now appears on its own line above the register in the embed, with the same
