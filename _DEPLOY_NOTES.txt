TWO STRUCTURAL CHANGES WORTH KNOWING
------------------------------------
1. cm-project-financials.js built its Redis connection at MODULE SCOPE - once,
   when the file was first imported, outside any request. It is now built
   inside the handler, per request. Checked: nothing outside the handler
   referenced it (0 references before the handler, 7 inside), so this is
   mechanical.

   This matters for multi-tenancy. A connection made at import time is made
   before any request exists, so there is no tenant to resolve against. Every
   one of these has to move inside the handler before tenancy goes in.
   That is now two found (this and crmGpSnapshots.js in pkg845).

2. lib/outstandingInvoicesReport.js called getRedis() in six separate places.
   All six now call getClient(). The helper functions take no client argument,
   so nothing is threaded through - each gets its own.
