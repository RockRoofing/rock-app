1. A COMMENT ON EVERY CELL
--------------------------
Every month cell now carries a small dot on its right - filled amber when there
is a comment, a faint outline when there is not, so an empty cell offers
somewhere to click without shouting.

Click it to write a comment. The cell then shows it on hover, anywhere on the
cell. Clearing the box removes the comment and the dot goes hollow again.

Works on BOTH kinds of month cell - a month switched to Actual and a forecast
month. On an actual cell the figure itself still opens the transaction drill-down;
the dot is a separate target, so commenting does not fight the drill.

The editor is a modal: Escape and the x close it, a backdrop click does NOT, per
the standing rule - a stray click must not discard something typed.

STORAGE. config:overhead-cell-comments, a FLAT map keyed "<accountCode>|<YYYY-MM>":

    { "310|2026-04": "Includes annual insurance renewal",
      "400|2026-07": "Van lease uplift" }

Flat rather than nested per account on purpose: writing one comment does not
involve reading and rewriting that account's whole set, so two people commenting
at the same time cannot lose each other's work. An empty comment is DELETED
rather than stored as "", so a cleared comment stops counting as one.


2. NEW COLUMN: FORECASTED ACTUAL
--------------------------------
Between Full-yr budget and Tracking (yr), on every row and the TOTAL.

Actual for the months switched to Actual, plus forecast (or budget) for every
month still to come. The figure was already computed as `projectedYear` purely to
produce Tracking, but only the VARIANCE was shown - so you saw +800 with no sight
of the 48,800 it came from:

    Budget to date     20,000
    Actual to date     20,500
    Full-yr budget     48,000
    Forecasted actual  48,800    <- new
    Tracking (yr)        +800

The TOTAL uses totals.projectedYear, the same figure the Lock forecast prompt
quotes, so column, total and lock agree by construction.

ON THE PDF - READ THIS BEFORE I BUILD IT
----------------------------------------
The comments are stored and ready for one. But hover text on a PDF is not
reliable: PDF annotations show on hover in Acrobat, and NOT in Chrome's built-in
viewer or on most phones. If whoever you send it to opens it in Chrome, hovering
gives them nothing.

So for the PDF I would PRINT the comments rather than hide them - most likely a
numbered marker in the cell and the comments listed underneath the table, which
survives any viewer and prints on paper. Tell me if you would rather have them as
hover annotations anyway and I will do both, hover plus a printed list as the
fallback.
