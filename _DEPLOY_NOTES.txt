pkg746 - Bibby: customers were never resolved
==============================================

DEPLOY OVER pkg745 (contains 742-745). Four files.

REPLACE:
  pages/api/business-financials.js
  pages/business-financials/cashflow.js
  pages/business-financials/monthly.js
  pages/business-financials/invoice-finance.js

WHAT WAS WRONG
--------------
Every row read "(no customer)" and the project showed as "L:J248" - the raw key,
not the job number. With no customer name, limits[cust] finds nothing, insured
resolves to 0, and the rule "no limit recorded means none of it is insurable"
disapproves the lot. Hence 1,367,621 applied for, 1,367,621 over insured limit,
£0 advance.

The insured limit list was never the problem. The names never arrived.

WHY
---
dashByNo and dashCustByNo were built from dashboard:cache alone. That key has a
four-hour TTL, so when it is cold every forecast comes back with a blank
projectName and a blank customer.

The Forecast P&L shows "J248-Renshaw House" from the SAME payload, because it
happened to load while the cache was warm. Your whole Bibby funding position
depended on whether somebody had opened the Dashboard recently.

Same class of fault as the receivables source flip - I fixed that one earlier
today and left the project labels sitting on the same cache.

THE FIX
-------
A persistent index, config:project-index. Seeded from the store, overlaid with
the cache when warm, written back afterwards. Names now survive the TTL.

AND, so this cannot hide again: a blank customer is no longer reported as an
uninsured one. A red banner says how many applications and how much value have
no customer attached, and states plainly that it is missing data rather than a
credit decision.
