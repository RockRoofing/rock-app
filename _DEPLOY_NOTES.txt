DEPLOY NOTES - CRM import fix (chunked upload for large files)
=============================================================

TWO files, BOTH EDITS. Replace both in GitHub.

  EDIT  pages/api/crm.js   (adds a chunked import action)
  EDIT  pages/crm.js       (import now uploads in batches + clearer error messages)

WHY
The "Could not read that file" error was misleading. The file WAS being read fine - the
failure was SAVING it: the full 6,850-deal payload exceeded Vercel's ~4.5MB request body limit
in a single POST, and the old code reported that as a read error.

FIX
- Imports now save in batches of 500 rows (14 small requests for the deals file) instead of one
  huge request, so the body limit is never hit.
- Error messages are now split by step, so you can tell read vs map vs save failures apart:
    * "Could not read that file..."  -> the .xlsx/.csv itself could not be parsed
    * "Could not map that file..."   -> parsed, but unexpected columns
    * "Saving failed (...)"          -> a save request failed (shows the real reason)
- If a save fails partway, just re-run the import - it restarts the set cleanly (the first
  chunk wipes and re-seeds), so no duplicates or half-states.

Behaviour is otherwise unchanged: still wipe & replace per set (deals / companies / contacts),
still auto-detects the file type, still .xlsx or .csv.

AFTER DEPLOY: retry the import. Upload the .xlsx exports as before. You'll now see a
"Saving X of Y..." progress message as each batch goes up.

NO vercel.json change. No cron. BUILD: Compiled successfully.
