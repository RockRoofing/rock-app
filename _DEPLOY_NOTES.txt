YOUR HUNCH WAS CORRECT
-----------------------
The activity was never being written to the deal. The Activities tab was innocent all
along - I had been looking at the wrong end of it.

There were TWO separate save faults. pkg323 fixed the first (the payload growing past the
request limit and failing silently). This is the second, and it is the one that would still
have been biting you.


THE RACE
--------
Opening a deal kicks off a background fetch of that deal's imported activities and notes.
When it returns, it merges them in - and it used to suppress the save that would otherwise
follow, since there was nothing new worth writing.

But saves are debounced by 800ms, and that suppression cancels anything already pending.
So if you opened a deal and added an activity while the fetch was still in flight:

    1. your activity     -> save scheduled, 800ms
    2. fetch resolves    -> merge suppresses saving, and in doing so CANCELS your
                            pending save
    3. nothing is ever written

Reproduced it in isolation: old behaviour saves nothing, new behaviour saves your change.

Adding an activity is exactly when this happens, because you open a deal and go straight
to it - inside the window while the fetch is still running.

FIXED by letting that merge save normally. It is harmless now: pkg323 already strips
imported records before saving, so the merge adds nothing to the payload - it just carries
your change along with it.


WHAT TO EXPECT
--------------
Add an activity inside a deal, wait a second for "Saved", then reload. It should still be
there, and it should appear in the Activities tab.

If a save ever does fail now, the badge in the header turns red and tells you, rather than
claiming "Saved" - that came in with pkg323 and stays.

The "Where are my activities?" breakdown from pkg324 is still there too. If anything is
still missing, open it and send me the numbers - but I expect this was the cause.
