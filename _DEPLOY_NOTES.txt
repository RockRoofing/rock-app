THE BUG
  The Planner blocked operatives from being added even when their CSCS / Working at
  Height were in date. Cause: an ID mismatch. The planner's operatives come from Site
  App Users, but the H&S Training Matrix stored certificates under the OLD operatives-
  roster IDs. So the competency lookup found nothing and reported "no CSCS/WAH" for
  everyone.

FIX
  Site App Users are now the single source of truth for people across the H&S portal:
   - The H&S Training Matrix builds its operative rows from Site App Users (ids now
     match the planner and /api/operatives). Office/portal users still appear too.
   - Existing certificates saved under the old roster IDs are BRIDGED by name onto the
     matching Site App User, so historic CSCS/WAH/etc still show and still count for
     planning - no re-entry needed.
   - The competency map (planner gating) and the supervisor dropdown now key off Site
     App User ids.
   - The monthly H&S expiry email resolves names from Site App Users too.

AFTER DEPLOY
  Operatives with in-date CSCS + Working at Height can be added to the planner again.
  If any historic cert doesn't appear for someone, it means their old roster name
  didn't exactly match their Site App User name - just re-enter that cert on the matrix
  (it'll then save under the correct id).
