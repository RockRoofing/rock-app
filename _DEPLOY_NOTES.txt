1. IHM - percentage to 2dp
--------------------------
Number field, step 0.01, 0 to 100, with a % beside it. Enter 2.50 and it stays 2.50.

Only a nonsense value is rejected on finalise - negative, or over 100. Those are typos and
they would quietly distort every Final Account on the project. Blank is fine.


2. AUTO-POPULATES EDIT PROJECT DETAILS
--------------------------------------
The Commercial MCD box now fills itself from the IHM, and says so in green underneath:
"From the Internal Handover Minutes."

Type over it and yours wins. Exactly the same override -> IHM -> stored chain that
retention already uses.


3. DEFAULTS TO 0% - AND SO IT NEVER FLAGS
-------------------------------------------
Nothing recorded is treated as no discount. Final Account equals the gross, nothing is
deducted, and MCD is NOT part of the "project details incomplete" check on either the
Retention page or Project Financials.

I have to be straight with you about one thing here, because you asked for two things
that cannot both be true.

You asked for MCD to be mandatory and to flag as incomplete, AND for it to default to 0%
so it never flags. A default means there is always a value, so there is never anything to
flag - the two cancel out. I have built the default, because that was the last thing you
said and it is the one that keeps the register quiet.

The cost of that choice: a project where somebody simply forgot to ask about the discount
is indistinguishable from one that genuinely has none. Both read 0.00%. If a 2.5% MCD is
missed on a £500k job, the Final Account is £12,500 too high and nothing anywhere will
tell you.

The retention register does what it can about this without nagging: an MCD that nobody set
shows "0.00% (default)" in pale grey, where one that was actually entered shows "0.00%" in
normal grey. Same number, and you can see which is which if you look.

If you would rather it DID flag when nobody has recorded one, say so - it is one line in
lib/projectComplete.js and I will add it.
