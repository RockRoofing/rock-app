DEPLOY NOTES - FIX: deleted invoices lingering in the app (stale sync)
=====================================================================

ONE file, an EDIT - just replace it.
  pages/api/sync-invoices.js

THE PROBLEM (confirmed with your data)
  INV-1721 "TEST" (Ł1,200) showed in the app but had been DELETED in Xero. Re-syncing
  didn't clear it. Root cause: when merging freshly-synced invoices with previously
  stored ones, the old code kept every stored line whose date was before the sync
  window OR had no date at all:
        existing.filter(l => !l.date || l.date < winStr)
  A deleted invoice is simply absent from Xero's response, so it was never overwritten;
  and because the stale line had a missing or odd date, the "!l.date" clause kept it
  alive on every single sync - forever.

THE FIX
  1. Old lines are now kept ONLY if they are genuinely dated AND before the sync window.
     Anything inside the window (or undated) is taken fresh from Xero each run, so a
     deleted/voided invoice disappears on the next sync.
  2. Every project that already has stored invoice lines is reconciled even if it has
     no fresh invoices this run - so a project whose only invoice was deleted still gets
     cleaned up (previously it was skipped entirely).

AFTER DEPLOY
  Run the invoice sync once. INV-1721 (and any other deleted invoices) will drop out.
  The app's outstanding total should then reconcile to Xero.
