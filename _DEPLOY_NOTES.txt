pkg332 - Notes unified too: one store per type
===============================================

REPLACES pkg302 through pkg331. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js
  pages/api/crm.js
  lib/crmImportMap.js     unchanged since pkg305


WHERE EVERYTHING LIVES NOW
---------------------------
  Deals          crm:deals                  imported and CRM-created together
  Organisations  crm:orgs                   together
  Contacts       crm:contacts               together
  Activities     crm:activities:<dealId>    together   (pkg331)
  Notes          crm:notes:<dealId>         together   (this package)

No type is split across two stores any more.


ONE THING THAT WAS NOT AS I EXPECTED
--------------------------------------
A note written in the CRM was never in a "notes" list at all - it is a HISTORY entry of
type 'note' on the deal. Imported notes were in their own store and got injected into the
history for display. Same two-stores problem as activities, but wearing a different hat.

So the fix had to move history entries of type 'note' - and only those. Stage moves, field
edits and activity events stay on the deal, where they belong.

CAREFULLY PRESERVED: a CRM note keeps its own id when it moves, so the comments on it and
any edits still match up. Verified by round-tripping a note with a comment through the
store and back - imported note preserved, CRM note returned with its comment intact.


MIGRATION - AUTOMATIC
---------------------
Existing notes move across the first time each deal is saved, exactly as activities did.
Nothing disappears in the meantime.


WHAT THIS BUYS YOU
------------------
Notes were not causing trouble yet only because there is no Notes tab to expose the seam.
The moment you want one - or search across notes, which you will - it would have behaved
exactly as activities did over the last dozen packages. This closes it before that.


STILL ON THE LIST
-----------------
The remaining structural issue is SIZE, not splitting: crm:deals is 6.4MB and is read in
full on every page load. Saving is fine now it only sends what changed, but load time will
keep creeping up as projects are added. The fix is to stop sending every field of every
deal to the board. Worth doing as its own piece before it becomes the next thing you are
chasing.
