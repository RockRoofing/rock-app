THE CHANGE
===========
+ Add Calculation now asks first:

    Do you want to send this for approval?

      No - just upload it
        Held on the project. Nobody is emailed and it shows as "Not issued".
        You can send it for approval later.

      Yes - send for approval
        Goes to the customer you choose, and they are emailed.

The approver dropdown only appears once you answer Yes, and the Choose file button
stays disabled until the question is answered - a default here is a default that
issues documents to customers by accident.

Same question on Mark superseded, which also forces a new revision.


SENDING IT LATER
-----------------
A held calculation carries a "Send for approval" action on its row. Tick several
and a "Send N for approval" button appears in the toolbar. Either way you choose the
approver, and from that point it behaves exactly as an upload-and-issue would have:
status moves to In Review and the approver is emailed.


WHY IT NEEDED A NEW STATE RATHER THAN JUST A BLANK APPROVER
-------------------------------------------------------------
The API already tolerated an upload with no approver - it just never emailed anyone.
But the document was still written as status 'in-review', so a wind load calc you
only wanted on the project sat there reading "In Review" and telling the customer's
side "Awaiting customer approval", when it had not been sent to a soul.

There are three states, so there are now three:

    held        uploaded, not issued, nobody emailed        "Not issued"
    in-review   with the approver, who has been emailed     "In Review"
    approved    signed off                                  "Approved"

Held documents are excluded from the "needs approval" count and from the
"Awaiting customer approval" line, because neither is true of them.


TWO THINGS GUARDED
-------------------
SEND-FOR-APPROVAL ONLY MOVES HELD DOCUMENTS. An approved one must not be quietly
pulled back into review, and one already in review would email the approver a
second time. Both are refused, by name.

THE BULK "NOTIFY PROJECT USERS" ACTION NO LONGER SWEEPS THEM UP. It assigned an
approver to every document that did not have one, which would have issued a held
calculation as a side effect of notifying somebody about something else.

Verified across the lot:

    held + approver chosen    -> in-review, approver set, emailed
    held, no approver         -> refused
    already in review         -> refused, no second email
    already approved          -> refused, not pulled back
    superseded                -> refused
    upload answering No       -> held, no approver, nothing emailed
    upload answering Yes      -> in-review, approver set, emailed

WORTH KNOWING
--------------
Existing calculations are untouched and keep their current status. Only new uploads
can be held. If you have old ones sitting in review that were never actually sent,
they will keep saying In Review - there is no way to tell those apart from genuine
ones in the data, so I have not tried to guess. Upload a new revision, or leave them.

The same pattern would suit the other design pages - drawings, tech submittals,
warranties, leak test certs - which all issue on upload in the same way. Say the
word and they get the same question.
