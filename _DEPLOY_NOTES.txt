WHAT YOU FOUND
===============
"When I click the applied for value ALL projects have the same message."

That is the answer to why pkg800, 802 and 803 each fixed something real and none of
them fixed your two projects. The diagnostic I built to settle this was returning
nothing, on every row, and saying so in a way that read like a finding.

A tracker row is built TWICE in pages/retention.js:

  ~line 549   from a project that has no saved entry
  ~line 730   by merging a saved entry with live dashboard data

appliedForDetail, certifiedSetOnApp, mcdBasis, afaFromApp and all four stamp fields
were added to the MERGE ONLY. Any row without a saved entry - which is most of them -
received none of it. So the drill-down reported "No application data for this
project" on projects with sent applications, and I read that as information.

Both builders now share one function, dashFields(), so a field added for one is
present on the other. This is the same fault class as everything else this session:
one rule written twice and left to drift.


A SECOND, REAL BUG FALLS OUT OF THE SAME FIX
----------------------------------------------
The project-derived builder tested `p.certifiedGross ? ... : ''` - truthy, not set.

entry whose latest sent application is its first, Certified was blank instead of
0.00. Both paths now test certifiedSetOnApp.
