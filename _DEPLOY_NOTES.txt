pkg464 - "read full email" actually reads the full email
========================================================

Deploy after pkg463. One changed file: pages/crm.js. No new files.
pkg463 must be in first - it added the fetch this now calls.


MY MISTAKE IN pkg463
--------------------
The fetch was built and wired correctly. It just never ran.

I only triggered it when the stored preview looked truncated at 400 characters:

    const maybeTruncated = preview.length >= 380

Microsoft caps bodyPreview at 255. It can never reach 380, so the condition was never
true and "more" carried on showing the same short extract. The 400-character slice I was
guarding against had never been doing the truncating either - Graph had already done it.

I should have checked what bodyPreview actually returns rather than assuming my own cap
was the limiting one.


FIXED - NO GUESSING FROM LENGTH
---------------------------------
The stored preview is Graph's SUMMARY of an email, never the email. So if we can fetch the
body, we offer to - the button now reads "read full email" and always works.

Press it and you get the whole thing, fetched from Outlook and kept for as long as the
page is open. Works the same in the Emails tab and on a deal's timeline.

Also fixed: an email whose preview came back EMPTY rendered no body block at all, so there
was nothing to click. It now shows the button with "No preview stored - press below to
read it."

Older records with no mailbox saved against them keep the old behaviour, since there is
nothing to fetch with.


ON YOUR WIDER POINT
-------------------
You are right that if reading mail in the CRM is a main feature, fetching one email at a
time is the wrong shape. It needs Outlook reachable, it is a request per email, and the
bodies cannot be searched - so "find the email where they agreed the price" still means
going to Outlook.

The alternative is storing bodies at sync time: instant, searchable, offline. It costs
storage and needs a re-run over the mail already filed.

Worth deciding once you have used this for a few days. If people are genuinely reading
mail here rather than glancing at it, storing them is the right answer and I will do it
properly.
