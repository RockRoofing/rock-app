THE 612 FAULT, FOR THE RECORD
-----------------------------
The App 2 credit note carries one Xero allocation. It resolves to a document that
cannot be the reversal - its 612 line is the same way up as the credit note's. The
pairing code read:

    const byRef = byAlloc.length ? [] : (...)

so the moment the allocation resolved to ANYTHING, the reference fallback was
switched off - even though the allocation candidate was rejected two lines later by
the sign guard. Nothing was cancelled and both columns stayed 642.20 high.

pkg790's fallback was never wrong. It never ran.

Reproduced on J147's real ten lines before the fix was written: with the fallback
suppressed it returns exactly 1,760.38 / 1,760.39; with it always running,
1,118.18 / 1,118.19.

--------------------------------------------------
