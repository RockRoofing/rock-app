THE CRASH
---------
The new "not in the forecast" banner reads retEvents to report retention releases
with no date. But retEvents was declared INSIDE the forecast useMemo - line 285 -
and the banner renders at line 592, outside it.

A const declared inside a hook is invisible to the JSX. It compiles perfectly and
throws ReferenceError on the first render, taking the page down. Same class of
fault as the gbp() one that took the Retention Tracker down: an undefined
identifier passes the build and only shows at runtime.

retEvents is now declared at component scope, above the forecast memo, so both
the calculation and the banner can see it.

I swept the whole file for the same pattern - anything declared inside a useMemo
and referenced in the JSX. Two more flagged, both false positives ('flex-end' in a
CSS value and finance.vatRate as a property). retEvents was the only real one.

ALSO FIXED WHILE THERE: the forecast memo reads finance.vatRate for the VAT
reclaim estimate but did not list `finance` in its dependencies, so it would have
kept a stale rate until something else happened to change. `manualBal` added for
the same reason.
