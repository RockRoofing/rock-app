NEW FILES: none.


THE CODE WAS ALREADY THERE - IT COULD NEVER FIRE
--------------------------------------------------
applicationPdf.js already generates a variation document for anything instructed and
appends it. The test it uses is:

    v.instructed !== 'yes' || !v.builder

But BOTH functions that prepare variations for an application rebuilt them field by field
and threw away exactly those two things:

    instructed: !!v.instructed     ->  true, not 'yes'
    builder                        ->  dropped entirely

So the condition failed twice over, and no document was ever generated. Nothing was wrong
with the variations or the instructions - the application was being handed a stripped copy.

Both now keep the builder block and 'yes'/'no' as written.


THE SECOND ONE WAS WORSE
------------------------
buildAppVariations is what gets FROZEN onto an application when it is sent. A sent
application kept a variation with no builder and no proper instructed flag - so its
document and its digital instruction could never be reproduced, even after this fix.

Applications already sent will still carry the stripped copy. Anything sent from here
carries the lot.


AND THREE PLACES THAT WOULD HAVE GONE WRONG
---------------------------------------------
Making instructed a string breaks every truthiness test on it, because !!'no' is TRUE:

    Contracted Rates view
    Project Report
    Applications page

All three would have shown EVERY variation as instructed. Fixed with the same explicit
test. No others remain in the codebase.
