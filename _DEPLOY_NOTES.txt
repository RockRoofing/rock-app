TWO THINGS I FOUND WHILE REMOVING IT
------------------------------------
1. THE PLANNING GANTT WAS READING PIPEDRIVE.
   pages/api/planning.js and planning-week.js pulled negotiated projects from the
   Pipedrive cache - the "N:<dealId>" rows on the Gantt and on the Weekly Labour
   Allocation. Deleting the sync would have frozen those, and eventually emptied them.
   Both now read the CRM.

   IMPORTANT AND CHECKED: CRM deals keep Pipedrive's original ID (the import maps
   "Deal - ID" straight through). So every existing N:<dealId> allocation still resolves
   to the same project. No planning data is lost.

2. HEALTH-CHECK WOULD HAVE EMAILED YOU A FALSE ALARM.
   It checked the Pipedrive sync had run in the last 25 hours and emailed an alert if not.
   With the sync gone it would have judged itself unhealthy on EVERY call and mailed
   ALERT_EMAIL each time. Rewritten as a plain liveness endpoint.
