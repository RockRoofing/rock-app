  instructed variations sum to        65,011.42

Projected Final Account 169,679.70 -> 140,274.20.

THE TEST WAS WRONG IN A SUBTLE WAY
-----------------------------------
lib/applications.js filtered with `v.instructed !== false`. That admits anything
except a literal false - undefined, null, a missing field. V12's flag was not set
to false; it simply was not set. So it counted as instructed.

MY FIRST FIX WAS ALSO WRONG. I changed it to a plain truthy test, matching the
ten other call sites. But `instructed` is a BOOLEAN on records written by the
current UI and the STRING 'yes'/'no' on older ones - and 'no' is truthy. That
would have counted every uninstructed variation on an older record.

  value      correct   !== false said   truthy said
  true       yes       yes              yes
  'yes'      yes       yes              yes
  false      no        no               no
  'no'       NO        YES  wrong       YES  wrong
  missing    NO        YES  wrong       no
  null       NO        YES  wrong       no

The right test is `v.instructed === true || v.instructed === 'yes'`. It is now a
single exported isInstructed() used by both the summary and the PDF.

THIS WAS ALREADY FOUND ONCE
----------------------------
lib/applicationPdf.js had the identical fix, with a comment saying the loose test
was "certifying every UNINSTRUCTED variation as instructed - a real figure on a
document going to the customer". It was fixed in the PDF and never in the shared
library the on-screen summary uses. Two copies of one rule; one got corrected.

They are now one definition, imported.
