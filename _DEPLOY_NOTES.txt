THE FAULT
==========
The Variation Description in the header block was drawn as a single line with
page.drawText, which does not wrap. Anything longer than the column ran straight
through the divider and over "Requested by", exactly as your screenshot shows.

The item descriptions had the opposite problem and it was worse: they were CUT to
fit, with

    while (t && f.widthOfTextAtSize(t, size) > w - 5) t = t.slice(0, -1)

so the end of a long description was silently thrown away. No ellipsis, no sign
anything was missing. A customer reading a priced variation would simply never see
the rest of it.

The clarifications block was the only part of the file that wrapped correctly.


THE FIX
========
One wrapToWidth() helper, used by all three.

  HEADER   The box now grows to fit the text rather than the text running out of
           the box. Labels stay on the first line, values flow beneath, and the
           divider between the two columns is drawn to the new height.

  ITEMS    The description wraps and the ROW grows with it. Quantity, Unit, Rate
           and Total stay on the first line. The page break is measured against
           that row's actual height, so a tall row cannot start too near the bottom
           and run off the page.

  NARROW   Quantity and Unit are too narrow to wrap into, so they still clip - but
  COLUMNS  now end in an ellipsis, so a clipped value looks clipped instead of
           looking complete.

  CLARIF.  Now uses the shared helper instead of its own private copy.

Wrapping is by MEASURED width, not a character count: at 8pt Helvetica "W" and "i"
are nothing like the same width, so a character limit either wastes a third of the
column or overflows it anyway. A single word wider than the column is broken
mid-word, so a long reference or a pasted URL cannot overflow either.
