THE BUG - MINE
--------------
Xero's Overpayment Type is "SPEND-OVERPAYMENT", not plain "SPEND". pkg573 tested

    String(op.Type).toUpperCase() !== 'SPEND'

which rejected every single one, so the fetch ran, succeeded, and returned nothing.
The total stayed at 307,471.06 and looked exactly like a working sync.

Worse: fetchBankTransactions in the same file already does
`bt.Type.startsWith('SPEND')` at line 494, for precisely this reason. The correct
pattern was ten lines up from where I was working.

Now uses startsWith, which also picks up SPEND-PREPAYMENT:

  SPEND-OVERPAYMENT      old: false   new: true
  SPEND-PREPAYMENT       old: false   new: true
  RECEIVE-OVERPAYMENT    old: false   new: false


A SILENT ZERO IS WHY IT WENT UNNOTICED
--------------------------------------
Two things made this invisible, and both are fixed:

1. sync() threw the API response away entirely - `await fetch(...); await load()`
   inside a bare try/catch. A failed sync and a successful one looked identical.
   It now reports next to the button:

     "117 bills, 1 credit notes, 4 overpayments."   green
     "Sync failed."                                  red

2. The overpayment fetch is wrapped in a try/catch that only console.errors, so a
   permissions or endpoint failure returned an empty list silently. It now logs a
   breakdown - how many Xero returned, how many were kept, how many were the wrong
   type, how many were fully allocated.


WHAT YOU SHOULD SEE
-------------------
After Sync bills, the message should read 4 overpayments and the total should drop
from 307,471.06 to 302,771.49.

If it still says 0 overpayments, the fetch itself is failing rather than the
filter - most likely the Xero app is missing a scope for the Overpayments
endpoint. Tell me and I will surface the actual error rather than swallowing it.
