WHY J109 READ ZERO
------------------
Not because it was added manually - because the Ret % you can see and the Ret %
the calculation uses are two different fields.

  the COLUMN shows      e.retentionPct - saved on the tracker row, and it wins
  the CALCULATION uses  settings.retentionPct - held on the PROJECT

J109 has 5% on the tracker row and nothing on the project, so the column said 5%
and Retention Owed said £0.00. Gross AFA reading "-" and MCD "0.00 (default)"
say the same thing: that project record is largely empty.

THE FIX
-------
Where the project has no retention percentage, the row falls back to its own
against its applied-for figure, less anything already claimed back.

  J109   £112,263.79 applied for at 5%   ->   £5,613.19

The project figure still wins wherever it is set, so nothing that was already
right changes. It also handles both forms - project percentages are stored as
fractions (0.05), tracker rows as whole numbers (5).

WHAT YOU SHOULD STILL DO
-------------------------
Set the retention percentage in Project Details on J109. Every other calculation
reads the project record, not the tracker row - the cash flow schedules releases
from it, the WIP figures use it, and the application certificates take it from
there too. This fallback fixes the column you were looking at; it does not make
the rest of the system agree.

If several projects show a Ret % with £0.00 owed, they all have the same gap.
