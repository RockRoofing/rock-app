I HAD THE AUTHENTICATION WRONG
------------------------------
I guessed OAuth2 with a client id and secret. It is not that.

8x8 Work Analytics wants an API KEY HEADER plus the USERNAME AND PASSWORD of a real 8x8
user who has Work Analytics access. Corrected.

    POST https://api.8x8.com/analytics/work/v1/oauth/token
    header  8x8-apikey: {key}
    body    username={8x8 user}&password={their password}

Every report request then sends BOTH the 8x8-apikey header and Authorization: Bearer.
Token lasts 1800 seconds and is cached.


SET THESE IN VERCEL
-------------------
    EIGHTX8_API_KEY     from Admin Console. For Work Analytics the SECRET is NOT needed.
    EIGHTX8_USERNAME    an 8x8 user with Work Analytics access
    EIGHTX8_PASSWORD    that user's password
    EIGHTX8_PBX_ID      the opaque PBX id - NOT the PBX name

Two things from their docs worth knowing before you waste an afternoon:

  - The user whose credentials you use MUST have opened Analytics for Work in a browser
    at least once. Until they have, the API will reject them. If you get a 401, that is
    the first thing to check - the error message now says so.
  - It does not have to be the same person who generated the API key.

I do not know your PBX_ID. It is an opaque string rather than a name, and their docs do
not show a way to list it - it will be in Admin Console or 8x8 can tell you.


THE GOOD NEWS - 8x8 ALREADY DOES "UNRETURNED CALLS"
-----------------------------------------------------
Their docs list it as its own report:

    GET /v2/pbxes/{pbxId}/calls/unreturned

That is very close to what you asked for. It means we do not have to stitch missed inbound
calls to later outbound ones ourselves and guess at matching phone numbers - which would
have been fragile and probably wrong.

Whether it can distinguish "not returned within an hour" from "not returned at all"
depends on what fields it carries. There is a probe for it below.
