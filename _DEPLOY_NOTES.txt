pkg604 - Nothing is broken: the API file was not deployed
==========================================================

*** SUPERSEDES pkg591 - pkg603. ***
*** BOTH FILES. The API one is the whole problem. ***

  pages/api/business-financials.js          <- THIS IS THE MISSING ONE
  pages/business-financials/invoice-finance.js


WHAT HAPPENED
-------------
Your screen is already telling you, in red next to the settings:

    API OLD - not deployed

The page went in; pages/api/business-financials.js did not. Without it, projects
come back with no `invoices` array at all - so the debt for every project is
zero, every customer drops out, and the table says "No applications found".

Nothing is lost. Your data is untouched. Deploy the API file and it returns.


TWO THINGS THAT MADE THIS HARDER THAN IT NEEDED TO BE - BOTH MINE
-----------------------------------------------------------------
1. THE VERSION MARKER WAS LYING ANYWAY. The page hard-coded a check for 'pkg597'
   while the API had moved on to 'pkg599', so it would have read "OLD" even when
   correctly deployed. Worse than no marker.

   Both sides now use ONE constant:
     invoice-finance.js   const EXPECTED_API = 'pkg604'
     business-financials.js   apiVersion: 'pkg604'

   Green "API pkg604" = deployed. Red tells you exactly what it is reporting and
   what to do.

2. "No applications found" WAS THE WRONG MESSAGE. It sent you to check projects
   and syncing when the cause was a missing file. The empty state now says which
   of the three it is:
     - API not deployed  -> deploy the API file (in red)
     - projects but no unpaid invoices -> press Sync invoices from Xero
     - no projects at all -> check projects are synced


ONE THING TO CLEAR AFTER DEPLOYING
----------------------------------
You typed 35069.31 into the High involvement VALUE box, so it now reads
"Overridden - calculated is GBP 0". That was the right move when the calculation
was broken; it is not now.

CLEAR THAT BOX. Leave the % at 35 and the value empty - it calculates from the
approved ledger. Leaving the override in means it will not follow the ledger when
Wates is paid down.


ALSO IN THIS PACKAGE
--------------------
pkg603 - High involvement takes its % of the approved ledger AFTER credit limits,
not before. Only that base reproduces their 35,069.31.

pkg602 - the debt basis is the unpaid INVOICE, not the application. The
application basis gave 1,375,463 because an application that cannot be matched to
an invoice by "App N" counts as unpaid.

With the limits right, the whole chain reconciles to the penny:
  approved ledger 323,029.46 -> HI 35,069.31 -> funding 172,776.09
  -> less drawn 122,711.31 -> availability 50,064.78
