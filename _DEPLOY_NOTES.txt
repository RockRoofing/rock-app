1. THE IMPORT NOW SAVES ITSELF
------------------------------
It only ever STAGED the parsed limits into local React state and asked you to
press Save. Close the tab, or click away, before pressing it and the entire
imported list was gone - with nothing on screen to say so. The import is the slow
part of the job; losing it silently is expensive.

Uploading now writes the limits immediately. Editing and Save still work
afterwards, so the review step is not lost - it just no longer decides whether
the data survives.

If the save fails the message says so plainly and tells you to press Save to
retry, rather than reporting a successful import that did not persist.


2. THE IMPORT DATE
------------------
Stored with the list and shown beside the Import button:

    List imported 29/08/26 14:07

Hovering gives the detail: "142 limits imported, 118 matched a customer, 24 did
not - bibby-limits.csv".

Kept in a SEPARATE Redis key (config:if-limits-meta) rather than folded into the
limits map. That map is a flat { customerName: {...} } and every screen that walks
it would have shown a debtor called "importedAt".


ALSO IN THIS PACKAGE (pkg591/592)
---------------------------------
THE DEBT IS THE INVOICE, the matched application is the evidence of what it
consists of - as you put it. Was: the sum of "this cert (net)" across unpaid
applications, which breaks badly when an application is entered GROSS with
"previously certified" blank. In that state thisCert computes as the FULL
cumulative value: on J240 App 4 that is 92,766.50 of phantom debt, inflating the
funding position by 55,660 at 60%.

Retention invoices excluded (purple chip - detected by "retention" in the
reference, so one raised without that note will NOT be caught). Unmatched
invoices counted as debt but flagged, capped via the project's unpaid
applications. Applied-but-not-invoiced shown grey and not funded.

BIBBY'S THREE CAPS - materials on site 25%, variations 25%, certified ceiling
90% - applied per project BEFORE the advance rate, measured on the cumulative
position, with the 90% ceiling applied LAST so money that is both a variation and
above 90% is not counted twice. All three editable beside the advance rate.
