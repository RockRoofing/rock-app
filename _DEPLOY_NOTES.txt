I COULD NOT FIND IT BY READING
------------------------------
I went through everything I changed on that page today - todayKey moved above the
memos, needsUpdate, the focus filter, the bar click, the stale badge, the prior
selection - and checked each identifier is declared before use and every array
access guarded. All of it compiles and all of it reads correctly. So rather than a
sixth theory, this makes the page tell us.

A production Next build replaces every render error with "a client-side exception
has occurred". That single sentence has now cost us three round trips on three
different pages. There is no good reason the person using the page is the only one
who cannot see what went wrong.

pages/_app.js now wraps every page in an error boundary that shows:

  - the real message, e.g. "Cannot read properties of undefined (reading 'has')"
  - which component it happened in, collapsed under "Where it happened"
  - Try again, and Reload

Deploy this, open the project cash flow, and SEND ME THE RED BOX. That names the
fault outright and I will fix it in one go.

ReportProblemButton deliberately sits OUTSIDE the boundary so it still works on a
page that has failed.

This is worth keeping permanently, not just for today - every future render error
on any page in the portal now identifies itself.
