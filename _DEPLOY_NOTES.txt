1. WHY SOME ROWS DID NOT MATCH THEIR LATEST APPLICATION
--------------------------------------------------------
A typed Applied-for value BEAT the application:

    e.appliedFor !== '' ? e.appliedFor : x.appliedForLatest

So an override entered once sat there for good and every later application was
ignored. That is the mismatch you spotted.

Reversed. The latest SENT application always wins; a typed figure is only used
where a project has no sent application.

The formula was already right - current.netBeforeRet, which is gross measured
works less MCD plus variations, the certificate sub-total. It just was not being
reached.

2. NEW COLUMN: CERTIFIED
-------------------------
Sits between Applied for and Invoiced.

Populated from Previously Certified (gross) on the latest sent application, with
the application number shown underneath. Editable through the row edit form -
the pencil - and the next application sent overwrites whatever was typed, same
rule as Applied for.

Included in the totals row and in the CSV import (column "Certified").

3. THE TICK NOW COMPARES CERTIFIED TO INVOICED
-----------------------------------------------
It compared Applied for against Invoiced. Certified against Invoiced is the
question worth asking - what has been certified but not billed, or billed but
not certified.

4. WARNING ON APPLIED FOR
--------------------------
A small amber triangle appears beside Applied for when it does not agree with
Certified, with the gap in the hover. Usually it means the latest application is
applied for but not yet certified, which is normal - but it is worth seeing
without reading across two columns.

NOTE ON MANUAL OVERRIDES
------------------------
The application now always wins where one exists, which is a blunt reading of
"the next application sent should override the manual input". A typed value on a
project WITH applications will be replaced on the next dashboard rebuild rather
than surviving until the next application arrives. If you want an override to
hold until a genuinely new application is sent, say so - it needs the
application number stamped against the override, which is a small extra field.
