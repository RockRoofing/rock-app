YOU WERE RIGHT - IT IS THE WHOLE AMOUNT
---------------------------------------
Look at what J190 was showing:

    Previously claimed (gross)   0.00      "From the start"
    Gross to date            401,663.50    the WHOLE contract
    Labour this period        79,496.48    the WHOLE labour budget

On a live job with real applications, previously claimed should never be zero.


THE CAUSE - line 954
--------------------
    const priors = editId ? cands.filter(c => !from || (c.end||'') < from) : cands

When EDITING, only certificates ending BEFORE this period's start counted. Your
forecast starts 31/08 and the last application ends after that, so the application
was filtered out entirely. No prior, previously claimed 0, and the whole contract
offered again as this period's work - which is why labour showed the entire budget.

This is the same fault behind the -160k you saw when reverting to Application 1.

The comment directly above that line already said, about NEW forecasts: "money
already claimed is already claimed - it cannot be un-claimed by choosing an earlier
start date." That is just as true when editing. It was only ever the FORECAST chain
that needed sequencing.


THE FIX
-------
A real APPLICATION is never filtered out by the period dates. Only forecasts are
sequenced, so a forecast in the middle of a chain still deducts only what came
before it.

  editing a forecast starting 31/08, App 3 ends 30/09
     before   prior: none          previously claimed 0
     after    prior: App 3         previously claimed = App 3's gross

  editing a mid-chain forecast starting 01/07
     prior: App 3, and a December forecast is still correctly excluded

You will see it worked because the box will read "From App 3" instead of "From the
start", and Labour this period will drop to the increment.
