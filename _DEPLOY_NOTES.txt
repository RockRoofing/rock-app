WHY THE OLD RULE MISSED SO MUCH
-------------------------------
It looked for the WHOLE project title as one unbroken run of characters in the subject.
For "Bensham Lane Phase 2":

    RE: Bensham Lane Phase 2 drawings          matched
    RE: Bensham Lane - drawings for phase 2    MISSED - not contiguous
    Bensham Ln Ph2                             MISSED - abbreviated

That is almost certainly most of your 94%.


WHAT IT DOES NOW
----------------
Words are scored instead of characters, and each word is weighted by how RARE it is across
your project titles. "bensham" is on one project and carries a match on its own. "lane",
"house", "roofing", "works" are on hundreds and barely move the needle. So a subject full
of common construction words does not score - which is the behaviour you want.

Above 70% it files itself, as you asked.


THE ONE THING I ADDED TO YOUR SPEC
----------------------------------
Auto-filing at 70% on score alone is not safe, and it is worth knowing why.

You have "Bensham Lane Phase 1" and "Bensham Lane Phase 2". A subject saying only "Bensham
Lane" scores about the same against BOTH. At a bare 70% threshold it would file into
whichever sorted first - silently, into the wrong job.

So it now files only when the best match is also CLEARLY AHEAD of the runner-up. If two
projects score close together it goes to review instead, however high the score. That is
what makes 70% mean "confident" rather than just "high".

Tested against exactly this case:

    RE: Bensham Lane - drawings for phase 2   -> FILED, Phase 2, 100%
    RE: Bensham Lane drawings phase 1         -> FILED, Phase 1, 100%
    Bensham Lane phase                        -> NOT filed, suggested only
    Roofing works                             -> no match
    Invoice for roofing works ltd             -> no match
    Tesco                                     -> no match

Both numbers are tunable from Vercel without a deploy:

    MS_MATCH_THRESHOLD   default 0.70   score needed to file itself
    MS_MATCH_MARGIN      default 0.12   how far clear of the runner-up it must be

Raise the threshold if you see anything file wrongly. Raise the margin if the wrong ones
are near-identical project names.


SUGGESTIONS IN THE REVIEW QUEUE
-------------------------------
Anything scoring over 45% but not confident enough to file now shows a blue bar on its
queue row:

    Looks like Bensham Lane Phase 2 (63%, next closest Bensham Lane Phase 1)   [Accept]

One click files it. The runner-up is named deliberately - if the two are near-identical
you want to see that before you accept.


SEE EXACTLY WHAT IT WOULD DO - BEFORE THE BACKFILL
---------------------------------------------------
    /api/cron/crm-email-sync?dryRun=1&detail=1&max=200

Writes nothing. Returns every subject line with its outcome - FILED, SUGGESTED or NO
MATCH - plus the project, the score and the runner-up. That is how you judge whether 70%
is the right number, on your real mail, before committing to anything.

Do that first. Then decide the backfill.
