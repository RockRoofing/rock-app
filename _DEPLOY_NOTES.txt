pkg327 - The 413, properly this time
=====================================

REPLACES pkg302 through pkg326. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js
  pages/api/crm.js        unchanged since pkg326
  lib/crmImportMap.js     unchanged since pkg305


WHY pkg326 DID NOT FIX IT
--------------------------
pkg326 sends only the deals that changed - which is right, and would have worked if only
one deal ever differed. But it decided what "changed" meant by comparing against the deals
AS STORED, while sending the CLEANED version (imported activities and notes stripped out).

crm:deals already contains those imported records, written by earlier saves that succeeded
back when the list was small enough to fit. So for every one of those deals the stored copy
and the cleaned copy differ - and the first save tried to send the lot. Straight back to
6.4MB and straight back to 413.

I introduced that mismatch in pkg323 when I started stripping imported records, and did not
join it up with the comparison added in pkg326.


THE FIX - TWO PARTS
-------------------
1. ONE SHARED DEFINITION. There is now a single leanDeal() function used both to build the
   comparison baseline and to build what gets sent. They cannot drift apart again, which is
   what caused this.

2. BATCHED BY MEASURED SIZE. A normal edit changes one deal and sends a few kilobytes. But
   the first save after this deploy legitimately has to rewrite every deal that still holds
   imported records, and that must not go in one request.

   Measured worst case - all 6,860 deals needing a rewrite:

       3 requests, largest 3.00MB, against the 4.5MB Vercel ceiling

   So even the full cleanup gets through. After it, the stored deals match the clean form
   and normal saves are tiny again.


WHAT TO EXPECT
--------------
On the first change you make after deploying, the badge may briefly read "Saving 1 of 3..."
while it writes the cleanup through. That is a one-off. After that it should read "Saved"
in green almost instantly on every change.

Then: add an activity in a deal, reload, and it should still be there and in the Activities
tab.

If it goes red again, send me the status code - but 413 should now be arithmetically
impossible.
