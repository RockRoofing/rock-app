IT IS A FORMULA, NOT A HARD-CODED WATES FIGURE
----------------------------------------------
    hiCap  = approvedDebt x hiPct%
    hiCalc = customers.reduce((t, c) => t + Math.max(0, c.debt - hiCap), 0)

Every customer, every time. Wates only appears in my COMMENTS as the worked
example that solved the percentage - there is no name in the code. Proved across
four scenarios:

  Wates dominant           cap 113,060.31   HI 35,069.31   over: Wates
  Wates paid down,
  Epiphany grows           cap 121,942.45   HI 58,057.55   over: Epiphany
  two debtors over         cap 108,500.00   HI 73,000.00   over: A and B
  ledger evenly spread     cap 112,000.00   HI      0.00   over: none

It follows whoever is over, counts several at once, and returns nil when nobody
is - all off the live ledger.


WHY IT WAS NOT ADDING - MY BUG
------------------------------
pkg594 saved the field with

    highInvolvement: Number(s.highInvolvement) || 0

so Redis already holds a literal 0 on your record. pkg600 then read ANY number as
a deliberate override - so the stored 0 forced High Involvement to nil and the
calculation never ran. It would have looked exactly like "it isn't adding".

Zero now counts as blank, on the way in AND on the way out, so the 0 already
sitting in Redis reads as "use the calculation" without you clearing anything.

Nothing is lost by it: an override of zero and a calculation returning zero give
the same answer, and to switch the deduction off deliberately you set the % to 0.

I also removed a stale comment block still saying the figure "is not derivable
from anything we hold... entered from their screen rather than calculated" -
left over from pkg594 and now the opposite of what the code does.
