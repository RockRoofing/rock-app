WHAT I BROKE, AND WHY IT MATTERS NOW
------------------------------------
I added accounting.transactions.read to the authorize URL. Xero rejects the
ENTIRE authorize request with invalid_scope if ANY single scope is unrecognised -
it does not ignore the bad one and grant the rest.

So /connect currently cannot connect AT ALL. That is worse than a missing
overpayment figure: if the refresh token ever expires you would have no way back
in. This package restores the known-good list first.

I asserted that scope was correct. It was not, for this app, and I should have
given you a way to test it rather than editing the live list.


THE SCOPE TESTER
----------------
The base list is now fixed and no longer edited to try things. /connect has a
small box above the Connect button for ONE EXTRA SCOPE, appended for that attempt
only, with quick buttons for the likely candidates:

  accounting.transactions
  accounting.transactions.read
  accounting.reports.read
  none

If Xero says invalid_scope, that name is wrong - clear the box, connect again,
and you are straight back to a working connection. No deploy needed between
attempts.

TRY accounting.transactions FIRST (no .read). Overpayments are documented under
that scope, and the .read variant is what was just refused.


WHEN ONE IS ACCEPTED
--------------------
Connect with it, then press Sync bills. The message now also prints what the
token actually grants, so there is no ambiguity:

  "117 bills, 1 credit notes, 4 overpayments."                        working
  "... Token HAS accounting.transactions. Granted: <list>"            granted but refused
  "... Token DOES NOT HAVE accounting.transactions. Granted: <list>"  not granted

Send me whichever line you get and I will work from the granted list rather than
guessing again.


ONE THING TO NOTE
-----------------
Every other scope in that list - accounting.invoices.read,
accounting.banktransactions.read, accounting.manualjournals.read,
accounting.reports.profitandloss.read - is accepted by this app and works. So the
app clearly takes fine-grained names. Which specific one covers Overpayments is
what the tester is for.
