pkg860 - Separate the switch from the credentials
=================================================

WHAT SHOULD LOOK DIFFERENT AFTER DEPLOYING THIS:  NOTHING.

DEPLOY THIS BEFORE CREATING THE UPSTASH DATABASE.


NEW FILES TO CREATE BY HAND
---------------------------
None. All four already exist.

  lib/tenants.js
  lib/withTenant.js
  lib/forEachTenant.js
  pages/api/admin/tenant-setup.js


WHY
---
As pkg854 stood, adding CONTROL_REDIS_URL and CONTROL_REDIS_TOKEN would switch
tenant resolution ON at the next deploy. But Rock would not be registered yet -
it cannot be, because registering it requires the app to be able to reach the
control database, which requires those variables to be live.

So there was a window where every request 404s until the registration call
lands. A live outage for no reason, and worse, it forces the registration to be
done in a hurry.

Now there are two separate things:

  CONTROL_REDIS_URL / CONTROL_REDIS_TOKEN
      the control database CREDENTIALS. Setting these lets the registry be read
      and written. Changes NOTHING about how requests are served.

  TENANCY_ENABLED=1
      the SWITCH. Only with this set does withTenant start resolving customers
      and refusing unknown addresses.

So you can set the credentials, register Rock, VERIFY it resolves correctly, and
only then throw the switch. No window, and nothing turns on until you have seen
it working.

/api/admin/tenant-setup now reports both, so you can see exactly which state you
are in.

---------------
Visit /api/admin/tenant-setup as admin. You should see:

Both false is correct. Then follow the Upstash steps.
