1. THERE WAS NO MANUAL CONTROL AT ALL
-------------------------------------
Worth correcting something I said earlier. release1Received / release2Received
exist as stored fields but NOTHING EVER SET THEM and the table never read them.
The green "released" state was derived:

  settledSecond = paidKnown ? (totalRemaining < 1) : false
  settledFirst  = paidKnown ? (settledSecond || totalRemaining <= r2v + 1) : false
  firstReceived = settledFirst && faMatchesInvoiced

It inferred release from the paid balance hitting zero, gated on Final Account
matching invoiced to within a pound. On an old project whose release went out
uncoded that can never settle, and there was no way to say so by hand. The edit
form only said "Auto: turns green once...".


2. CLICK THE RELEASE CELL
-------------------------
Click the 1st or 2nd release cell on any row to mark that half released. Click
again to undo. No opening the edit form. The date it was marked is stored.


3. AUTOMATIC FROM THE APPLICATION
---------------------------------
If the retention section on the project's latest application has a half ticked,
the register marks itself off - the cell reads "released (app)".

app.retentionRelease1 / retentionRelease2 are cumulative across applications, so
the latest one carries the whole picture. Exposed as appRelease1 / appRelease2.

So: new projects run through the app mark themselves; old spreadsheet projects
get marked by hand. Both work, as you asked.


4. MANUAL BEATS AUTOMATIC, IN BOTH DIRECTIONS
---------------------------------------------
The manual flag is an explicit true/false, not a "set or unset". So clicking a
green "released (app)" cell records FALSE and it stays false - if an application
says released and it never actually was, somebody can say so.

  old project, nothing set        released: false   source: none
  old project, marked by hand     released: true    source: manual
  new project, app ticked half    released: true    source: application
  app ticked, overridden off      released: false   source: overridden
  marked, then undone             released: false   source: none

An overridden cell goes amber and reads "not released *", so a deliberate
override never looks like an oversight.


5. THE OLD PAID-BALANCE GUESS IS NOW A HINT
-------------------------------------------
It no longer decides anything. Where Xero looks paid off but nobody has marked
the half, the cell turns pale blue and reads "due - looks paid". A prompt, not a
decision - which is what it should always have been.


6. ALSO IN THIS PACKAGE
-----------------------
RETENTION OUTSTANDING CARD - the halves not released, across the projects shown.
Now driven by the real release state, so it means something.

612 SPLIT INTO THREE COLUMNS - Deducted / Released / Held. dashboard.js was doing
Math.abs() on a signed net, so 10,000 deducted with 5,000 released was
indistinguishable from 5,000 never deducted. A project with NO 612 lines shows
dashes, not zeros - "no evidence" and "nothing released" are different answers,
and old projects give the first.


WHAT TO DO ON DEPLOY
--------------------
Every row starts unmarked, so Retention Outstanding will read the full gross
until you work down the register. The pale blue "due - looks paid" cells are the
ones Xero thinks are already settled - those are the quickest wins.
