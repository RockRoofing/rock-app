1. THE TICK WAS MEASURING THE WRONG THING - YOU WERE RIGHT
----------------------------------------------------------
It tested Retention Owed - 612 Deducted + 612 Released = 0. But Retention Owed
only deducts what an APPLICATION claimed. Since releases are now marked by hand
on the tracker, a hand-marked release left Owed untouched and the row flagged
even when Xero and the register agreed perfectly.

Your own screenshot proves it: 5,100.00 deducted, 2,550.00 released - EXACTLY
half - and it flagged. Meanwhile rows releasing odd part-amounts ticked, which
are precisely the ones worth looking at.

NEW RULE, as you described it: retention is released in halves, so 612 Released
should be NOTHING, HALF of 612 Deducted, or ALL of it. Anything else flags.

Measured against 612 Deducted - Xero's own gross - so the check is self-contained
and does not care whether an application or a manual mark recorded the release.

Your six visible rows, before and after:

    Deducted    Released    now      new
    9,163.10    9,163.10    flag  -> tick  (both halves)
    2,046.67      170.29    tick  -> flag  (out by +170.29)
    4,659.92    2,104.11    flag  -> flag  (out by -225.85)
    4,761.45      977.81    tick  -> flag  (out by +977.81)
    8,172.18    1,975.81    tick  -> flag  (out by +1,975.81)
    5,100.00    2,550.00    flag  -> tick  (1st half)

Five of six change. A live job that has released nothing ticks "none yet", so
work in progress stays clean rather than flagging everything.

The cell now shows WHICH of the three it matched underneath the tick, or how far
out it is next to the flag - so a flag says why at a glance instead of needing a
hover. The hover adds the nearest expected figure and the likely cause: a
part-release, or a deduction still growing because the job is not fully invoiced.


2. RETENTIONS DUE DID NOT DEDUCT ANYTHING
-----------------------------------------
retentions-due.js:17 tested `e.release1Received` - a field NOTHING EVER SETS. It
is left over from the tracker's old design, where the released state was inferred
from the paid balance at render time and never stored.

So confirming a half on the tracker changed nothing on that page, and every
project showed its full retention as due for ever. Same fault in both the balance
figure and the list of dated cash-in events.

It now uses the same rule as the tracker: manual mark wins either way, and with no
manual mark a half ticked on the latest application releases it. Checked on two
5,000 halves:

  nothing released           rows 1st + 2nd    outstanding 10,000
  1st confirmed by hand      rows 2nd only     outstanding  5,000
  both confirmed             rows none         outstanding      0
  1st via application        rows 2nd only     outstanding  5,000
  app says yes, overridden   rows 1st + 2nd    outstanding 10,000

The "Balanced with the Retention Tracker" banner still holds - both sides now use
the same rule.
