WHAT HAPPENED
-------------
My bug, from pkg773. The line showing what the search had narrowed to read:

  {filtered.length} of {items.length}

The memo in EmailQueue is called `shown`, not `filtered`. Nothing is named
`filtered` anywhere in that component. So the moment you typed a character the
count line rendered and threw "filtered is not defined".

Fixed - it reads `shown.length`, the same variable every other line in the
component uses.

WHY THE BUILD DID NOT CATCH IT
-------------------------------
esbuild compiles an undefined identifier without complaint; it only fails on
syntax. And the line only renders when the search box is NOT empty, so it never
executed on load - which is why it got through.

I also swept the whole component for any other identifier used in JSX with no
declaration in scope. Nothing else - the only hits were callback parameters and
one module-level style constant.
