1. ACTUALS NOW SUPERSEDE FORECASTS
----------------------------------
The chart was built from saved forecasts and retention releases only. Real
applications never entered it. So once a forecast period passed and the real
application went in, the chart kept showing the guess, at the guessed date, for
ever - and the actual never appeared at all.

Two changes:

REAL APPLICATIONS ARE NOW IN THE CHART. Each one lands as sales-in on its own
payment date (finalDate, falling back to paymentDate) at its actual certificate
value. That is the contractual date off the application itself, which beats any
forecast payment term.

FORECASTS THEY COVER DROP OUT. A forecast is superseded when the latest
application's VALUATION date is at or past the forecast's end date. Its cash
stops counting - otherwise the same money is in twice.

A forecast still RUNNING when the application lands is left alone. Only part of
its period has been certified and it is still forecasting the rest. Checked:

  App 4 values to 31 Aug
  forecast ending 31 Aug   -> superseded
  forecast ending 30 Sep   -> kept (straddles)
  forecast starting 28 Sep -> kept (future)
  negotiated project       -> untouched, it has no applications

NOTHING IS DELETED. The superseded forecast stays on the record and on the gantt,
greyed and struck through, reading "Superseded" with a tooltip explaining why.
You can still read what you predicted against what happened, which is the only
way the forecasting gets better. Deleting it would have thrown that away and
there would be no undo if a match were ever wrong.

The certificate value is computed server-side exactly as pages/api/applications.js
does it - prevCertGross where it has been entered, otherwise the previous
application's computed gross. Anything else makes every certificate cumulative.

NOTE: this is why J240 Application 4 matters. Its "Previously certified (gross)"
is blank, so its certificate value computes as the FULL 92,766.50 rather than the
increment - and that is now what goes into the chart. Enter 92,766.50 on it.


2. REVENUE OVERRIDE
-------------------
"Revenue this period" is now editable, like Labour and Materials on site.
Override / type / Reset. Drives the cash only - spread, schedule, sales-in
stream, and the saved revenueThisPeriod. It does NOT rewrite the percentages, so
the measured position and the next forecast's starting point stay honest.
thisCertTotal is still saved as the calculated value.


3. "REMAINING" MEASURES FROM THE PREVIOUS CERTIFICATE
-----------------------------------------------------
The grey line was budget less everything INCLUDING what you were typing, so it
shrank as you worked and restated the box above it. It now reads budget less the
PREVIOUS certificate and names it:

  "GBP 225,511.46 left after App 4"

Headroom for this period, and it holds still while you type.


PERFORMANCE NOTE
----------------
The all=1 call now scans project:* and reads each record to build the actuals.
Same pattern as getAllProjectSettings, so it is nothing new, but it is a heavier
call than before. If the cash flow page feels slow to load, that is where to
look first and it can be cached.
