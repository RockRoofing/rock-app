PROJECT FINANCE - WHAT IT DOES
-------------------------------
New tile in the Contracts Manager section of the Site App. It does NOT appear for anyone
else - the page itself also redirects away if the user is not accessLevel
'contracts-manager', so it cannot be reached by typing the URL.

Project-first, as asked: you land on a project list and pick one before seeing anything.
That list shows only LIVE projects (status 'active' - completed and archived are excluded)
where the logged-in user is named as Contracts Manager.

Once a project is picked:

  MARGIN        one big number, colour-coded (red negative, amber under 10%, green above),
                with the valuation date it is stated as at.

  LABOUR        budget / spend / remaining, with a usage bar
  MATERIALS     budget / spend / remaining, with a usage bar
  TOTAL         the two combined

Bars turn amber over 90% used and red when over budget, and "Remaining" goes red when
negative, so an overspend is obvious at a glance on a phone.


HOW THE MARGIN IS CALCULATED
-----------------------------
Deliberately the SAME basis as the EOM report, using the same shared computeProjectWip
from lib/wipCalc.js: to the LAST COMPLETED month's valuation date, INCLUDING WIP.

  margin = (profit to valuation date + WIP profit) / (invoiced to valuation date + WIP)

The valuation date is the project's own - a per-month override wins, otherwise the
project's valuation day applied to that month. This is the same rule Commercial use, so a
CM on site and Commercial in the office see the same number.

If a project has no valuation date set for last month, the margin shows as a dash with
"No valuation date set for last month" rather than a misleading figure.

Budgets are taken from the dashboard snapshot and INCLUDE instructed variations, which
matches Project Financials.


TWO THINGS TO BE AWARE OF
--------------------------
1. THE FIGURES COME FROM THE DASHBOARD CACHE, which rebuilds every 4 hours. So the numbers
   can be up to 4 hours behind a fresh Xero sync. For a high-level "how is my job doing"
   view on site that is fine, but it is not a live feed. If a project has never been
   through a dashboard sync, the page says there is no financial data yet rather than
   showing zeroes.

2. ACCESS CONTROL MATCHES THE EXISTING CM SCREENS, NOT MORE. The Site App has no portal
   login cookie, so the server checks the CM name supplied by the app against the project's
   Contracts Manager and refuses if they do not match. That is the same trust model the
   existing CM Applications / Variations / Contracted Rates screens already use, and it is
   a real check rather than nothing - but it is client-supplied identity.

   Given this screen shows margin, I would rather flag that plainly than let it pass. If
   you want it hardened, the fix is a proper signed Site App session token, which would
   also benefit every other CM screen. That is a separate piece of work - say the word.
