pkg283 - Variations / Edit Project Details: show pence, not whole pounds
=========================================================================

CHANGED FILES
-------------
  pages/project/[id].js       Edit Project Details - variations, budgets, AFA
  pages/variations.js         Variations page

No new files. Both straight replacements. Independent of the other packages.

FOLDER NOTE: pages/project/[id].js goes in the folder with LITERAL square brackets -
pages/project/[id].js


ROOT CAUSE - AND THE GOOD NEWS
-------------------------------
Nothing is wrong with your data. Nothing has ever been saved rounded.

Both screens formatted money for DISPLAY with maximumFractionDigits: 0, so every figure
was rounded to whole pounds on the way to the screen only. The stored values keep full
pence, and every calculation (AFA, budgets, margin, the EOM report) has always used the
real numbers.

The imbalance you were seeing is what happens when you round the parts and the total
separately:

  SHOWN (old):   £1,235 + £890 + £77  =  £2,202     three lines, shown total
  ACTUALLY:      1234.56 + 890.45 + 77.30 = 2202.31
  ADD UP THE SHOWN LINES: 1235 + 890 + 77 = 2202    ... but each line is out by pence,
                                                        and on more lines the gap grows

With enough variations the visible discrepancy can be several pounds, which is exactly the
"imbalance" you spotted. It was never in the arithmetic - only in what was printed.


THE FIX
-------
1. Both screens now display 2 decimal places:

   Edit Project Details - each variation's Total, "Instructed variations", and AFA
   Variations page      - every money figure (14 places, all on that page)

   The whole-pound formatting is UNCHANGED on the project dashboard cards, cost tables and
   invoice tables, where whole pounds are easier to read and nothing has to sum on screen.
   If you want those at 2dp as well, say so.

2. Every money input on both screens now carries step="0.01" and inputMode="decimal".
   They were plain type="number", which defaults to step="1" - so some browsers flagged
   "please enter a valid value" on a pence figure and the up/down arrows jumped a whole
   pound at a time. Entering pence now behaves properly, and mobile gets a numeric keypad.

   Inputs changed: Original contract value, Labour budget, Materials budget, and the
   Materials / Labour / Profit boxes on every variation (project page, plus the Add and
   Edit variation modals on the Variations page).


NO DATA MIGRATION NEEDED
-------------------------
Because the values were never rounded on save, existing variations will simply start
displaying their true pence as soon as this deploys. You may see figures you have not seen
before (e.g. a variation you thought was £890 showing as £890.45) - that is the real stored
value, not a change.
