WHAT THIS DOES
--------------
A slim column down the left of the RFI page (260px, table sits to the right) headed
"Comments / Approvals", for filing documents you have downloaded out of a client's own
portal.

  "+ Upload Comments / Approvals"   internal only. Multi-file - pick several at once.

Each uploaded document is listed newest first with a date/time stamp and who uploaded it,
in the same style as the Revisions list on the O&M page. Each entry has:

  View      opens the file in the browser
  Download  saves it with its proper filename
  Delete    internal only, with a confirm prompt

Customers on the project can see and download the list but cannot upload or delete.


WHERE THE DOCUMENTS ARE FILED
------------------------------
These are filed against the PROJECT, not against an individual RFI - so the column is the
same whichever RFI you have open, and the documents do not disappear when an RFI is
resolved. That matches "the documents should save on the RFI page".

New store:  design:rfi-uploads:<projectNo>

This is separate from the per-RFI Attachments, which are unchanged - if you want a
document tied to one specific RFI, that still goes on the RFI itself via Attachments.


CHOICES I MADE - SAY IF YOU WANT THEM DIFFERENT
------------------------------------------------
1. NO comment/approval TAG. Every upload goes into one list rather than being tagged as
   either a Comment or an Approval. The filenames coming out of a client portal usually
   say which it is. Easy to add a tag and a filter if you want them separated.

2. UPLOAD IS INTERNAL ONLY. "Allow us to upload" read as Rock Roofing filing what comes
   back from the client's portal. If customers should be able to upload their own comments
   directly, that is a one-line change.

3. NO EMAIL NOTIFICATION on upload. Filing a document does not currently notify anyone.
   Say if it should.
