TWO FAULTS, BOTH IN THE GROSS AFA
----------------------------------
1. IT TOOK THE LATEST APPLICATION OF ANY STATUS. A draft that had been started
   but never issued could set the Gross AFA - and with it the Final Account and
   the retention calculated on it. A draft is a working document, not a figure
   put to the customer. Now filtered to status === 'sent', which is how
   application-send.js and applications.js already treat it (a missing status
   counts as draft).

2. THE MANUAL OVERRIDE BEAT EVERYTHING. A figure typed once into
   settings.afaOverride sat on top of a real issued application indefinitely,
   and nothing moved when the application changed.

ORDER OF PREFERENCE NOW
------------------------
  latest SENT application  ->  manual override  ->  project details

  sent app + stale override    uses the application, override ignored
  sent app only                uses the application
  no sent app, override set    uses the override
  neither                      contract value + instructed variations

The override is kept as a fallback for projects with no sent application, which
is the case it was added for. It simply can no longer contradict one.

FINDING YOUR MISMATCHED PROJECT
--------------------------------
The Gross AFA cell already showed its source in small grey text. Two changes:

  "manual override" now prints in AMBER rather than grey, so it stands out
  "stale override saved" appears where an override exists but a sent
  application has overtaken it

Sort or scan for those two and you will have the project. Clear the override in
Edit Project Details and the row follows the application from then on.
