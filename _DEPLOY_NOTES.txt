pkg315 - Activities tab: the real cause
========================================

REPLACES pkg302 through pkg314. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js            THE FIX
  pages/api/crm.js        unchanged since pkg314
  lib/crmImportMap.js     unchanged since pkg305


THE SCREENSHOT SETTLED IT
--------------------------
    Deals currently loaded: 6,860
    Their ids look like: 258, 379, 414, 428, 646
    The activities are attached to deal ids: (none)

Your deals are fine - 6,860 of them, real ids, not the sample data. And "(none)" is the
answer: the activity list was EMPTY. Nothing was being compared, so nothing could match.
The "different exports" message was wrong, and so was telling you to re-import.


ROOT CAUSE - AND IT WAS SOMETHING I INTRODUCED
------------------------------------------------
Your activities were imported before the flat outstanding-list existed, so pkg312 added a
fallback: read the per-deal summary, find the deals with outstanding activities, fetch
just those. That fallback never ran.

    if (view !== 'activities' || healedRef.current) return;
    const needed = ...summary...
    if (!needed.length || openActivities.length) { healedRef.current = true; return; }

pkg311 made the CRM remember your last tab. You were on Activities, so the page now opens
straight onto it - and that code runs on mount, BEFORE the deals and summary have loaded.
With an empty summary it found nothing to do, marked itself finished, and never ran again.
The summary arrived a moment later to a switch already flipped off.

So two features I added a few packages apart combined to break this. It would have worked
for anyone whose last tab was Pipeline, which is why it looked so inconsistent.

FIXED: it now waits for the summary to arrive instead of giving up when it is absent, and
only marks itself finished once it has actually seen the data.

Reproduced the exact mount sequence before and after: old guard never fetched, new guard
does.


ALSO ADDED
----------
A "Load activities" button on that screen. If the fetch ever fails - a dropped connection
mid-load - you can retry without reloading the page. It only appears when the list is
genuinely empty rather than mismatched.

The wording is also corrected: it no longer tells you to re-import when it does not know
that is the problem.


WHAT TO EXPECT
--------------
Open the Activities tab and you should see your 1,023 outstanding activities, oldest due
first, with project, person responsible and customer details. The kanban dots should come
to life at the same time, since both read the same data.
