1. TOTAL RETENTION CARD REMOVED
-------------------------------
Four cards now: Retention Outstanding, Remaining to Claim, In Defects Liability,
Live Projects. The gross figure it showed is still readable on any row as the two
release values.

totals.total was only ever used by that card, so it has gone with it rather than
being left computing something nothing reads.

The Outstanding tooltip said "not yet ticked as Received", which was left over
from the old field name. It now describes what actually drives it - the release
marks on each row, and any half ticked on an application.


2. THE RELEASE MARKS SAY WHAT TO DO
-----------------------------------
An unmarked cell said "due", which describes a state and gives no clue the cell
is the control. It now names the action, is underlined, and has a dashed outline
so the column reads as a row of buttons.

  unmarked, nothing known      orange, dashed   "click to confirm released"
  unmarked, Xero looks paid    blue,   dashed   "looks paid - click to confirm"
  marked by hand               green,  solid    "released"
  marked by application        green,  solid    "released (app)"
  app says yes, overridden     amber,  dashed   "not released - click to accept"

Headings read "1st Value - click to release" and "2nd Value - click to release".

A half ticked in the retention section of the latest application marks the
register by itself. Manual beats automatic BOTH ways - clicking a green
"released (app)" cell records an explicit false and it stays false.


3. 612 COLUMNS AND THE RECONCILIATION
-------------------------------------
  ... Retention Owed | 612 Deducted | 612 Released | tick | Ret % ...

Named "612 Deducted", not "Allocated": the old Allocated column was Math.abs() of
a SIGNED sum, i.e. the net - the same thing as Held. Reusing the name for the
gross would have put a different number under the same heading silently.

  Retention Owed - 612 Deducted + 612 Released, green at zero.

  nothing released           10,000 - 10,000 +      0  ->  tick
  half claimed + released     5,000 - 10,000 +  5,000  ->  tick
  claimed on app, not in 612  5,000 - 10,000 +      0  ->  FLAG, out by -5,000
  deduction never coded      10,000 -  4,000 +      0  ->  FLAG, out by  6,000
  no 612 lines at all                                  ->  dash


BEFORE YOU RECONCILE
--------------------
Run a LONG invoice sync. The button sends months: 6, the endpoint accepts 60, and
per sync-invoices.js:186 lines outside the window are never re-fetched.

Every row starts unmarked, so Retention Outstanding reads the full gross until you
work down the register. The blue "looks paid" cells are the quickest wins.
