WHAT THIS DOES
--------------
A "Save" button now sits in the header of the open RFI window, visible to EVERYONE
including customers (the existing internal Edit / Save pair is unchanged and still only
appears in edit mode).

Everything already saved on its own - that has not changed. What the button adds:

  1. It posts any comment still sitting UNSENT in the comment box. Previously a customer
     could type a comment, not press "Comment", close the window, and lose it. That was
     the only real data-loss path in this window and it is now closed.

  2. It waits for the markup autosave to land, then shows a green confirmation:
     "All changes saved 14 Aug 26, 15:42"

So a customer who is unsure whether their work stuck can press Save and get told plainly.


WHY IT WORKS THIS WAY - PLEASE READ
------------------------------------
The zip I was given is at pkg264. It does NOT contain pkg265 - `hideDownload` does not
exist anywhere in components/DrawingMarkup.js.

The tidy way to build this button was to edit DrawingMarkup.js so Save could force the
markup write instantly. Had I shipped that file as a full replacement built on this copy,
it would have SILENTLY REVERTED pkg265 and brought back the untracked Download button on
the O&M page - the exact bug pkg265 existed to fix.

So I did not touch DrawingMarkup.js. Markup already autosaves 800ms after you stop
drawing, so Save waits 1 second and then confirms - same end result for the user.
