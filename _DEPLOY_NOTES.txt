WHY NOTHING SAVED
-----------------
Line 456:

    if (view === 'invoice-finance') {          // no method check
      ...
      return res.json({ ... })                 // always returns
    }

`view` is read from the POST BODY as well as the query string. So every
invoice-finance POST fell into that GET block, was answered with the GET payload,
and RETURNED - before ever reaching the save handlers, which sit ~130 lines
further down the file.

The client got a 200 with sensible-looking JSON and reported success. Nothing was
ever written: not the insured limits, not the advance rate, not the caps, not the
import date. Pure handler ordering.

THE SAME FAULT WAS ON CASHFLOW. `if (view === 'cashflow')` at line 644, also with
no method check, shadowing FIVE POST handlers - save-lumps, refresh-balances,
save-finance, save-bill-paydate, save-bill-cis. None of them have ever persisted
either. Fixed, and I scanned every view block in the file: those two were the
only ones and all POST handlers are now reachable.


NO MORE SAVE BUTTON FOR LIMITS
------------------------------
  - The Bibby CSV import writes immediately on upload.
  - Typing a limit in the table saves when you leave the cell.
  - If a save fails it says so - "Limit did NOT save" - rather than reporting
    success.

The blur handler reads a ref rather than the state variable: onBlur can fire in
the same tick as the change, and the state closure would still hold the PREVIOUS
value, so it would post the figure you just typed over.

The button is now "Save settings" and covers only the advance rate, drawn, caps
and high involvement.
