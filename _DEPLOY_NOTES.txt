THE SEARCH
===========
One box, above the table. It matches people and projects at the same time:

  PEOPLE     name, company, email, mobile, role and trades
  PROJECTS   job number OR project name - everybody who can see that job

Project NAMES as well as numbers, so it works whichever way you happen to remember
the job. projectAccess stores numbers only, so the name is resolved through the
project list the page already loads for the access picker.

The count beside it reads "4 of 26 users" while a search is on, so a short list is
obviously a filtered one rather than a page that has lost its data.


ONE DECISION
-------------
SOMEBODY WITH ACCESS TO EVERYTHING MATCHES EVERY PROJECT SEARCH.

Search "Farmstead" and you get the people explicitly assigned to it AND the managers
with all-project access - because they can see it too, and the question this page is
really being asked is "who can see this job?". Leaving them out would answer that
wrongly.

Checked against the awkward overlap: searching "farmer" returns Eve Farmer by name
and does NOT drag in Farmstead Drive, and searching "farmstead" returns the project's
people without returning Eve.
