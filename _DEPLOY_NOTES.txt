pkg288 - Project Financials CM now matches Edit Project Details
================================================================

CHANGED FILES
-------------
  pages/api/dashboard.js

No new files. Straight replacement. Independent of the other packages.

BEST DEPLOYED WITH pkg286 (the Ops -> Commercial project details work), since the two
share the same resolver - but it works on its own.


WHY THEY DISAGREED
------------------
Edit Project Details resolves the CM through lib/projectPeople.js:

    commercial override  ->  Ops/IHM  ->  blank

The dashboard, which feeds Project Financials, did its own thing instead:

    contractsManager: (ihmByNo[String(cp.jobNo).trim()]?.contractsManager)
                      || settings.contractsManager || ''

Two separate faults in that one line.

1. IT IGNORED THE COMMERCIAL OVERRIDE ENTIRELY. If a CM had been changed in Edit Project
   Details, that screen showed the new name and Project Financials carried on showing the
   Ops one. This is the likely cause of what you are seeing.

2. IT MATCHED THE JOB NUMBER BY EXACT STRING. ihmByNo is keyed on the Ops project number,
   so "J203" only matched "J203". The resolver matches tolerantly - it strips a leading J,
   collapses case and spaces - so "203" and "J203" are the same project to it but were two
   different things here. Any project where the two systems spell the number differently
   would show a blank or stale CM.

The odd part is that the dashboard ALREADY calls the resolver two lines above (for the
`people` field) - the CM line just was not using it.


THE FIX
-------
contractsManager now comes from that same resolver result, with the old chain kept purely
as a fallback. One source of truth, so the two screens cannot drift apart again.

ALSO - AND THIS MATTERS FOR THE OPS SIDE:
Saving in Commercial clears the dashboard cache, so commercial edits always showed up
promptly. Saving in OPS does not clear it - so an Ops change to the CM would not have
reached Project Financials for up to 4 hours even once the above was fixed.

The cached path now refreshes the CM live on every read (using the same resolver), so an
Ops change appears immediately. This deliberately does NOT force a full Xero rebuild - it
is a cheap per-read overlay, the same trick already used for the WIP fields.

A cache-validity marker (cmResolved) has been added, so existing snapshots rebuild once on
the first load after deploy rather than serving the old CM.


WHAT TO EXPECT
--------------
First load after deploying may be slower than usual - that is the one-off rebuild. After
that, the CM column and filter on Project Financials should match Edit Project Details on
every project, and follow changes made in either portal.

If a project still disagrees, open Edit Project Details and look at the badge on the
Contracts Manager field - "override" means Commercial is deliberately deviating from Ops
(pkg286 adds a "use Ops value" button to undo that).


TESTED
------
npm run build - Compiled successfully.
Both faults reproduced and confirmed fixed: exact-key vs tolerant job-number matching, and
override-vs-Ops precedence.
