THE TAB
========
Bookkeeping now reads: Costs (Bills) | IN QUERY | Sales Invoices | Direct Wages |
Overheads | Retention | WIP.

Same columns, same month and supplier filters, same Labour/Materials filter and the
same export as the Costs tab - In Query rows are cost lines, they are just parked.
A short note at the top of the tab says what it is, so somebody opening it cold does
not read it as another project.


WHERE THOSE COSTS WERE GOING BEFORE
=====================================
Nowhere new - and that is the point. A tracking option looks exactly like a project
to everything downstream, because a project IS a tracking option here. So anything
tagged In Query was already arriving as a project called "In Query" and being
counted in the Costs tab as project spend.

They now route to their own tab instead, and out of the Costs figures. A cost parked
in query is in the books but not yet on a job, and it should not be adding to job
cost until somebody says which job.

The tracking option beats the account category, so an In Query line lands in the tab
whatever code it carries. And a sales invoice tagged In Query is no longer listed as
a sale against a project.

Matched loosely on the name, because the option is typed by hand in Xero:

    "In Query", "in query", "IN QUERY", "In  Query", " InQuery "   all match
    "Inquiry", "In Query Ltd", "J228 - Farmstead"                  do not


THE BIT YOU SHOULD KNOW ABOUT
===============================
This fixes Bookkeeping. It does NOT fix everywhere else.

Because In Query is a tracking option, it will also be appearing as a PROJECT on
Project Financials, in the dashboard project list, and anywhere else that builds its
list from Xero tracking categories. A project with costs and no revenue drags the
margin figures it sits in.

I have not changed that here. Excluding it from the dashboard moves numbers on
pages you have spent this week checking, and it should be a deliberate decision
rather than something that arrives attached to a new tab.

Two questions worth answering before I do:

  1. Should In Query be hidden from Project Financials and the dashboard entirely?
  2. Are there other non-project tracking options in Xero doing the same job -
     "Overheads", "Suspense", anything similar? If so the right fix is one list of
     non-project options, not a special case for this one.

Tell me and it is a contained change in lib/ and pages/api/dashboard.js.
