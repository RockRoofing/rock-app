pkg347 - Inline editing removed; an Edit button instead
========================================================

REPLACES pkg302 through pkg346. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js
  pages/api/crm.js        unchanged since pkg346
  lib/crmImportMap.js     unchanged since pkg305


WHAT CHANGED
------------
Inline editing is gone. The Activities table has an EDIT column immediately after Mark
Done, with a proper button on every row. It opens the same window you already liked -
big text box, due date, person responsible.

Column order: Mark Done | Edit | Project | Activity | Due date | Person responsible |
Customer company | Customer name | Customer email | Customer phone.

Header and body cell counts verified at 10 each, so nothing has slipped out of line.


YOU WERE RIGHT ABOUT THE DATE
------------------------------
A native date box fires a change on every keystroke, so typing a date sends part-formed
values as you go, and clicking away could commit whichever fragment it had - or nothing at
all, if the browser had not settled on a valid date. That is why it was unreliable rather
than simply broken.

It also made the whole thing ambiguous: a cell that silently saves when you click away
gives you no confirmation, which is exactly what you were describing. A button and a window
with a Save in it does not have that problem.


ONE IMPROVEMENT WHILE I WAS IN THERE
--------------------------------------
The edit window's Person responsible was a FREE TEXT box - which is how names like "James"
ended up sitting alongside "James McVeigh" in the first place. It is now the same dropdown
as everywhere else: you first, then the other pre-contract and admin users, then Nobody.

If an activity is already assigned to somebody no longer on that list, they are shown as
"(no longer available)" and kept unless you change it - so historic ownership is not
quietly rewritten.
