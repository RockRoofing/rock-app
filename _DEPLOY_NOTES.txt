THE FIX - SMALLER THAN IT LOOKS
=================================
Archiving was already three-quarters built. 'archived' was already a status, already
in the labels, already in the Status filter, already in the row dropdown and already
in the Add/Edit modal. Nothing needed inventing.

What was missing was that Delete still existed alongside it.

  DELETE IS GONE from the projects list.

  DELETE IS REFUSED BY THE API, with a message saying to archive instead. It
  previously had NO guard at all - it removed whatever project number it was given.
  The only thing stopping anyone was a hidden button, and per your last question that
  button was hidden in the wrong places: a manually-added project KEEPS manual: true
  after an Internal Handover is completed against it, because the IHM upsert spreads
  the existing record. So Delete appeared on projects with full minutes behind them.

  RESTORE appears on archived rows, putting them back to Live.

  ARCHIVING ASKS FIRST, because the project leaves every live list: "It disappears
  from the Planner, the Site App and every live list, but nothing is deleted. You can
  restore it from the Archived filter at any time."

  STATUS IS VALIDATED server-side against draft / active / complete / archived. A
  typo would have set a status no consumer recognises and the project would have
  vanished from every list with nothing to explain it.

  archivedAt and archivedBy are recorded, and cleared on restore.


WHY ARCHIVING ALREADY WORKS EVERYWHERE
========================================
Every consumer of the project list allowlists 'active' and 'draft' rather than
excluding 'complete'. So a status they have never heard of drops out on its own.
Checked all of them:

    Planner, project process board        draft, active      archived excluded
    Site badges, RAMS approvals, notices   draft, active      archived excluded
    RAMS matrix                            draft, active      archived excluded
    Site App project picker                active             archived excluded

That is the allowlist paying off - had any of them been written as "not complete",
archived projects would have carried on appearing and this would have been a much
larger change.


WHY DELETING WAS NEVER RIGHT
==============================
The handover minutes, the RAMS, the drawings, the submissions and the planner
allocations all key off the project number, and none of them were removed with the
project. Worse, saving that project's handover again simply recreated the record -
so on an IHM project the button would have appeared to do nothing.
