WHAT THIS FIXES

1. CUSTOMER LOGIN EMAIL (was not being sent at all)
   - When you add a Design Customer in the Admin centre, they are now EMAILED their login
     details (their email address + a temporary password + a link to the login page).
     They're asked to set their own password on first login.
   - The admin confirmation now tells you whether the email actually sent; if it couldn't
     send, it shows the temp password so you can pass it on manually.
   - NEW button per customer: "Resend login email" - generates a fresh temporary password
     and emails it. Use this for the customer you already created (they never got an email
     because the feature didn't exist yet). Note: the original temp password can't be
     recovered (it's stored hashed), so resending necessarily issues a new one.

2. RFI COMMENT NOTIFICATIONS (were not being sent)
   - Adding a comment on an RFI now emails: anyone @mentioned in the comment, plus the
     RFI's "Customer responsible" - except whoever wrote the comment. The email includes
     the comment and a link that opens that RFI directly.
   - Also: when a NEW RFI is created, the responsible customer is emailed to tell them an
     RFI has been raised for them, with a link.
   - Email links open the RFI directly (the page now honours ?open=<id>).

REQUIREMENTS
   - Uses the existing Resend setup (RESEND_API_KEY, and NOTIFY_FROM_EMAIL / FORMS_FROM_EMAIL
     for the from-address). These are already set for the rest of the app. If RESEND_API_KEY
     is ever missing, the app still works - it just reports the email wasn't sent.
   - Customer/mention notifications only email people who have an email address on file and
     (for customers) are scoped to that project.
