pkg418 - the snapshot found zero projects. My mistake.
======================================================

Deploy after pkg417. One changed file: lib/crmGpSnapshots.js. No new files.


THE BUG
-------
    "projects": 0  on every month

/api/dashboard computes a variable called `stage` and returns it under the key `status`.
I filtered on `p.stage`, which is undefined on every project, so nothing was ever
INPROGRESS and every month recorded nothing.

Reproduced on the bench: the old filter returns 0 of 4 test projects, the corrected one
returns the 2 that are live.

Now reads `status`, and accepts `stage` as well in case that endpoint is ever tidied up.


TWO THINGS SO THIS CANNOT HAPPEN QUIETLY AGAIN
------------------------------------------------
1. The response now reports what it actually saw:

       "projectsSeen": 214,
       "liveNow": 63,
       "statusCounts": { "INPROGRESS": 63, "DEFECTS": 22, "CLOSED": 129 }

   and warns outright if nothing came back as INPROGRESS. A run reporting zero with no
   explanation is what cost you the last deploy.

2. The failed run has already WRITTEN empty snapshots for all six months. Left as it was,
   the "reuse the recorded project set" rule would have faithfully reused those empty
   lists and kept every month blank for ever - correct behaviour applied to junk data.

   An empty recorded set is now treated as a failed run rather than a decision, and gets
   rebuilt. No need to clear anything by hand.


RUN IT AGAIN AFTER DEPLOYING
----------------------------
    /api/cron/gp-snapshot

Check "liveNow" in the response is a sensible number against what Project Financials
shows. If it is, the GP margin card will have six months of figures.

The caveat from pkg415 still stands: this first real run uses today's live project list

approximate. Everything recorded from the 22nd onwards keeps its own set and is sound.
