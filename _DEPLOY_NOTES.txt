THE CHANGE
===========
"Insert your name" and "Your name" now take ONE person. Choosing somebody replaces
the choice rather than adding to it, so picking the wrong name and then the right
one leaves one name on the form, not two.

They are members fields, which are multi-select, so it was possible to put three
people in the box for who filled the diary in.

Identified by the same /your name/i rule the auto-fill already uses to decide where
to drop the logged-in user - not a second rule of my own. Checked against every
members field in formDefs.js:

    Insert your name                                   single
    Your name  (x3)                                    single
    Personnel on site working on behalf of Rock        unchanged, multi
    Operatives on site                                 unchanged, multi
    Rock personnel on site                             unchanged, multi
    Operatives on site on the last day of the project  unchanged, multi


THE STORED VALUE IS STILL AN ARRAY OF ONE
===========================================
It has always been stored that way. Existing submissions, the exports and the
missing-forms checks all read it as an array, so changing the shape to a bare string
to suit the UI would have broken every form already submitted.

The only difference is that the array can no longer hold more than one name.

Wording follows: the search box reads "Search for your name..." on those fields, and
once a name is picked the list says "Pick a different name to change it" rather than
"Everyone is selected".
