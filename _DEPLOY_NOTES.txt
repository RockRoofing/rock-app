pkg331 - Activities now live in ONE place
==========================================

REPLACES pkg302 through pkg330. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js
  pages/api/crm.js
  lib/crmImportMap.js     unchanged since pkg305


YOU WERE RIGHT
---------------
There was no good reason for two stores. The split existed because the import could not put
36,824 activities onto the deals (crm:deals would have been 31MB, read on every page load) -
but that was a constraint on the IMPORT, not a reason for activities created in the CRM to
be filed somewhere else. Once Pipedrive is gone the distinction means nothing, and it has
been the cause of nearly every fault in this run.

Now there is one store: crm:activities:<dealId>. Imported and CRM-created sit side by side
in the same place, and the deal view and the Activities tab read the same records.


WHAT CHANGED
------------
  - activities are no longer written onto the deal at all
  - creating, editing or completing one writes to the shared per-deal store
  - the kanban summary and the flat outstanding list are rebuilt on EVERY write path, so
    the board, the deal and the tab cannot drift apart
  - imported activities are preserved when CRM ones are saved - the server keeps them and
    replaces only the CRM-created set

Verified end to end: adding an activity keeps the imported ones, puts the new one in the
tab's list, updates the kanban dot, and completing it removes it from both again.


MIGRATION - AUTOMATIC, NOTHING TO DO
-------------------------------------
Activities already sitting on a deal are moved across the first time that deal is saved.
Until then they still display, so nothing disappears and nothing is lost. It happens
quietly as you work.


WHAT THIS FIXES
---------------
The activity you have been chasing. It will now appear in the tab because there is only one
list to appear in. It also removes the whole class of problem behind the last several
packages - two lists that had to be stitched together, with every rule applied to the seam.

Also in this package, from pkg330: the project scope dropdown (Open / Open + won / All,
defaulting to Open + won), so a won job's activities are no longer hidden.


ONE THING I HAVE NOT DONE
--------------------------
Notes are still on the deal. They are far smaller, and the same argument applies but with
much less at stake. Worth doing eventually for consistency - say if you want it now.
