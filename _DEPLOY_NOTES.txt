1. RETENTION - YES, STRAIGHT FROM THE TRACKER, AND ONE THING WAS BROKEN
-----------------------------------------------------------------------
The DATES come only from the tracker's 1st and 2nd release fields. Whatever is
typed there wins, whatever the PC or sub label says. A blank date contributes
nothing, which is right - an unknown release date is not a forecast.

That part was already true. The VALUES were not.

/api/retention returns the RAW saved entry. The tracker page merges the Xero
financials on when it renders:

    finalAccount: e.finalAccount || x.finalAccount,
    retentionPct: e.retentionPct || x.retentionPct,

So on a Xero project where you only set the two release dates - which is the
normal way to use it - finalAccount and retentionPct are BLANK on the stored
entry. The tracker looked right. The cash flow computed a total of zero and
dropped the row without a word.

Now: the entry's own figures first, the dashboard's afa / retentionPct /
totalRetention behind them, and explicit release1Value / release2Value ahead of
both, because the two halves are not always equal.

Checked across the real cases:

  Xero override, dates only     1st 6,853.46  |  2nd 6,853.46     (was: nothing)
  Manual entry, own figures     1st 2,500.00
  Uneven halves set             1st 5,000.00  |  2nd 8,706.91
  1st half already received     2nd 6,853.46  only
  No dates at all               nothing

So yes - manual entries and Xero-derived rows are both accounted for now.
Anything with a date set appears; anything without still does not, and that is
the correct behaviour rather than a gap.


2. MCD BASIS - IT WAS NOT ALLOWED FOR
-------------------------------------
The forecast never sent the flags, and the two sides default OPPOSITE ways:

  lib/applications.js:144        app.mcdOnVariations !== false    -> absent = TRUE
  pages/api/applications.js:194  project.mcdOnVariations === true -> absent = FALSE

On a project with the boxes unticked the real application charged no MCD on
variations or materials and the forecast charged it on everything. Both flags now
come from Edit Project Details and go on EVERY computeApplicationSummary call in
the modal, via one `mcdBasis` object so no call site can miss one.

  100,000 works + 20,000 variation, MCD 2.5%:
    MCD on everything      sales 117,000.00
    MCD on contract works  sales 117,500.00


3. FORECASTS NOW RECOMPUTE
--------------------------
Each saved forecast is recalculated on load against the CURRENT applications.
Percentages stay exactly as saved; only the deduction for what has already been
claimed moves, which is the one part that depends on anything outside it.

  Forecast saved when the prior certified 40,000, later corrected to 70,000:
    stored      74,575.00   <- double counts 30,000 of gross
    recomputed  46,787.50

Overridden forecasts are left alone - you typed those deliberately. Cash
instalments scale by the same ratio so the dates and monthly split survive. Read
time only; nothing is written back, so reopening a forecast shows what you saved.
