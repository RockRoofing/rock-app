pkg308 - CRM activities import: fixes the 413
==============================================

REPLACES pkg302 through pkg307. Deploy this one only.

CHANGED FILES
-------------
  lib/crmImportMap.js     unchanged since pkg305
  pages/api/crm.js        request body limit raised (this is the fix)
  pages/crm.js            chunks sized by bytes rather than by project count

No new files. All straight replacements.


WHY 413, AND WHY NOTES WORKED BUT ACTIVITIES DID NOT
------------------------------------------------------
413 means "payload too large". Next.js caps API request bodies at 1MB BY DEFAULT, and
pages/api/crm.js never raised it. Every other bulk-import endpoint in the app does -
import-bills-bulk uses 10mb, issues 8mb, pre-start 4mb - the CRM one was simply missed
when the chunked import was built.

Measured against your real files at 300 projects per chunk:

    activities   largest request 1.18MB   ->  4 chunks over the 1MB limit  ->  413
    notes        largest request 0.82MB   ->  0 chunks over the limit      ->  fine

That is exactly the behaviour you saw: notes uploaded, activities failed partway.

Activities are bigger per record than notes - subject, type, due date, assignee, creator,
done flag - so they cross the line and notes do not.


THE FIX - TWO PARTS
-------------------
1. The CRM endpoint now allows an 8MB body, in line with the other import endpoints.

2. More importantly, chunks are now built by MEASURED SIZE rather than a fixed count of
   projects. A fixed count was always a guess: one project with 96 activities is worth a
   hundred projects with one each, so a busy run could blow the limit even when the
   average looked comfortable. Each chunk now fills to a 3MB budget (against the 8MB
   server limit), with a 400-project cap as a second guard.

   This is the part that stops it happening again - if a project accumulates a lot of
   history in future, the chunker simply makes that chunk smaller.

Re-measured with the new chunker:

    activities   32,564 records / 5,415 projects  ->  14 requests, largest 1.26MB
    notes        10,232 records / 5,542 projects  ->  14 requests, largest 0.82MB
    every project accounted for in both cases

There is now roughly 6x headroom between the largest request and the server limit.


RE-RUNNING THE ACTIVITIES IMPORT
---------------------------------
Just import the file again. It is wipe-and-replace, and the partial data from the failed
run is overwritten - the wipe now only clears keys that will not be rewritten, so a re-run
is quick rather than the 200-second stall that pkg307 fixed.

Your notes import is unaffected; leave it alone.
