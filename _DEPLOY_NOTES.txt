DEPLOY NOTES - Site Issues: fix malformed resolution date
=========================================================

ONE file, an EDIT - just replace it.
  pages/operations/project-management/issues.js

WHAT WAS WRONG
  The Required Resolution Date could show a corrupted year like "22/02/222026". This
  happens when typing into a native date field's year segment lets extra digits pile up
  (222026), which the browser then stores as-is.

FIX
  - Date entry is now sanitised: only a valid YYYY-MM-DD with a plausible year
    (2000-2100) is saved; anything malformed is dropped (field clears) so a bad year
    can't be stored.
  - min/max are set on the date inputs as a browser-level guard.
  - Existing malformed values are no longer displayed as the corrupted "222026" - the
    field shows blank so it can be re-entered cleanly.
  Applies to both Required Resolution Date and Resolved Date, in the list and the
  edit/create forms.
