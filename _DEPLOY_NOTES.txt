THE CHECK PANEL FOUND IT IN ONE GO
----------------------------------
"0 monthly columns, 0 total rows found" - on a payload that contained both.

The refresh writes everything Xero returned:

    await redis.set('bs:accounts', { ...r, fetchedAt: ... })     <- correct

But the READ whitelists what it sends back to the page:

    accounts, asAt, fetchedAt, items, assumptions                <- columns and
                                                                    totals dropped

So the twelve monthly columns and Xero's Net Assets row were fetched, stored, and
then thrown away on the way out. The page was working correctly on data it never
received.

FOURTH TIME THIS EXACT FAULT HAS APPEARED IN THIS FILE - the finance config
whitelist, the manual balances whitelist, the invoice-finance settings, and now
this. Storing more than you return is silent by nature: nothing errors, the field
is simply absent.

I swept the file for other write-then-drop mismatches. bs:accounts was the only
spread write, and the paid-invoices and cash-commitments endpoints return the same
shape they store.

-------------------
The check panel turns GREEN:

    Xero balance sheet check - 8 monthly columns, 6 total rows found
      Net Assets: 56,460 | 119,573 | 133,000 | 251,938 | ...

and the ACTUAL columns become Xero's real figures - 56,460 at July, not 889,966 -

No need to press Read balance sheet again - the data is already in Redis. It just
could not get out.
