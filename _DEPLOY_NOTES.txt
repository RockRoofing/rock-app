THE PROBLEM
-----------
You asked whether the (CRM) pages were free of Pipedrive. They were not, and it mattered
more than a labelling point.

Three metrics are built from VALUE-CHANGE records:

    Total value of work priced
    Value priced - existing customers
    Projects priced over 200K

Those records were only ever written by pages/api/webhook.js, when Pipedrive fired an
event. Switch Pipedrive off and they stop being written - on the live pages AND the (CRM)
ones. Those three metrics would have silently flatlined and nobody would have seen why for
a month.


THE FIX
-------
The same records are now derived from the CRM's own deal history:

    a value edit on a deal        -> value change record
    a deal entering a priced stage -> stage entry record
    (priced stages: MC Unsecured, MC Secured, Negotiating, Variations)

That history is already being kept, so this works on changes made BEFORE today as well as
after. Older entries hold the numbers only inside the text ("Value: £180,000 -> £250,000")
so those are parsed; from now on the numbers are also stored outright on the entry, which
is the change to pages/crm.js.

Tested against both shapes, and against the awkward cases:
  - a deal moving in, out, and back into Negotiating counts ONCE, not twice
  - a value already counted by an edit is not counted again by the stage move
  - a deal entering a priced stage with no value is recorded as zero, not skipped
That matches how the old webhook behaved, so the numbers are comparable.

Derived records are computed on read, never stored, so they cannot drift out of step with
the deals they came from.


BEFORE YOU COMPARE - RUN THIS ONCE
-----------------------------------
The CRM only has history from when the CRM started. Everything before that lives in the
old Pipedrive-era store. Copy it across:

    Open /sales-crm, or just hit the endpoint - it is a one-line POST. Easiest way:
    ask me and I will add a button, or run it from the browser console on any portal page:

        fetch('/api/value-changes-crm',{method:'POST',headers:{'Content-Type':'application/json'},
          body:JSON.stringify({action:'seed'})}).then(r=>r.json()).then(console.log)

    It returns { copied: n }. Safe to run twice - it skips anything already copied.

Those are your records; only the collection method was Pipedrive's. Without this, the
three metrics above will read near-zero for any month before the CRM existed, and the
comparison against the live page will look alarming for no good reason.

Say the word and I will put a proper button on the page instead of a console command.
