THE BUTTON
===========
An "Open website" button in the Organization panel on a deal, directly under the
Website field. Opens in a new tab.

It only appears when the field holds something that could actually be a website. A
button that opens a blank tab because somebody typed "TBC" is worse than no button.


WHY IT IS NOT JUST target="_blank"
------------------------------------
A website typed into a CRM is rarely a URL. "rockroofing.co.uk" with no scheme is a
RELATIVE path to a browser, so a plain link lands you on

    app.rockroofing.co.uk/rockroofing.co.uk

which is a 404 inside the portal, not the company site. The value is normalised
first: a scheme is added where missing, trailing punctuation is stripped, and
anything that is not shaped like a domain returns nothing and the button stays
hidden.

Verified against what people actually type:

    rockroofing.co.uk           -> https://rockroofing.co.uk
    www.example.com             -> https://www.example.com
    https://example.com/about   -> unchanged
    example.com,                -> https://example.com   (trailing comma dropped)
    "  example.co.uk/contact  " -> https://example.co.uk/contact
    -  /  n/a  /  TBC           -> no button
    01234 567890                -> no button  (phone number in the wrong box)
    ask Roman                   -> no button

Opened with rel="noopener noreferrer", so the company's site gets no handle on the
portal tab it was opened from.


TWO SMALL THINGS THAT CAME WITH IT
------------------------------------
The button sits UNDER the Website field rather than beside it. Every row in that
panel is a space-between pair of label and value; adding a third child would have
pushed the value into the middle of the row and knocked the whole panel out of
line.

The Website line in the read-only Organisation section of the Make contact panel is
now a link too, using the same rule. Phone and email were already one click there
and the website was the odd one out.
