THE ERROR SCREEN GAVE IT AWAY IMMEDIATELY
-------------------------------------------
React error #300 means "Rendered fewer hooks than expected". That is a specific, and
entirely my, mistake - and it is ONE fault causing BOTH problems you have reported.

When I built the Activities tab I added six hooks - a useRef, a useEffect and four
useMemos - and they landed BELOW this line in the page component:

    const live = deals.find((d) => d.id === openId) || null;
    if (live) { return ( ...deal view... ); }

On the board, every hook runs. Open a deal and that early return fires first, so those six
never run. React sees the hook count drop between renders and refuses to continue, which
is the screen you sent.

AND THAT IS WHY ADD PROJECT CRASHED TOO. Creating a project calls openDealById() to show
the new deal - the same path, the same crash. I spent three packages hunting the Add
Project bug separately when it was this all along. The error boundary from pkg318 is what
finally surfaced it; it was the right call and it paid for itself.

FIXED: all six moved above the early return, so both paths declare the same hooks in the
same order. Verified programmatically - there are now no hooks after the early return
anywhere in the page component.

I have left a comment at that spot explaining why they must stay there, so it does not get
undone later. This is the same rule as the standing note about React hooks needing to come
before any early return; I broke it and did not spot it.
