pkg867 - The lost application. Cause found and fixed.
=====================================================

TWO FILES. No new files to create.
  pages/api/applications.js
  pages/api/application-send.js


WHAT HAPPENED
-------------
application-send.js read the whole project record, then built a PDF, then sent
the email through Resend, and only THEN wrote the whole record back - from the
copy it read several seconds earlier. Anything that saved that project during
those seconds was silently overwritten.

Reproduced, with a create landing in the middle of a send:

    OLD  applications after both writes : 0    <- LOST
         rest of the record intact?      : true
    NEW  applications after both writes : 1    <- kept

Applications gone, everything else untouched. That is exactly Gas Lane: 34
fields, contracted rates and both variations intact, applications empty.

/api/applications ALSO WROTE ON A GET. backfillAppNumbers saved the entire
project record on a page load, so every refresh was a write competing with that
window. A read that writes is a read that can roll back somebody else's save.


THE PART THAT SHOULD NOT HAVE HAPPENED
--------------------------------------
variation-send.js has done this correctly for a long time, and says why in its
own comment:

    Re-read immediately before writing: a variation edited in the portal while
    the customer had the page open would otherwise be rolled back by this save.

The same fault was found, understood and fixed for variations - and never
applied to applications. One rule fixed in one place. That is the fault class
this project keeps producing, and this time it cost real data.


THE FIX
-------
Every write now re-reads the record immediately before writing and applies only
what it changed:

  applications.js    all 7 POST writes go through a new commit() helper
  applications.js    the GET no longer writes at all - numbers are still filled
                     in for the response, and persisted next time something
                     writes deliberately
  application-send   re-reads after the PDF and the email, writes applications
                     and the AFA override only

Whole-record writes remaining in applications.js: 0.


AN AUDIT TRAIL
--------------
Every write now records what it did, at app:audit:<projectId> - last 50 per
project:

    { at, why, before, after, delta }

why is one of: create, send, mark-sent, revert-to-draft, delete,
set-hidden-pos, dismiss-month, set-variation-instructed.

The reason this is here: when your application went missing there was no way to
tell what had written the record. We spent this session narrowing it down by
elimination. Next time the answer is a single read. Neither the audit nor its
failure can affect the write it is recording.
