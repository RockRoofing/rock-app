pkg749 - Set an insured limit straight from the projection
===========================================================

DEPLOY OVER pkg748 (contains 742-748). Four files.

REPLACE:
  pages/api/business-financials.js
  pages/business-financials/cashflow.js
  pages/business-financials/monthly.js
  pages/business-financials/invoice-finance.js

WHAT
----
In the projected availability drill-down, every customer without a limit now has
an "add limit" button beside the name. Type the figure, it saves against that
EXACT name, and every application under that name is funded from then on.

Where a limit already exists the row shows "limit £X" in green instead, so you
can see at a glance which names are covered and which are not.

It writes to the same store as the limits table below and the Bibby CSV import -
one place, so nothing drifts.

WHY NOT JUST FUZZY-MATCH THE NAMES
-----------------------------------
I looked at doing that and it would be wrong on your data. Hollis Croft is
Torsion CONSTRUCTION; Market Drayton is Torsion PROJECTS. Two different entities
with two different limits. Normalising the names would merge them and fund one
against the other's cover.

Same for "Barnfield Construction Limited" and "Barnfield Construction Ltd." -
those probably ARE the same company, but the code cannot tell that apart from
the Torsion case without guessing. So the match stays exact and you set the
variant by hand, which takes one click and is always right.
