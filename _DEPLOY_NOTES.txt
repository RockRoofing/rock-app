WHAT I GOT WRONG
----------------
I shortened the sender fallback chains while consolidating them. The originals
differ from file to file, and I flattened them into one shape:

  original 'notify'      NOTIFY || FORMS || resend.dev
  pkg862                 NOTIFY || NOTIFY || resend.dev        FORMS lost

  original 'commercial'  COMMERCIAL || ACCOUNTS || FORMS || resend.dev
  pkg862                 COMMERCIAL || NOTIFY || resend.dev    ACCOUNTS, FORMS lost

So with NOTIFY_FROM_EMAIL unset in Vercel and FORMS_FROM_EMAIL set, a variation
email would have started arriving from onboarding@resend.dev instead of your
real address:

  correct        : Rock Roofing <notifications@rockroofing.co.uk>
  pkg862         : Rock Roofing <onboarding@resend.dev>     <- the fault
  as shipped now : Rock Roofing <notifications@rockroofing.co.uk>

Delivered, read, wrong sender, nothing on any screen to say so. Whether it
actually bit depends on which of those variables are set in your Vercel project,
which I cannot see.

Found because you asked whether the variation test was really necessary. It was.


THE LESSON, written into the file
---------------------------------
Consolidating a rule is only safe if the consolidated version is the SAME rule.
Four near-identical chains are not one chain. The comment in the file now says
so, and lists which files each chain came from, so the next person to tidy them
can see why they are not tidy.

This is the project's dominant fault class arriving from the other direction:
usually it is one rule written twice and left to diverge. Here it was four
rules merged into one that matched none of them.


THE FIX
-------
Each chain now mirrors its original exactly, env var for env var and default for
default, with the source file named against each:

  notify      NOTIFY_FROM_EMAIL, FORMS_FROM_EMAIL
              (variation-send.js, wip-lock.js)
  forms       FORMS_FROM_EMAIL
              (pre-start-send.js, outstandingInvoicesReport.js)
  accounts    ACCOUNTS_FROM_EMAIL
              (chase-email-send.js)
  commercial  COMMERCIAL_FROM_EMAIL, ACCOUNTS_FROM_EMAIL, FORMS_FROM_EMAIL
              (application-send.js)
