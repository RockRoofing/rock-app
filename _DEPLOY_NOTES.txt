pkg446 - "+ add period" did nothing
===================================

Deploy after pkg445. One changed file: pages/project/[id].js (literal [id] folder).


THE CAUSE
---------
The button worked. The row never appeared.

Pressing it creates an empty period - "2026-08#2": {} - ready for you to fill in. But the
code deciding which rows to render only included a key if it ALREADY HAD A DATE on it:

    if (r.applicationDate || r.valuationDate || r.paymentDate) keys.push(k)

An empty period fails that test, so the row was created in state and never drawn. Press
the button, nothing happens, press it again and you have silently made three of them.


FIXED
-----
An EXTRA PERIOD now earns a row whether or not it has dates - that is the entire point of
a button that adds a blank one.

A base month still needs a date to appear outside the rolling window, otherwise every
month anyone had ever touched would pile up at the top of the table.


AND A SECOND FAULT BEHIND IT
----------------------------
Even once rendered, the row would have vanished again the moment you cleared a date to
retype it. The cleanup rule removes any row with all three dates empty - which is right
for a base month, and wrong for a period somebody added deliberately and which has its own
"remove period" link.

Extra periods are now exempt. They go when you remove them, not when you empty them.


CHECKED WHILE IN THERE
----------------------
A freshly added blank period does NOT set off the "Still to complete" banner. It only
starts asking for the rest once you fill in the first date - which is the right moment,
since a half-filled period is a real gap and an untouched one is not.


IF YOU PRESSED IT A FEW TIMES ALREADY
---------------------------------------
You may have several blank periods saved on that project. They will all appear as rows
after this deploys - "August 2026 - period 2", "period 3", and so on. Use "remove period"
on the ones you do not want.
