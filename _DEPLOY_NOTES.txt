pkg381 - select all in the email queue, then act on the lot
===========================================================

Deploy after pkg380.

CHANGED FILES (replace)
-----------------------
  pages/crm.js
  pages/api/crm.js
  lib/crmEmailSync.js

NEW FILES: none.


WHAT YOU GET
------------
A tickbox on every row in the Emails review queue, and a bar across the top with
"Select all". Once anything is ticked the bar offers:

    Allocate to project     files them all against one job
    Do not assign           marks them all, in one go
    Clear                   drops the selection

The project search is the same one you already use, and after a bulk allocate you get
"Filed 23 against Poland House" with an Open project link.


SELECT ALL MEANS WHAT IS SHOWN, NOT THE WHOLE QUEUE
---------------------------------------------------
If you have searched for "Nishkam" and tick the box, you get the Nishkam ones. The label
says so - "Select all 14 shown" when a search is on, "Select all 14" when it is not.

Acting on 700 hidden rows because a filter happened to be applied is how people lose
things, so it does not work that way. To clear the whole queue, clear the search first.


ONE REQUEST, NOT HUNDREDS
-------------------------
Both bulk actions are a single call and a single write. Doing it the easy way - a loop of
single requests from the browser - would be 300 round trips and 300 rewrites of the same
key to clear 300 rows, and a failure halfway would leave the queue in a state nobody could
reason about. Either the whole batch lands or none of it does, with the rows put straight
back on screen if the write fails.

Bulk allocate also carries the THREAD links across, same as filing one by hand, so replies
to those conversations land on the right project from now on.


NO UNDO ON A BULK ACTION
------------------------
Single Do-not-assign still offers Undo. A bulk one does not - there is no sensible way to
unpick which of 200 you meant to reverse. The confirmation says so plainly before you
commit. Nothing is deleted from Outlook either way.

Selection clears on every refresh, because ids may no longer exist after one.
