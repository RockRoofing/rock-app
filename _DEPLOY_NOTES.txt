1. STATUS CHANGEABLE ON THE ROW
=================================
The Status cell is now a dropdown. In Query or Approved, straight from the table.
Approving a run of invoices is the common job and it should not need a modal opened
and closed for each one. It still works inside the comments window as well.


2. YOUR APPROVED ITEMS ARE NOT GONE - AND NOW IT SAYS SO
==========================================================
They were never deleted. The view defaults to In Query, so approving something makes
it leave that view, and a collapsed dropdown gave no clue where it went. That reads
as "the row vanished", which is exactly how you read it - and fairly.

Two changes:

  The filter is now a SEGMENTED CONTROL WITH COUNTS, not a dropdown:

      [ In Query (12) ]  [ Approved (3) ]  [ All (15) ]

  "Approved (3)" sitting there in plain sight says both that they still exist and
  where to find them. The counts are taken before the filter is applied, so they
  always describe the whole tab rather than the view you happen to be in.

  And while you are on In Query with approvals present, a line appears:
  "3 approved invoices are hidden by this view - they are not gone. Show them."

They leave the tab for good only when you re-tag them to a project in Xero.


3. MONTHS DEFAULTS TO ALL MONTHS
==================================
Done, and a fault of mine fixed with it.

The page already had a switchTab() that sets the defaults per tab - Overheads, for
instance, gets Categorised plus all months. In pkg827 I added the In Query
categorised default as a SEPARATE useEffect instead of using it.

Two mechanisms for one job, and they fought: switching to Overheads set Categorised,
then my effect saw a tab that was not In Query, saw Categorised, and set it back to
No. So pkg827/828 broke the Overheads tab's default.

The effect is deleted and In Query now sits alongside Overheads in switchTab -
Categorised, all months. One mechanism, and Overheads behaves again.

All months matters here in its own right: a query can sit for months, and defaulting
to last month hides the old ones, which are the ones that need chasing.
