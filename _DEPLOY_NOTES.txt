WHY pkg785 DID NOT FIX IT
--------------------------
My fallback read e.retentionPct - the percentage saved on the TRACKER ROW.

But the Ret % column resolves `e.retentionPct || x.retentionPct`. So where the
PROJECT carries the percentage and the row does not, the column still shows 5%
while my fallback saw nothing and returned zero. Exactly the fault I was fixing,
one field along.

Same for Applied for, which is a typed value on the row OR the figure from the
latest application.

THE FIX
-------
Retention Owed is now computed from precisely what the two columns beside it
display, using the same resolution:

  Ret %        e.retentionPct || x.retentionPct
  Applied for  typed on the row, else from the latest application

  pct on the ROW only        £5,613.19
  pct on the PROJECT only    £5,613.19
  applied-for typed on row   £5,613.19
  neither                        £0.00
  dashboard already right    unchanged

J109 should read £5,613.19 - £112,263.79 at 5%.

The card and the totals row both read this merged value, so they follow without
further change.

THE UNDERLYING POINT
--------------------
Three columns sat side by side and were computed from three different places.
Reading across them could not make sense. They now come from one resolution.

Setting the retention percentage in Project Details on J109 is still worth
doing - the cash flow, WIP and the application certificates all read the project
record, not the tracker row.
