THE FAULT
---------
retentions-due.js line 17 tested `e.release1Received`:

    const received = (e.release1Received ? r1 : 0) + (e.release2Received ? r2 : 0)

NOTHING EVER SETS THAT FIELD. It is left over from the tracker's old design, where
the green "released" state was inferred from the paid balance at render time and
never stored. So no release was ever deducted here - confirming a half on the
tracker changed nothing at all on this page, and every project showed its full
retention as still due for ever.

Same fault in two places: the balance figure, and the list of dated cash-in events.


FIXED
-----
The page now uses exactly the same rule as the tracker:

  manual mark true   -> released
  manual mark false  -> NOT released, even if an application says otherwise
  no manual mark     -> released if a half is ticked on the latest application

Checked, on a project with two 5,000 halves:

  nothing released           rows: 1st 5,000 + 2nd 5,000   outstanding 10,000
  1st confirmed by hand      rows: 2nd 5,000               outstanding  5,000
  both confirmed             rows: (none)                  outstanding      0
  1st via application        rows: 2nd 5,000               outstanding  5,000
  app says yes, overridden   rows: 1st 5,000 + 2nd 5,000   outstanding 10,000

Xero-derived rows carry appRelease1 / appRelease2, and the merge layers them onto
saved overrides - without that an edited row would show blanks where an untouched
one shows the flags.

The "Balanced with the Retention Tracker" check still holds, because both sides of
it now use the same rule.


ONE DEAD BLOCK LEFT ALONE, DELIBERATELY
---------------------------------------
There was an empty if-block reading

    if (retStatusOf(e) === 'complete') {
      // Complete = fully released; only include anything still flagged not received.
    }

with no continue and no filter - it did nothing. I have left the behaviour as it
is and replaced the comment with an explanation, because a project marked complete
whose halves are NOT released is exactly the money you would want chasing.
Skipping those would drop them from this page and break the balance check against
the tracker, which counts them.

Say the word if complete projects should in fact be excluded - it is a one-line
change, but it needs to be a decision rather than an accident.
