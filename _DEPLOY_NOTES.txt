WHY REFRESH BALANCES WAS FAILING
--------------------------------
It calls Xero's Balance Sheet report, which needs accounting.reports.balancesheet.read.
That scope was NOT in the connect list - same class of fault as the overpayments
one. It IS on your app's permitted list, so it has been added: reconnect Xero from
/connect and the button will work.

The error was being swallowed into a generic message, so it never said so.


BUT YOU WERE RIGHT NOT TO RELY ON IT
------------------------------------
Xero's Balance Sheet gives the BOOK balance - only what has been entered and
reconciled. The bank's real position is the STATEMENT balance, and the Xero API
does not expose it at all; it exists only in the bank feed.

So if reconciliation is a week behind, the opening figure is a week behind, and
every one of the 13 weeks inherits the error - SILENTLY, as a perfectly plausible
number.

MANUAL IS NOW THE PRIMARY SOURCE. A new Balances panel: add each bank account and
each credit card, type what is actually in it, and set the date you read it.
Kind (Bank / Card) drives the totals, so cards feed card debt and banks feed
opening cash.

Saves the moment you change anything, with saving / saved / NOT SAVED shown.

"Start from Xero's accounts" seeds the list from whatever Xero last returned, so
you are not typing account names from scratch.


XERO BECOMES A CROSS-CHECK, WHICH IS THE USEFUL PART
----------------------------------------------------
Where a manual account matches a Xero one by name, the row shows Xero's figure
and the difference:

    Xero GBP 38,200 (+GBP 4,300)

That gap is not an error - it is unreconciled items. It tells you how far behind
reconciliation is, which is worth knowing in its own right.
