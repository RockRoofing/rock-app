WHY pkg293 CHANGED NOTHING
---------------------------
The IHM form does not read lib/ihmSchema.js. It reads /api/templates, and that endpoint
does this:

    const stored = await getTemplate(key)
    sections: stored?.sections || DEFAULTS[key]

Once the IHM template has been edited ONCE in Admin > Templates, a stored copy exists in
the database and the code schema is ignored completely, for ever. Your template has been
edited, so my change to the schema file could never appear no matter how many times you
deployed it.

THIS ALSO EXPLAINS THE PROCUREMENT SAVINGS QUESTION. I said I could not find it in the
code - because it is not in the code. You added it through Admin > Templates, so it lives
in the stored template. That is also why my "this package will remove it" note in pkg293
was wrong: replacing the schema file was never going to touch it. Apologies - I should
have traced how the form actually loads its questions before telling you that.


THE FIX
-------
Fields in the code schema can now be marked `syncFromCode: true`. On read, any such field
missing from a stored template is merged into its section. The new checklist and its
"Anything else that needs adding?" box are both marked, so they will appear on your
customised template as soon as this deploys.

Only FLAGGED fields merge, so nothing else you have added or removed in the editor is
disturbed. Verified: a custom field you added is kept, the flagged checklist is added, and
an unflagged code field is NOT forced in.


REMOVING THE PROCUREMENT SAVINGS QUESTION - YOU DO THIS ONE
------------------------------------------------------------
Because it lives in the stored template, it has to be removed there:

  Admin > Templates > Internal Handover Minutes > Commercial section > press the red X on
  that question > Save.

I cannot do it from a code package. If I forced it, the merge above would be the wrong
tool - it adds, it does not delete, deliberately.


ALSO: THE EDITOR CAN NOW BUILD CHECKLISTS
------------------------------------------
"Checklist (tick list of items)" is now an option when adding a question in
Admin > Templates, with a box to type the items one per line. So you can add rows to the
Design Handover list, or build a checklist anywhere else, without needing me.
