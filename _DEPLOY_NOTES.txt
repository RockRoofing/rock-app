1. YOU WERE RIGHT - "ALLOCATED" WAS THE SAME AS "HELD"
------------------------------------------------------
The original code was

    retention612Allocated: Math.abs(retention612)

and retention612 is the SIGNED sum (sync-invoices.js:277) - deductions negative,
releases positive. So the old "612 Allocated" was the NET, which is exactly what
I had renamed to "612 Held". The tooltip claimed it was "retention actually
deducted", but the code never computed that. I quoted that tooltip at you as
justification without checking the code agreed with it. It did not.

Keeping the label "612 Allocated" for the gross figure would therefore have meant
the same column name showing a different number after deploy, with nothing on
screen to say so.

So the gross column is called "612 Deducted". Its tooltip says explicitly that
the old "612 Allocated" was the net and is a different number.


2. THE COLUMNS
--------------
  ... Retention Owed | 612 Deducted | 612 Released | tick | Ret % ...

  612 Deducted   gross withheld - the negative 612 lines
  612 Released   invoiced back out - the positive 612 lines

The net column is gone entirely. Any two of the three determine the third, and
the net was the one duplicating Retention Owed.


3. THE CHECK
------------
  Retention Owed - 612 Deducted + 612 Released, green at zero.

  nothing released           10,000 - 10,000 +      0  ->  tick
  half claimed + released     5,000 - 10,000 +  5,000  ->  tick
  both released                   0 - 10,000 + 10,000  ->  tick
  claimed on app, not in 612  5,000 - 10,000 +      0  ->  FLAG, out by -5,000
  deduction never coded      10,000 -  4,000 +      0  ->  FLAG, out by  6,000
  no 612 lines at all                                  ->  dash

The hover says which way it is out and by how much. No 612 lines gives a dash,
not a flag - there is nothing to reconcile against, and a red mark on every
pre-612 project would just train you to ignore the column.

Imported rows keep any "612 Allocated" figure from the spreadsheet on the record
but it is NOT fed into 612 Deducted - that column was the net, and putting a net
into a gross field would flag every imported row.


4. RELEASE MARKS - MANUAL AND AUTOMATIC
---------------------------------------
Click the 1st or 2nd release cell to mark that half released; click again to
undo. The date marked is stored.

A half ticked in the retention section of the project's latest application marks
the register automatically - the cell reads "released (app)".

Manual beats automatic BOTH WAYS: the flag is an explicit true/false, so clicking
a green "released (app)" cell records false and it stays false. That cell goes
amber reading "not released *".

There was no manual control at all before. release1Received existed but nothing
set it and the table never read it - the green state was inferred from the paid
balance hitting zero, gated on Final Account matching invoiced to within a pound,
which could never settle an old project whose release went out uncoded. That
guess is now only a hint: "due - looks paid", in pale blue.
