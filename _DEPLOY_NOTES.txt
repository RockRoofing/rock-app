2. CREDIT LIMIT APPLIES TO THE DEBT, NOT THE ADVANCE
----------------------------------------------------
Was:  advance = hasLimit ? min(debt x 60%, limit) : 0
Now:  overLimitDebt = max(0, debt - limit); advance = (debt - over) x 60%

Bibby fund UP TO the limit and disapprove only the excess. The old rule capped
the ADVANCE at the limit and ZEROED a customer entirely when no limit was
recorded - which is why the app disapproved 160,832 where Bibby disapproved
88,583.

  Torsion Projects   debt 71,838  limit fully used  -> 0, matches their 71,871
  Selsdon            debt 32,626  limit 25,000      -> was 0, now funds 15,000
  Wates              debt 148,130 limit 300,000     -> unchanged at 88,878

Selsdon is the case that proves it: Bibby disapprove 30,569 of theirs and fund
the rest. The app funded none of it.

4. A DATA FAULT THAT WAS INFLATING THE DEBT
-------------------------------------------
An application entered GROSS with "Previously certified" BLANK computes its
this-cert as the FULL cumulative value. On this page that presents a whole account
as one period's debt.

Any such application is now flagged red on the row - "N app(s) missing prev cert"
- so it reads as the data fault it is rather than a large application. J240
Application 4 is in exactly this state.
