WHAT YOU GET
------------

1. EMAIL ON THE DEAL
   Open any project. Below Notes, above History, there is now an "Email" section listing
   everything filed against that project - subject, who it was from, who it went to, the
   date, a preview, and "Open in Outlook".

   Long previews are cut at 180 characters with a "more" link, so a deal with forty emails
   is still readable.

   Each card shows the mailbox it came from and HOW it was matched (reference in subject,
   project name in subject, known contact, company domain, allocated by hand). That last
   bit matters: it is how you will judge whether the matching rules are pulling their
   weight before you commit to the backfill.

2. REVIEW QUEUE
   New "Emails" button in the black nav, next to Activities. It carries an amber count
   badge when there is anything waiting, so you do not have to go looking.

   Each row has:
     Allocate to project - opens a search box over your OPEN projects. Searches title,
                           company and contact name, so any one of the three will find it.
     Dismiss             - takes it off the queue. Asks first, because there is no undo.
                           The email itself stays in Outlook untouched.

   After allocating you get a confirmation with an "Open project" link, so you can check
   it landed where you meant.

   Both actions remove the row immediately and put it back if the save fails - the same
   pattern as Mark Done on the Activities tab.

ON THE 24-MONTH BACKFILL - DO NOT RUN IT YET
--------------------------------------------
The dry run matched 22 of 394 (~6%), and on the other mailboxes unmatched historical mail
is DISCARDED rather than queued. Run it now and roughly 370 emails are silently thrown
away, and you have no way of knowing whether they should have filed.

Now that the screens exist, the sensible order is:

  1. Let the hourly sync run normally for a few days. New mail that does not match goes to
     the review queue (it is not a backfill), so you will SEE the misses rather than
     guessing at them.
  2. Look at what is sitting in the queue. That tells you which rule is missing - most
     likely subject lines that name the site but not in the exact project title.
  3. Loosen the rules on that evidence, then backfill.

If you would rather not wait, I can change the backfill so unmatched historical mail is
queued rather than discarded, capped at a few hundred, so nothing is lost. Say the word.
It is a small change to lib/crmEmailSync.js.


TESTING IT
----------
Fastest proof it works end to end:

  1. Open any project, click the [CRM-nnn] chip in the header to copy the reference.
  2. Send yourself an email with that reference in the subject, BCC crm@rockroofing.co.uk.
  3. Hit /api/cron/crm-email-sync (no dryRun) - or wait for the hour.
  4. Reopen the project. It should be in the Email section, matched by "reference in
     subject".

For the queue: send a BCC with NO reference and nothing recognisable in the subject. After
a sync it should appear under the Emails tab.
