THE RULE, AS YOU SET IT
------------------------
Certified is the "Previously certified (gross)" box on the latest SENT application.
The typed figure. Nothing derived.

That box is stored as prevCertGross (pages/applications.js line 816): a number when
filled in, 0 on a first application, null when never touched. It is what prints in
the Previously Cert. column, and This Certificate = current less previously.


WHAT CHANGED FROM pkg795
-------------------------
pkg795 read sentSum.previously.gross - the computed previous column, which falls
back to recomputing from the preceding application where the box is empty. It now
reads prevCertGross directly, with NO fallback.

No fallback is deliberate. The certificate does fall back; this column should not.
A blank here means "nobody has filled that box in", which is worth seeing and is
fixable by typing it. Substituting a computed number hides it. The drill-down still
reports what the certificate would have fallen back to, marked as not used.

Second change, and the one that would have bitten: the merge tested whether the
value was TRUTHY. A first application legitimately carries 0, so 0 failed the test
and the row fell through to whatever had been typed on the tracker - showing a stale
figure on exactly the projects where nothing has been certified yet. It now tests
whether the box is SET, so a first application shows 0.00.

Verified across the five cases that matter, including that one:

  App 3 sent, box typed 120000        -> 120,000.00
  App 1 sent, box is 0 (first app)    -> 0.00        (pkg795 gave the typed row value)
  App 4 sent, box never filled        -> typed row value
  App 4 sent, box empty, nothing typed-> blank
  no sent application at all          -> typed row value


ALSO IN THIS PACKAGE (from pkg795)
-----------------------------------
1. APPLIED FOR was reading a DRAFT. dashboard.js had two different applications
   feeding the two columns - `latest` (any status) for Applied for, `latestSent` for
   Certified. A draft nobody issued silently superseded the sent one, which is why
   it only went wrong on some rows. Both columns now read the latest sent
   application. The tooltip has promised this since pkg792; the code never did it.

2. One prevGrossFor() rule, replacing two divergent copies in the same file.

3. APPLIED FOR / CERTIFIED DRILL-DOWN. Click the Applied for cell on any row: how
   many applications exist and how many are sent, which one each column read, its
   status, the typed box, This Certificate, and the fallback the column does not
   use. Always on. Banners for a superseding draft, no sent application, and an
   empty box.

4. CERTIFIED EDITABLE INLINE. Click the value, Enter saves, Escape cancels. Module
   scope component, so no remount-on-render focus loss. Saves through the existing
   saveEntry path; the diagnostic blob is stripped before writing to Redis.

5. Both modals now close on Escape as well as the x. Neither had an Escape handler.
