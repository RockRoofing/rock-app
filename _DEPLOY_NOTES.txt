"PROJECT APPLICATION DATES"
---------------------------
Fourth option in Sales received, alongside Per application / Weekly / Fortnightly.

It uses the application calendar already set on Edit Project Details - application
day, valuation day, payment day, final payment days - and produces one application
per calendar month in the period, dated on the VALUATION date, with cash on the
FINAL DATE FOR PAYMENT.

A second dropdown appears next to it so you can take cash on payment due instead
of the final date, since both are on the application and different customers pay
against different ones. Defaults to the final date, as you asked.

Worked through, with apply 25th / value 28th / pay 14th of the following month /
final +7 days, and 60,000 across three months:

  Sep 26   val 28/09   due 14/10   final 21/10   cash 21/10   19,800.00
  Oct 26   val 28/10   due 14/11   final 21/11   cash 21/11   19,800.00
  Nov 26   val 28/11   due 14/12   final 21/12   cash 21/12   20,400.00

It calls resolveAppDates() - the SAME function the applications screen uses - so
the forecast lands on the exact dates the real applications will, rather than an
approximation that drifts the moment one of the rules changes. Per-month date
overrides are honoured too: an override of 31/10 valuation and 20/11 payment came
straight through in testing.

The monthly Sales % row stays visible for this cycle, because it is still one
application per calendar month and the split is what decides how much each one is
worth.


THE GUARD
---------
A valuation day with no payment day resolves to a BLANK cash date, which would
have dropped that money out of the forecast entirely and silently. Confirmed in
testing. So the option only produces a schedule when the calendar can actually
yield a payment date, and otherwise says:

  "No application calendar on this project - set the valuation and payment days
   on Edit Project Details."

When it is working, the line underneath previews it: "val 28/09 -> cash 21/10,
then 2 more".
