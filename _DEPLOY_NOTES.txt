THE CAUSE - FOUND
-----------------
pages/connect.js:17 requested these scopes:

  openid offline_access accounting.invoices.read accounting.contacts.read
  accounting.reports.profitandloss.read accounting.settings.read
  accounting.manualjournals.read accounting.banktransactions.read projects.read

accounting.invoices.read covers Invoices AND CreditNotes - which is exactly why
bills and credit notes sync perfectly. OVERPAYMENTS and PREPAYMENTS sit under
accounting.transactions, which was never requested. Hence a 401
AuthorizationUnsuccessful on that endpoint alone, on a token where everything
else works.

Nothing in the fetching code could ever have fixed this.


WHAT TO DO
----------
1. Deploy this package. Check the heading reads "Bills to Pay v577".

2. GO TO /connect AND RECONNECT XERO.
   This is the bit that actually matters. Adding a scope does NOT apply to an
   existing connection - the token was issued under the old scope list and keeps
   those permissions until you re-authorise. The consent screen will now ask for
   the extra permission.

3. Press Sync bills.
   Expect: "117 bills, 1 credit notes, 4 overpayments."
   Total drops 307,471.06 -> 302,771.49.


IF THE SCOPE IS STILL MISSING
-----------------------------
The 401 no longer reports Xero's "AuthorizationUnsuccessful", which tells you
nothing. It now says:

  "Xero has not granted accounting.transactions.read, which Overpayments needs.
   Reconnect Xero from /connect to grant it - adding the scope does not apply to
   an existing connection."


THE TWO EARLIER MISTAKES, BOTH MINE, BOTH THE SAME SHAPE
--------------------------------------------------------
Reusing a neighbouring pattern without checking it meant the same thing:

  pkg573  tested Type !== 'SPEND'. Xero uses "SPEND-OVERPAYMENT".
          fetchBankTransactions ten lines up already used startsWith('SPEND').
  pkg576  filtered Status=="AUTHORISED", copied from the credit-note fetch. An
          overpayment is already paid, so Xero marks it PAID.

Both are fixed. There is no status filter now - RemainingCredit > 0 is the real
test of "still outstanding", and only VOIDED/DELETED are dropped.


ALSO IN THIS PACKAGE
--------------------
Cost account filter beside the supplier filter - searchable, remembered per
browser. A bill shows if ANY of its lines is on a picked account. Credit notes
and overpayments carry lineCodes so they cannot vanish under a filter and push
the total up.

Sync now reports what it found, with a full breakdown when nothing comes through.
