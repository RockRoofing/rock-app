THE CHANGE
===========
Three project pickers now filter as you type:

  Variation Tracker    the Project filter in the filter box
  Variation Tracker    the Project field in the Add Variation modal
  Variation Builder    the project selector at the top

Type any part of the job number or the name and the list narrows. Arrow keys move,
Enter picks, Escape closes. Clicking the field clears the box so the whole list is
there again - you are choosing, not editing what is already chosen.


WHY NOT JUST LEAVE THE NATIVE SELECT
--------------------------------------
Browsers do have type-ahead on a <select>, but it only matches the START of the
option text. Every option here reads "J228 - Farmstead Drive", so typing "Farmstead"
matches nothing at all - and the job name is how people remember a job. Typing the
number worked; typing the name did not, which is the half that is missing rather
than the half that is there.

Matching is anywhere in the label, and a prefix match ranks first, so "J228" puts
J228 at the top rather than some other job that mentions it.

    ""         all options
    "farm"     J228 - Farmstead Drive, J250 - Farmstead Annexe
    "J228"     J228 - Farmstead Drive
    "warwick"  J194 - Warwick Road      <- name match, not a prefix
    "zz"       No project matches that


ONE COMPONENT, NOT THREE
-------------------------
components/SearchableSelect.js is shared by all three. Three separate dropdowns is
how they end up behaving differently from one another - which is the fault behind a
good deal of what has been fixed this week.

Customer, CM, Estimator and Instructed? are deliberately left as plain selects. They
are short lists and a native select is quicker on those; a search box on a list of
six is friction, not help.


A DETAIL
---------
The list closes on a click anywhere outside it, tracked on the document rather than
with onBlur. onBlur alone does not work here: the list sits inside the same box, so
clicking an option blurs the input first and the list would close before the click
landed on it.
