pkg530 - an instructed variation is locked
==========================================

Deploy after pkg529.

CHANGED FILES (replace)
-----------------------
  components/VariationBuilder.js
  pages/api/project/[id]/settings.js     <- literal [id] folder

NEW FILES: none.


THE WORST OF IT, FIXED FIRST
------------------------------
Every save wrote instructed: 'no' unconditionally.

So opening an instructed variation and pressing save would have WITHDRAWN the customer's
instruction - silently, and taken it out of the anticipated final account with it. It now
keeps 'yes' where it was already 'yes'.


LOCKED ON SCREEN
----------------
Open an instructed variation and you get:

    Locked. This variation has been instructed by the customer and cannot be changed.
    Raise a new variation for any change to the works or the value - that is also how
    it reaches the account correctly. The workings can still be viewed.

Everything is read-only: the number, date, requested by, description, the items, the
clarifications. Add item and Remove are gone, Save is greyed, and Workings opens as
"Workings (instructed - view only)".

Download PDF and Send reminder still work, because neither changes anything.


AND LOCKED ON THE SERVER
------------------------
The screen is a convenience; this is the control. The settings endpoint now refuses any
POST that changes or removes an instructed variation:

    unchanged            allowed
    value edited         REFUSED
    description edited   REFUSED
    reverted to draft    REFUSED
    removed              REFUSED

The customer authorised a specific scope at a specific value, and their instruction is the
record we would produce if it were ever disputed. Editing it afterwards would leave their
signature attached to figures they never agreed to.

A change to instructed work is a new variation - which is also the only way it reaches the
account properly.
