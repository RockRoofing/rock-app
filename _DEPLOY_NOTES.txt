pkg855 - Wrap the top-level API routes. STILL DORMANT.
======================================================

WHAT SHOULD LOOK DIFFERENT AFTER DEPLOYING THIS:  NOTHING.

The wrapper does nothing at all while CONTROL_REDIS_URL is absent from Vercel,
which it still is. Every route calls its handler straight through, exactly as
now. This is a big package by file count and a small one by behaviour.


REQUIRES pkg854 TO BE LIVE (lib/withTenant.js).


BIGGER UPLOAD THAN USUAL
------------------------
150 files, all in pages/api. Drag the pages/api FOLDER from this package into
GitHub - it replaces those 150 and leaves the cron, xero, project and admin
subfolders untouched, because they are not in here.

No new files to create by hand. No lib files. Nothing to configure.


WHAT CHANGED IN EACH FILE - three lines, identical everywhere
-------------------------------------------------------------
Before:
    export default async function handler(req, res) { ... }

After:
    import withTenant from '../../lib/withTenant'
    async function handler(req, res) { ... }
    export default withTenant(handler)

Nothing inside any handler changed. No key names, no logic, no responses.

Done this way - handler becomes a plain function, wrapper applied at the bottom -
rather than wrapping it in place, because 7 files have other exports AFTER the
handler (export const config, export { computeApplicationSummary }). Wrapping in
place needs brace matching, and brace matching in a script across 150 files is
exactly where one goes wrong quietly.


TWO ROUTES DELIBERATELY NOT WRAPPED
-----------------------------------
health-check.js
  A liveness probe has to answer even when tenant resolution is broken. That is
  the entire point of one. Not in this package, left as it is.

admin/tenant-setup.js
  Not in this package (it lives in a subfolder). It must work BEFORE a customer
  exists in the registry - wrapped, it would 404 on the very request you need in
  order to stamp Rock's identity. Chicken and egg.

THE 22 CRONS ARE ALSO NOT IN HERE, and that is the important one. A cron has no
meaningful web address - Vercel calls it on the deployment URL. Wrapping them
would silently bind every cron to whichever host it was called on, which for you
means every cron runs as Rock forever and never runs for anyone else. They need
a loop over customers, not a wrapper. Own package.


THREE FILES RE-SHIPPED FROM pkg854
----------------------------------
sync-status.js, hidden-projects.js and staff.js were wrapped inline in pkg854.
Same behaviour, different shape. Normalised to match the other 147 so that a
single grep for "export default withTenant(handler)" is a complete check of the
whole application rather than a partial one.


CHECKS I RAN
------------
- esbuild compile on all 151 top-level routes: 0 failures.
  It earned its keep: the first run of the script inserted the import INSIDE a
  multi-line import statement in two files (hs-renewal-settings.js and
  site-badges.js). esbuild caught both. Fixed by inserting above the first
  import instead, a position that cannot be inside another statement.
- Four structural checks on every one of the 150: imports withTenant, handler is
  a plain function, exactly one default export, and that export is the wrapped
  one. 0 failures.
- REVERSED the wrapper edit in memory on all 150 and compared the result to the
  file as it stood before this pass. 111 reverse exactly to the original; 37
  reverse to the version pkg843-852 produced; the remaining 2 were hand-checked
  line by line and are the wrapper edit and nothing else. So no file was touched
  beyond the three lines above.
