1. VARIATIONS - THEY WERE NEVER THERE
-------------------------------------
Two reasons, and the second one was mine:

  workApp = { contractWorks: rows, variations: [], ... }   <- hard-coded empty
  latestApplication in pkg542 returned contractWorks only  <- dropped variationData

So instructed variations added nothing to forecast revenue, and no variation
percentage carried over from the last application.

Now: a Variations table under the contract works, with a cumulative % complete
per variation, seeded from the last application exactly as the works are.

TREATED THE SAME WAY AS THE CONTRACTED SCOPE, as you asked:
  - revenue this period  = variation value x % ADDED this period
  - labour this period   = the variation's LABOUR element x % added
  - materials            = the variation's MATERIALS element x % added, and it
                           feeds the "Fill from line items" button alongside the
                           works materials

INSTRUCTED ONLY BY DEFAULT. Uninstructed variations are listed, greyed, badged
"Not instructed", and excluded until you tick them in. Ticked ones behave
identically from then on. Which ones you ticked is saved with the forecast.

Worked through, no MCD or retention, V01 worth £1,000 split 400 materials /
400 labour / 200 profit, moved 50% -> 75%:
  revenue this period    £250.00
  labour this period     £100.00
  materials this period  £100.00
Nothing moved at all -> £0.00 on all three.

A NOTE ON A LIVE BUG ELSEWHERE. variationValueToDate() in lib/applications.js
tests `v.instructed === false`. On this codebase instructed is the STRING
'yes'/'no', so 'no' sails through and an uninstructed variation is counted IN
FULL. Confirmed: feeding it one uninstructed £500 variation returns £500. This
package cannot hit it - only ticked variations are ever passed in, and they go in
with instructed: true. But it is still live in the applications maths and worth a
package of its own. Say the word.


2. MATERIALS ON SITE - SHOWN, NOT SPENT
---------------------------------------
The two screens mean opposite things by the same words:

  On an application  materials on site are stock you have bought and certified to
                     the customer with a mark-up. Money IN.
  On this forecast   materials lines are supplier payments with a payment term,
                     written only to the matOut stream. Money OUT.

Per your answer, what has already been claimed is now NOTED rather than moved
into either side. A purple panel above the materials table reads:

  "£12,480.00 of materials on site already claimed on Application 4 (3 lines).
   That is money IN from the customer. The lines below are money OUT to
   suppliers, so this figure is shown for reference only and is not added to
   either."

It only appears when the last application actually claimed some.
