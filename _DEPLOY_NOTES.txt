pkg476 - a project opened in a new tab showed no activities
===========================================================

Deploy after pkg475. One changed file: pages/crm.js. No new files.


WHY ONLY IN A NEW TAB
---------------------
That detail was the whole diagnosis, so thank you for it.

Opening a project loads two things: the deal list (crm:deals, about 6.4MB) and that
project's activities and notes (tiny). loadDealSubs merged the second into the first with

    setDeals(prev => prev.map(d => d.id !== id ? d : { ...d, activities: [...] }))

FROM THE BOARD the deals are already in memory, so the merge lands.

IN A NEW TAB both fetches start together, and the small one regularly wins. The map then
matches nothing, does nothing - and worse, the "already loaded" flag had been set on the
first line of the function, so it never tried again.

The result is a project with no activities, showing the blank "add activity" form. The
activity was never lost; this page had simply never received it.


FIXED
-----
The flag is only set once there is actually a deal to merge into. If the deals have not
arrived, the request is remembered and retried the moment they do.

Tested: deferred on a new tab, retried when the deals land, merged once, and a second call
is still a no-op.

Nothing else changes. From the board it behaves exactly as before, because the deals were
always there.


WORTH KNOWING
-------------
This will have affected notes, filed email and the timeline in the same way, not just
activities - anything loadDealSubs brings in. If a project opened from a link has ever
looked emptier than it should, this was why.
