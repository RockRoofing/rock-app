THE FILTER
----------
"Cost accounts" multi-select next to the supplier filter. Same behaviour -
searchable, Clear, Select shown, and a count in the label. Searches on code or
name, so "310" and "materials" both find it.

Only accounts that actually appear on the current bills are listed. The full
chart is hundreds of accounts and most never touch a supplier bill.

A bill is shown if ANY of its lines is on a picked account. Bills are NOT split
across accounts - a mixed bill appears in full under every account it touches,
because showing part of a bill would make the Filtered total wrong.

  pick 310        ->  materials bill, mixed bill, credit note
  pick 321        ->  mixed bill only
  pick 310 + 400  ->  materials, plant hire, mixed, credit note


THE SELECTION IS REMEMBERED
---------------------------
Saved to localStorage, the same approach the CRM already uses for its view prefs.
Deliberately NOT a Redis config key - that is shared, so one person narrowing the
filter would silently narrow it for everybody else on the same page.

The restore runs before the save effect can fire, so an empty initial state never
overwrites a stored selection on load.


TWO THINGS THAT NEEDED FIXING TO MAKE IT WORK
---------------------------------------------
CREDIT NOTES HAD NO ACCOUNT CODES. lib/xero.js stored lineCodes on bills but not
on credit notes, so every credit note would have vanished under any filter - and
because credits are NEGATIVE, the filtered total would have gone UP. A credit
silently disappearing is worse than one showing under a code you did not pick.
They now carry lineCodes the same way.

THE API RETURNED NO ACCOUNT NAMES. It now returns the codes present on the
current bills paired with their names from config:chart-of-accounts, so the list
reads "310 Materials" rather than a bare number.


WORTH KNOWING
-------------
A bill with NO account codes at all drops out under any filter - there is nothing
for it to match. That is correct, but if you see the filtered count fall further
than expected, that is why. Codes come from the bill sync, so anything synced
before lineCodes existed will have none until you press Sync bills.
