YOU WERE RIGHT - STOP REBUILDING IT
====================================
The highlighted cell on your screenshot, Proj. Final Account / Application Total,
is 140,274.20. That number already exists as a stored figure.

When an application is sent, applyAfaOverrideFromApp() in pages/api/applications.js
writes its Anticipated Final Account straight onto the project:

    project.afaOverride       = sum.anticipatedFinalAccount
    project.afaOverrideAt     = Date.now()
    project.afaOverrideAppSeq = app.seq

That is the printed figure, saved at the moment it was issued.

The register was ignoring it and REBUILDING the same number from the stored
application - measuredContractSum + variationsFinal. A rebuild only matches if the
stored record is identical to what the page had in hand when the total was produced,
and the applications page computes its summary from workApp, the live edit state
(pages/applications.js line 685), not from the saved record. So the rebuild could
drift, and no amount of correcting the formula fixes that - the formula was never
the right approach.

Gross AFA now reads the stamped figure. No formula.


ORDER OF PREFERENCE
--------------------
  1. afaOverride stamped BY the latest sent application  <- as issued, no arithmetic
  2. rebuilt from the stored application                 <- only where nothing was
                                                            stamped, i.e. applications
                                                            sent before this existed
  3. a manual override
  4. project details

Step 1 is only taken when afaOverrideAppSeq matches the latest sent application. A
stamp left by an OLDER application is not the current figure, so it drops to step 2
and is treated as an override, not as the application's number.

The stamp can land on either settings record - project:{id} or project:{jobNo}, the
same duality that hid the applications themselves in pkg797 - so both are read and
the most recent stamp wins.

Verified:
    stamped by latest sent app    -> 140,274.20  (as issued)
    stamped by an older app       -> rebuilt, flagged as an override
    no stamp at all               -> rebuilt from the application
    no stamp, no application      -> project details

ONE CONSEQUENCE WORTH KNOWING
------------------------------
Because the stamp is written at SEND, editing a sent application without re-sending
it will not move Gross AFA. That is deliberate - the register should show what went
to the customer - but it does mean re-sending is what republishes the figure.
