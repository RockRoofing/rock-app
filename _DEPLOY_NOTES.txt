WHAT CHANGED IN EACH
--------------------
Each file previously opened its own connection to Redis. Each now does:

    const redis = await getClient()

and everything after that line is untouched. Key names, logic, responses and
error handling are all identical.


TWO THINGS WORTH KNOWING
------------------------
1. getClient() never returns null. Several of these files had a guard like
   "if (!redis) return 500 No Redis" or "redis ? await redis.get(...) : null".
   Those guards existed because a missing environment variable produced a null
   client. That cannot happen now - lib/db.js falls back to an in-process store
   instead - so the guards have been removed or left as dead code where
   removing them would have widened the diff. No behaviour change on a working
   deployment.

2. clear-financial-data.js uses scan() with a cursor. That is supported by the
   shared client and was added in pkg843 alongside del().
