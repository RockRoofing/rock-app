pkg485 - status flips to Sent, and you land back on the list
============================================================

Deploy after pkg484. One changed file: pages/applications.js. No new files.


WHY THE BADGE STAYED ON DRAFT
-------------------------------
The server was doing its job - it marks the application sent and returns it. The parent's
list was updated too.

The EDITOR was not. Since pkg444 it keeps its own copy of the application, so that a save
landing mid-typing cannot overwrite what you are entering, and that copy is only refreshed
when a DIFFERENT application is opened. The same one coming back marked sent was
deliberately ignored.

So the record was correct, the list behind you was correct, and the badge in front of you
was wrong.

Now updated on both routes - emailed to the customer, and marked as sent by hand.


AND IT TAKES YOU BACK TO THE LIST
-----------------------------------
After either route: the message shows briefly, then you land on that project's
applications table, refetched.

The row already shows a green Sent badge and its button changes from Open to View, so the
action is visibly done rather than something you have to go and confirm.

The 400ms pause is deliberate - "Application sent." needs a moment on screen or the view
changes before you have registered that anything happened.
