DEPLOY NOTES - FIX: cron jobs were blocked by middleware (401) - weekly report + notifications
=============================================================================================

ONE file, an EDIT - just replace it.
  middleware.js

THE ACTUAL PROBLEM (found from the Vercel cron log)
  The weekly-report cron WAS running every hour, but the request was being rejected by the
  app's middleware with 401 Unauthorized - before it ever reached the send code (the log
  showed "No outgoing requests"). On the main portal domain the middleware required a
  logged-in session for everything except a short allow-list, and /api/cron was NOT on
  that list. Vercel's cron caller has no login session, so every run was blocked. That is
  why "Last sent" was always "never".

  This also affected /api/cron/notifications (the email notification builder) - same block.
  So the notification emails would not have been sending either.

THE FIX
  Middleware now lets /api/cron/* through without a portal login. These endpoints are
  instead protected by an optional CRON_SECRET:
    - If you set an env var CRON_SECRET, Vercel automatically sends it as
      "Authorization: Bearer <CRON_SECRET>" on scheduled runs, and the middleware requires
      it. (You can also test in a browser with ?key=<CRON_SECRET>.)
    - If CRON_SECRET is NOT set, cron routes are simply allowed through so the jobs work.
