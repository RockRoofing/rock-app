pkg427 - test2 and test3 share an id. Here is why, and the way out.
===================================================================

Deploy after pkg426. If pkg426 is not in yet, deploy both - this builds on it.

CHANGED FILES (replace)
-----------------------
  pages/crm.js
  pages/api/crm.js

NEW FILES: none.


WHAT IS HAPPENING TO TEST2 AND TEST3
--------------------------------------
They have the same id. Everything in the CRM is keyed by id, so they are not two projects
as far as the code is concerned - they are one project listed twice.

    clicking test3   -> deals.find() returns the FIRST match -> opens test2
    deleting test3   -> the delete filters on id -> removes BOTH

You were right that it looked like it was deleting the other one. It was.

Reproduced on the bench, both behaviours.

The cause was in pkg426: new ids came from a counter hard-coded to 900000 that reset on
every page load. Two projects created in different sessions both got 900000.


WHY pkg426 WAS NOT ENOUGH
-------------------------
It seeded the counter above the highest existing id, which fixes one browser. But four
people using the CRM at once each compute "highest + 1" from their own copy of the list
and all reach the same answer. Demonstrated: two users, same list, same id.

New ids are now a MILLISECOND TIMESTAMP. It cannot repeat across sessions or between
people, it is still a plain sortable number, and there is a guard that steps past any id
that somehow already exists.


AND DELETE NO LONGER TAKES TWO
------------------------------
Both the browser and the server now remove exactly ONE project, not everything sharing
that id. If a duplicate is still present, the shared activities, notes and email are left
alone - otherwise deleting one project would gut the other.

Ids cannot collide any more, but a delete that can destroy a project you did not ask about
should not depend on nothing upstream being broken.


WHAT TO DO WITH TEST2 AND TEST3
---------------------------------
1. Deploy this.
2. Go to /crm-scores, red panel at the top, "Check for duplicates". It will list them.
3. "Renumber" - test2 keeps 900000, test3 gets a fresh id.
4. Both then open and delete independently. Delete them both if they were only tests.

Any project created from now on gets a timestamp id and cannot collide with anything.
