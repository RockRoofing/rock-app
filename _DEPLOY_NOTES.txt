WHY IT TURNED INTO 0
=====================
Nothing was wrong with the input, the save or the server. The value was written
correctly and then overwritten on the way back out.

The merge read:

    certified: x.certifiedSetOnApp ? String(x.certifiedGross) : (e.certified || '')

certifiedSetOnApp means "the Previously certified (gross) box is SET on the latest
sent application". On a FIRST application that box is legitimately 0 - nothing has
been certified before it. So the flag is true, the value is 0, the application wins,
and whatever was typed is discarded and replaced with zero.

    app 1 sent (box 0), user types 5000  ->  "0"

On any project whose latest sent application is App 1, Certified was not editable at
all, however editable the cell looked. That is a direct consequence of pkg796, where
I made a zero display as 0.00 rather than fall through - correct for display, wrong
once the cell became editable in pkg797.


THE FIX - TWO PARTS
--------------------
1. A REAL FIGURE FROM THE APPLICATION STILL WINS. A ZERO DOES NOT.

   Where the box holds an actual value it continues to beat anything typed, exactly
   as you specified. Where it holds 0, a typed value is used, and 0 still shows when
   nothing has been typed.

       app 1 sent (box 0), user types 5000   ->  5,000.00   editable
       app 1 sent (box 0), nothing typed     ->  0.00       editable
       app 3 sent, box 119,506.55            ->  119,506.55 READ-ONLY
       no sent app, user types 5000          ->  5,000.00   editable
       no sent app, nothing typed            ->  blank      editable

2. THE CELL NO LONGER INVITES AN EDIT IT WILL THROW AWAY.

   Where the application owns the figure, the cell is read-only - no box, no pencil,
   no "Add". Hovering explains why: the value comes from the Previously certified
   (gross) box on application N and must be changed there. Previously it looked
   editable, accepted a value, saved it, and silently reverted.

Applied to BOTH row builders, through the shared dashFields() from pkg804, so the
behaviour is identical whether or not a row has a saved entry.
