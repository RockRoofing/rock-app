pkg364 - Name the mailboxes directly
=====================================

REPLACES pkg302 through pkg363. Deploy this one only.

CHANGED FILES
-------------
  lib/msGraph.js          the fix
  everything else unchanged since pkg363

If pkg363 is already deployed, lib/msGraph.js is the ONLY file that has changed.


WHAT THE EMPTY RESULT MEANT
----------------------------
    {"ok":true,"mailboxes":[], ...}

Not an error - it found the group and the group reported no members. A mail-enabled
security group created through Exchange PowerShell does not reliably expose its membership
through Graph, even with GroupMember.Read.All granted. The two systems keep group
membership in slightly different places.


THE FIX - ADD ONE MORE VERCEL VARIABLE
----------------------------------------
    MS_MAILBOXES = james@rockroofing.co.uk,edita@rockroofing.co.uk,Niall@rockroofing.co.uk,roman@rockroofing.co.uk

Comma separated, no spaces needed. When this is set the group is not consulted at all -
the app syncs exactly those mailboxes and nothing else.

Add it, REDEPLOY, then run the dry run again.

This is arguably the better arrangement anyway: the app no longer needs to read your
directory to work out who to sync, and the list is visible in one place rather than
inferred. You can even remove GroupMember.Read.All from the app registration afterwards if
you want it tighter still.

KEEP THE GROUP AND THE ACCESS POLICY. They are what stop the app reaching anyone else's
mailbox - MS_MAILBOXES only says who to ASK for. If the two ever disagree, Exchange wins
and refuses. Both together means a mistake in either one cannot expose a mailbox it should
not.

The group lookup is still there as a fallback, and now says plainly what to do if it comes
back empty rather than reporting success with nothing.
