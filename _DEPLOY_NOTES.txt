1. REVERT TO LAST APPLICATION
-----------------------------
New button on the "Contract works" header: "Revert to Application N".

Puts every line back to the percentages on the last real application, along with
its MCD and retention. Revenue and labour this period then read zero, and you add
only what you are claiming on top.

It targets the APPLICATION specifically, not whatever the rows happened to be
seeded from. A button with that label that quietly reverted to a forecast would
be lying. Hidden when the project has no applications.


2. REVENUE ZERO UNTIL SOMETHING EXTRA IS CLAIMED
------------------------------------------------
This mostly followed from pkg542 - seed and prior are the same record, so the
increment is zero - but there was a hole.

`prior` filtered on "ends before this period starts". Pick a period beginning
before the last application's valuation date and the application dropped out of
the running, prevGross fell to zero, and the whole value to date was spread
again. Exactly the fault pkg542 set out to fix, reachable through the date box.

Money already claimed cannot be un-claimed by choosing an earlier start date. So:

  NEW forecast   prior = the latest certificate, whatever period you pick.
  EDITING        prior = the certificate ending before this one's period, so a
                 forecast in the middle of a chain still deducts only what came
                 before it.

Checked: seed from an application, change nothing, revenue this period = 0.00 and
materials this period = 0.00.


3. MATERIALS FROM LINE ITEM RATES
---------------------------------
New button on the "Materials on site" header: "Fill from line items (£X)".

It values the material rate on each contract works line (matRate x qty) against
the percentage ADDED this period, not the cumulative figure - the same increment
logic as revenue and labour. Materials for work already certified were bought
long ago.

  Strip out  100 m2, material rate £4.00, moved 40% -> 60%
  = 100 x 4 x 20% = £80.00

It adds ONE line, not one per rate item - this is a cash-timing figure and thirty
supplier-less lines all landing on the same day is noise. The line is tagged, so
pressing the button again replaces it rather than doubling it up. It is an
ordinary material line once added: retype the value, change the delivery day, set
its own payment term, or delete it.

Disabled with an explanation until you have actually moved a percentage.

Lines that go BACKWARDS are ignored rather than netted off. A reduced percentage
does not send materials back to the supplier.

The manual "+ Add material" route is untouched, so materials this period can come
from either source, or both.
