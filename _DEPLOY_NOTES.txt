WHAT'S NEW (Operations > Project Management > Planning)
  A new "Planned / Actual" column sits BEFORE the Start column.

  - Start (unchanged) = the CONTRACTED start date.
  - Planned / Actual = the first on-site day in the gantt (earliest allocated bar).
    It auto-populates from the gantt, so it can never drift from the real plan.
      * Blank ("add bars") until the project has its first allocation.
      * Shows BLUE while it's in the future (planned).
      * Shows GREEN once it's on/before today (i.e. actually started).
  - Editing the Planned / Actual date SHIFTS THE WHOLE PROJECT'S GANTT so the first
    bar lands on the new date - every allocation for that project moves by the same
    number of days. Only that one project moves. (Shifts silently, as agreed.)

WHY IT MATTERS
  This makes the plan's timing a single source of truth: move the planned start and
  the whole sequence follows. The upcoming Commercial Cash Flow page will read this,
  so cash timing will move automatically with the planned start - Commercial won't
  need to re-do anything when Operations reschedule.

NOTE: it moves the allocation bars by re-dating them. Marking days Actual is still
what confirms them; a started project's date naturally becomes the actual start as
days pass.
