I CANNOT SEE YOUR SERVER, SO THIS MAKES THE FAILURE VISIBLE
------------------------------------------------------------
The send was fire-and-forget: if it failed, nothing was reported and the history line
still said "Emailed: Roman". That was my mistake - it made a silent failure look like a
success. Three changes:

1. The toolbar now REPORTS the outcome next to Saved:
       "Emailed Roman Jarosz."                       - it went
       "Mention email not sent - 403 <reason>"        - it did not, and why
   Shows for 8 seconds. The note itself still saves either way.

2. Whatever Resend says back is now kept instead of discarded. The status code and the
   first 300 characters of its reply come through to that message.

3. The history line says "Mentioned: Roman" rather than "Emailed: Roman", because the
   history should not claim something that may not have happened.


RUN THIS FIRST - IT ANSWERS THE QUESTION WITHOUT SENDING ANYTHING
------------------------------------------------------------------
On any portal page, F12 -> Console. Type  allow pasting  and Enter if Chrome asks. Then:

    fetch('/api/crm',{method:'POST',headers:{'Content-Type':'application/json'},
      body:JSON.stringify({action:'mention-diagnose',body:'@Roman test'})})
      .then(r=>r.json()).then(console.log)

It sends no email. It returns:

    mentionableUsers   everyone who CAN be mentioned, with their email address
    resolved           who "@Roman test" actually matched
    resendConfigured   true/false - is RESEND_API_KEY set
    from               the address it would send FROM

WHAT THE ANSWER WILL PROBABLY BE
--------------------------------
My strongest suspicion, in order:

  a) mentionableUsers is EMPTY or missing people.
     Users are only mentionable if they have an email address on their portal account AND
     a pre-contract or admin role. A user with no email set is silently skipped - there is
     nowhere to send to. Check Admin -> Users.

  b) "from" reads  Rock Roofing <onboarding@resend.dev>
     That is Resend's test sender. It is only allowed to deliver to the address that owns
     the Resend account - everyone else is rejected. If that is what you see, set
     FORMS_FROM_EMAIL in Vercel to a verified rockroofing.co.uk sender and it will work.
     This would also explain why the daily activity email may only ever have reached you.

  c) resendConfigured is false - the key is missing on this deployment.

Send me what it returns and I will know which. If it is (b) it is a Vercel setting, not a
code change.
