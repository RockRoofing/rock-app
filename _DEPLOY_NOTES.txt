pkg351 - Fixes the Activities tab crash from pkg349
====================================================

REPLACES pkg302 through pkg350. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js            THE FIX
  pages/api/crm.js        unchanged since pkg346
  lib/crmImportMap.js     unchanged since pkg305


WHAT HAPPENED
-------------
"activityStaleFilter is not defined" - my mistake in pkg349.

Taking the diagnostics out, I removed a block by line range and it took an adjacent
definition with it. That one was still in use: it is the check that spots a saved filter
matching nothing, so the filter can be ignored instead of silently emptying the table.

Used in one place, defined in none - so the tab threw the moment it rendered.

It is back, with a comment saying what it does so it does not get swept up again.


WHY THE BUILD DID NOT CATCH IT
-------------------------------
It compiles perfectly well. JavaScript only complains about a missing name when that line
actually runs, which is when you open the tab - not when it is built. So "Compiled
successfully" was never going to tell us.

I have since scanned every value passed into the Activities table and the deal view for
names that are used but never defined. Nothing else is missing.

I am adding that check to what I do before packaging anything from this file - two crashes
in a row (pkg346 and now this) have both been of exactly this kind, and both got past a
clean build.


ALSO IN HERE FROM pkg350
-------------------------
The next activity box is prefilled with "Call", selects on click so typing replaces it, and
falls back to "Call" if emptied. "Done & set next" is no longer greyed out.
