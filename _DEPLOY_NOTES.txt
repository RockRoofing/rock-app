NOTHING FOR YOU TO DO DIFFERENTLY - I HAVE BEEN GUESSING
--------------------------------------------------------
You have refreshed both pages; that is not the problem. I have now assumed the
shape of these forecast records four times - matItems, then amount vs value, then
the bill suppression, then the legacy fields - and been wrong each time. The
honest thing is to stop assuming and look.

This package adds a panel at the top of the Cash Flow page:

    Forecast data check - what the saved records contain (N forecasts)

Click it. For each saved forecast it shows, straight from Redis:

    matItems              how many material lines, or "absent"
    1st mat line          pay:  amt:  val:  mode:  del:
    matDeliverDay         the legacy delivery date, if any
    materialsThisPeriod   the legacy total, if any
    labourSched           how many labour lines, or "absent"
    cost-ish keys         EVERY cost-related field name actually saved

That last column is the one that matters - it lists what is really in the record,
so we stop arguing about field names.


WHAT TO SEND ME
---------------
Open it, screenshot four or five rows for projects you KNOW have materials, and
send them over. From that I can tell in one look which of these it is:

  pay:NONE            the line has no payment date, so it can never land in a week
  amt:null val:0      the figure was never resolved
  matItems absent     legacy record - the fallback should be catching it
  a field name I have not accounted for at all

I would rather take one more round trip and fix it properly than ship a fifth
guess.
