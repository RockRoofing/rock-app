pkg348 - Mark done is instant now

WHY IT WAS SLOW
---------------
Completing an activity did the work first and updated the screen afterwards. For an
imported activity that meant TWO round trips before the row moved:

    fetch that deal's activities  ->  write them back  ->  only then remove the row

Plus the window stayed open until both had finished. So a couple of hundred milliseconds
each way felt like a hang.


NOW
---
The row disappears immediately and the window closes immediately. The saving happens behind
it. Nothing waits on the network.

If the save fails, the row is PUT BACK and the badge says "That activity could not be
marked done - it has been put back." So a dropped connection cannot leave you thinking
something was actioned when it was not.


ONE THING THIS NEEDED CARE WITH
--------------------------------
The tab refreshes itself every 60 seconds. Without a guard, a refresh landing while a save
was still in flight would fetch server data that did not yet include your change - and the
row you had just completed would flicker back onto the list.

The refresh now stands aside while any write is in progress. Briefly stale is fine; a row
reappearing after you have actioned it is not.
