pkg432 - three years of email volume
====================================

Deploy after pkg431. One changed file: pages/api/cron/crm-email-volume.js. No new files.

The month window was capped at 24. Asking for 37 quietly gave you 24 - which would have
looked like "the data does not go back further". Now capped at 60.


RUN THIS
--------
    /api/cron/crm-email-volume?months=37&mailbox=edita@rockroofing.co.uk

37 months = three years plus the current month. Re-running OVERWRITES the months it
recounts, so the year you already have is simply rewritten with the same figures. No
duplicates, nothing lost.

It should scan roughly 10,900 messages - her thirteen months scanned 3,815, so about 293 a
month including internal mail - against a cap of 20,000. Comfortable.

CHECK THE RESPONSE for "truncated". If it appears, add &max=40000 and run it again.


IF THE OLDER MONTHS COME BACK MISSING OR ZERO
-----------------------------------------------
That would be Microsoft, not us. Sent Items retention and archiving are Exchange settings -
if mail older than a certain age has been archived out of the mailbox, Graph will not
return it and there is nothing this code can do about it.

You will be able to tell the two apart: a month that is absent from byMonth was never
reached; a month present with 0 was reached and genuinely had no external mail. After
pkg409 a truncated run no longer writes zeros for months it did not get to, so an absent
month is honest rather than misleading.
