pkg295 - H&S Matrix: freeze the header row
===========================================

CHANGED FILES
-------------
  pages/operations/hs/hs-matrix.js

No new files. Straight replacement. Independent of every other package.


WHAT WAS WRONG
--------------
The first four columns (Employee, Company, Trade, Phone) were already frozen horizontally
- they use position:sticky with a left offset. The header ROW had no sticky positioning at
all, so scrolling down lost the training column names and left you looking at coloured
cells with nothing to identify them by. With the header being 150px tall and the labels
rotated at -60 degrees, there was nothing to orient by once it went.


THE FIX
-------
Sticky positioning sticks to the nearest SCROLLING ancestor. The matrix only scrolled
horizontally in its own box - vertical scrolling belonged to the page - so a sticky header
had nothing local to stick to. Adding top:0 alone would not have worked.

So the matrix box now scrolls in BOTH directions itself:

    overflow: auto, maxHeight: calc(100vh - 300px), minHeight: 320

and the header row is sticky at top:0 within it. Scroll down and the column names stay
put; scroll sideways and Employee/Company/Trade/Phone still stay put. Both at once works -
the four fixed headers hold the top-left corner.

The header row also got a solid background, so body rows cannot show through it as they
pass underneath.


TWO THINGS YOU WILL NOTICE
---------------------------
1. THE MATRIX NOW SCROLLS INSIDE ITS OWN BOX rather than with the page. That is what makes
   the freeze possible. The box is sized to the window (roughly the full height below the
   filters), with a floor of 320px so it never collapses to nothing on a short window.

   If it feels too short or too tall on your screen, the number to change is the 300 in
   calc(100vh - 300px) - larger number, shorter box. Tell me how it looks and I will tune
   it.

2. THE DATE EDITOR POPUP still opens above the frozen header when you click a cell near
   the top. I left it that way deliberately so the editor is never partly hidden behind
   the header - but if you would rather the header always stayed on top, that is a
   one-line z-index change.


TESTED
------
npm run build - Compiled successfully.
Layering checked: header above body cells, the four fixed columns above the scrolling
header cells, column-options menu still on top within the header.
