FIRST - HAVE YOU RECONNECTED?
-----------------------------
The message you got is the one I added, so pkg578 IS live and the scope has been
added to the authorize URL. But the error means the TOKEN still does not carry it.

Deploying the scope changes nothing on its own. The existing token was issued
under the old scope list and keeps exactly those permissions for ever. It has to
be re-authorised:

    Go to /connect  ->  click Connect/Reconnect Xero  ->  approve

If you have already done that and it still fails, the next section settles it.

ONE FRAGILITY WORTH KNOWING (not changed)
-----------------------------------------
pages/connect.js hard-codes the client id:

    const clientId = '934571EC178A488AAFFB4C7E8C4DDD43'

while the token exchange and every refresh use process.env.XERO_CLIENT_ID. They
must be the same app or the exchange fails outright with invalid_grant - so they
almost certainly are. But if that env var is ever pointed at a different Xero
app, the authorize step and the token step would silently disagree. Worth making
connect.js read from the env too, as its own small change.


THE FIX ITSELF (from pkg578)
----------------------------
accounting.invoices.read covers Invoices AND CreditNotes, which is why bills and
credit notes sync perfectly. Overpayments and Prepayments sit under
accounting.transactions, which was never requested. Added to connect.js.


ALSO IN THIS PACKAGE
--------------------
Cost account filter, remembered per browser. Credit notes and overpayments carry
lineCodes so they cannot vanish under a filter and push the total up. No Status
filter on overpayments - RemainingCredit > 0 is the real test. Type checked with
startsWith('SPEND') to match SPEND-OVERPAYMENT.

When it works: "117 bills, 1 credit notes, 4 overpayments." and the total drops
307,471.06 -> 302,771.49.
