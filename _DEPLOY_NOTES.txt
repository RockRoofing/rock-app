1. THE CARD
-----------
Now: total Retention Owed across ALL projects, less the 1st or 2nd Value of any
half marked released.

Two changes from pkg782:
  - it no longer nets off 612, it nets off the RELEASED HALVES
  - it is no longer limited to Live and Defects

Dropping the status filter is deliberate. A completed project with an unreleased
half is still money being held, and hiding it is how retention gets forgotten -
which is what this register exists to prevent.

"Released" means released1/released2 - a click on the cell OR a half ticked in
an application's retention section. Those are the same functions that colour the
cells, so the card and the rows cannot disagree.

  J244 live       owed 12,455   released      0  -> 12,455
  J197 defects    owed 16,530   released  8,265  ->  8,265
  J147 complete   owed 16,530   released 16,530  ->      0
  card                                              20,720

Floored per project, so a release larger than its owed figure cannot pull the
total down - that is a data problem on one row, not a credit against the others.

2. TOTALS ROW
-------------
At the foot of the table, sticky, so it stays visible however far you scroll.

Totals: Gross AFA, MCD, Final Account, Applied for, Invoiced, Account Remaining,
Retention Owed, 612 Deducted, 612 Released, VAT, Total Due, Total Paid, Total
Remaining - and the 1st / 2nd Value columns showing only the halves actually
RELEASED, matching the card.

It sums the rows CURRENTLY SHOWN, so it answers the filter you have applied. The
row count sits beside the label - "43 shown" - so a filtered total cannot be
mistaken for the whole register.

Cell count checked against the header: 28 and 28, so nothing sits under the
wrong column.
