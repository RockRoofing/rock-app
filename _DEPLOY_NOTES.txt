pkg790 - Why the netting never fired
=====================================

DEPLOY OVER pkg789 (contains pkg789). Fourteen files.

FOLDER NOTE: pages/project/[id].js uses LITERAL square brackets.

REPLACE:
  pages/api/sync-invoices.js        (changed here)
  pages/api/dashboard.js            (changed here)
  everything else as pkg789

THE CAUSE
---------
Xero's /CreditNotes LIST endpoint omits Allocations - the same reason it omits
LineItems, which the sync was already re-fetching one credit note at a time.

I only tested for missing line items. Allocations are absent even when the lines
ARE present, so allocatedTo came back empty on every credit note and there was
never anything to pair against. The netting in pkg789 was correct and simply
never ran.

TWO FIXES, SO IT WORKS EITHER WAY
----------------------------------
1. The sync now fetches the whole credit note when EITHER lines or allocations
   are missing, and keeps the allocations.

2. The dashboard falls back to matching on REFERENCE where a stored line has no
   allocation - a credit note reversing an application carries that
   application's reference, and it must also be an exact equal-and-opposite 612
   amount. Two coincidences at once is not a coincidence.

The second means lines already in the store net correctly without waiting for a
re-sync. Tested against J147 with allocations stripped out entirely:

  deducted 1,118.18   released 1,118.19   Retention Owed 1,118.19

WHAT TO DO
----------
Deploy, then hard refresh. The reference fallback should correct J147
immediately without a re-sync.

Then run Sync Invoices at 48 months when convenient - that picks up the real
allocations, which are more reliable than reference matching for anything where
the reference was edited or a credit note covers more than one invoice.
