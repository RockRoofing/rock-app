THE PATTERN IN YOUR SCREENSHOT GAVE IT AWAY
--------------------------------------------
Six projects showing labour and materials with NO sales at all - J242, J190, J244,
J240, J241, J230. Cost with no income against it, which is why the table read as
if half the jobs were pure expense.

    const hasInvoice = projNosWithInvoiceThisWk.has(String(fc.projectNo))
    const sIn = (hasInvoice || salesSpent(fc)) ? 0 : ...

ALL OR NOTHING. One unpaid invoice on a project in a week wiped out that project's
ENTIRE forecast sales for the week - any invoice, any amount.

This is EXACTLY the fault I fixed for BILLS in pkg618 and never applied to
invoices. I fixed one side of the same guard and left the other.

NOW NETTED, like the bills:

    forecast sales 20,859, real invoice 12,000  ->  forecast sales 8,859

The invoice is already counted in Invoices in, so only the part of the forecast it
covers comes out. Anything above it is work still to be billed. The allowance is
consumed, so one invoice cannot net against two different weeks.

Excluded invoices no longer suppress anything either - if you have taken an
invoice out of the forecast it should not be displacing forecast sales.
