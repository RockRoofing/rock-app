CONFIRMED, AND IT WAS WORSE THAN THE PAGE
===========================================
Pre-Start Minutes live in their own store, one record per project at
ops:prestart:{projectNo}, filled in from the project page. They are not a Site App
form and nothing ever writes them to the submission index.

Both places that check them looked in the submission index:

    subs.some(s => s.formTitle.toLowerCase().includes('pre-start'))

That test could only ever return false. So:

  FORMS MISSING showed every Pre-Start as Missing, however many had been completed.

  AND THE MONDAY CRON did the same thing - pages/api/cron/forms-weekly-notify.js
  uses the identical check, so every Monday the Contracts Manager was emailed
  "projects that require a Pre-Start Notification" listing Pre-Starts they had
  already done. That is the half worth fixing first: a page being wrong is
  irritating, a chaser that cannot be satisfied gets ignored, and then the real ones
  get ignored with it.

Both now read the actual store, through one shared rule in lib/preStartDone.js
rather than each growing its own.


WHAT COUNTS AS DONE
====================
SENT. A Pre-Start is complete once it has been issued - sentAt, or sentManually
where it went out another way and was marked off. That is the same line the project
page already draws: at that point the form locks and cannot be edited.

A Pre-Start saved as a draft and not sent still reads as Missing, which is correct -
it has not gone to anybody.

    never started                        missing
    saved as a draft, not sent           missing
    sent                                 done
    marked sent manually, no timestamp   done  (falls back to the last save)

On the Forms Missing page it is judged AS AT THE END OF EACH WEEK, so minutes issued
weeks ago count for every week since, while a week that closed before they existed
is not marked complete after the fact:

    Pre-Start sent 31 Aug, week ending 9 Aug   -> missing
    Pre-Start sent 31 Aug, week ending 6 Sep   -> complete
