THE FIX
========
The email read:

    ... mentioned you in a comment on a cost on
    Speedy Asset Services - 7307666662 - project fdbb2ec3-1cb7-498e-864a-82b63b6cf71d

`id` in that endpoint is the Xero tracking option GUID out of the address bar. I
used it as the project reference, which tells the reader nothing and reads like a
broken link.

It now says:

    ... mentioned you in a cost comment on
    J228 - Farmstead Drive - Speedy Asset Services - 7307666662

Same change in the subject line.


HOW THE NAME IS RESOLVED
-------------------------
Server-side, from the dashboard cache, which already holds jobNo and name against
xeroId. One read, and the name is not taken on trust from the browser.

The page also sends its own label as a FALLBACK, used only if the dashboard cache
has just been cleared - a sync or a retention save empties it, and an email landing
mid-rebuild should still name the job.

    cache hit                       -> J228 - Farmstead Drive - Speedy Asset Services - 7307666662
    cache empty, page label sent    -> J228 - Farmstead Drive - Speedy Asset Services - 7307666662
    cache empty, no label at all    -> project <id> - Speedy Asset Services - 7307666662

Only the last case can still show a GUID, and it needs the cache to be empty AND
the page to have no job number, which in practice means a project that is not in
Xero.
