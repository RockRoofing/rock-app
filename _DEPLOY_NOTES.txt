WHAT CHANGED
------------
lib/db.js gains three exports:

  getClient()   the shared data client - get / set / del / keys / scan.
                Same shape as an Upstash client, so call sites read identically
                to the direct connections they replace.
  del(key)      generic delete helper
  scan(c, o)    generic scan helper

The ten API files previously each opened their own connection to Redis and
built their own keys. They now ask lib/db.js for a client instead. Nothing else
about them changed.

WHY: when the app becomes multi-tenant, getClient() is the single place that
picks the right customer's database. Any file holding its own connection would
not follow, and would serve one customer's data to another. 39 files still do
this; they follow in pkg844-847.

SIDE EFFECT WORTH KNOWING: sync-status.js and hidden-projects.js used
Redis.fromEnv(), which only reads UPSTASH_REDIS_REST_URL / _TOKEN. If Vercel
holds the credentials under the KV_REST_API_* or kv_KV_REST_API_* names
instead, those two endpoints have been silently failing. Going through
lib/db.js, which accepts all three naming conventions, fixes that. So the
"last synced" stamps and the hidden-projects list may start working if they
were not before. That is the only thing in this package that could visibly
change, and only in the direction of working.
