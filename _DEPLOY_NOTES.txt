WHAT THIS DOES
--------------
Reads the four mailboxes in your CRM Sync Mailboxes group, matches each email to a project,
and files it. Runs hourly.

MATCHING, in order:
  1. project title appears in the subject
  2. sender or recipient is a known contact on a project
  3. sender or recipient domain matches exactly ONE project's company

Rule 3 only fires when the domain points at a single project. Two projects with the same
customer means no match, because a wrong project is worse than none. Free domains -
gmail, hotmail, outlook and so on - never match by domain.

Project titles shorter than 8 characters do NOT match by subject. Your "Tesco" project
would otherwise claim every email with Tesco in the subject. Tested: it does not.

Only OPEN projects claim email.


YOUR MAILBOX
------------
james@rockroofing.co.uk matches on RULE 1 ONLY - the project title in the subject. Never on
who the email is with.

Anything else from your mailbox is DISCARDED, not queued. It is never stored and never
appears in the review list. Tested both ways: an email to a known contact with a project
name in the subject is filed; the same contact without one is ignored entirely.

Set by MS_PRIVATE_MAILBOXES if you want to change who this applies to.


THE BACKFILL - IMPORTANT
-------------------------
The first run for each mailbox does the history. It is NOT automatic - you trigger it:

    /api/cron/crm-email-sync?backfillMonths=24&max=500

Unmatched historical email is DISCARDED rather than queued, as agreed - 79,000 unallocated
emails would have made the review queue useless. Only matched history is kept.

Start with max=500 to see it work on a small slice before running the full 24 months.

From then on the hourly run only asks for mail newer than its last run, and unmatched mail
DOES go to the review queue - a handful a day, which is workable.


TESTING FIRST
-------------
    /api/cron/crm-email-sync?dryRun=1&max=100

Reports per mailbox how many were fetched, matched, queued and discarded, and writes
nothing at all. Run that before anything else - it is also the quickest confirmation that
the Azure app, the secret and the access policy are all working.
