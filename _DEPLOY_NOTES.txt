THE BUTTON
===========
"Download PDF" in both places:

  PRE-CONTRACT   on the handover form, in the button row beside Meeting Complete
  OPERATIONS     top right of the Handover tab inside a project

Both produce the identical file, because both fetch it from the same endpoint.


BUILT FROM THE SCHEMA, NOT FROM A LIST OF FIELDS
--------------------------------------------------
The PDF renders lib/ihmSchema.js - and the CUSTOM template from admin/templates
where one has been saved, resolved exactly as /api/templates does it for the form.

That matters more than it sounds. A hand-written list of fields in the PDF would go
stale the first time somebody added a question in admin/templates, and nobody would
notice until a handover went out with a section missing. Verified by building one
against a template with an extra section bolted on: the new question appears with no
change to the PDF code.

It also means the PDF asks the same questions the meeting worked through, rather
than the stock schema.


EMPTY FIELDS ARE PRINTED, NOT SKIPPED
---------------------------------------
This is the record of a meeting. "Has the warranty period been confirmed? -" is a
finding. Dropping unanswered fields would make the document read as though the
question was never asked, which is the opposite of what a handover record is for.

Unanswered values print as a grey dash so they are distinguishable at a glance from
answered ones.


DETAILS
--------
It prints the SAVED record, not what is on screen. On the Pre-Contract form the
button is greyed until there is a project number to fetch by, and says so if you
press it early - before the first save there is nothing stored to print.

Repeatable sections each get their own layout: site contacts as one line per person,
roof types as a block per type, the risk log numbered, checklists as one line per
item with its Yes / No / N-A answer.

Text wraps inside the value column, so a project address or a long note stays in its
column instead of running across the page.

Smart quotes and dashes pasted out of Word are converted. pdf-lib throws on anything
WinAnsi cannot encode, and a curly apostrophe should not fail a download.

A failure returns JSON, not a half-written PDF - otherwise the browser saves a broken
file and there is nothing to say what went wrong.

Verified against: an entirely empty handover, null data, Word punctuation, a
half-answered checklist, an empty contacts array, a field holding an unexpected
object, and a customised template. All produce a document.
