pkg492 - "CR not locked" on a project whose rates ARE locked
============================================================

Deploy after pkg491. One changed file: pages/applications.js. No new files.


THE CAUSE
---------
The Upcoming Applications table is fetched ONCE, when the page first loads.

Contracted rates are locked on a DIFFERENT page. Lock them, come back here, and you are
looking at the state as it was when this page loaded - so a project you have just locked
still reads "CR not locked", and the row stays blocked.

Nothing was wrong with the lock. I checked the save path: it writes locked:true to the
project and clears the dashboard cache. The data was right and the screen was old.


FIXED TWO WAYS
--------------
IT REFRESHES WHEN YOU COME BACK. On window focus and when the tab becomes visible again,
which covers returning from Contracted Rates whether you opened it in this tab or another.

AND THERE IS A RECHECK LINK on the blocked row itself, beside the warning:

    CR not locked  Recheck

That matters because this warning BLOCKS the row - no application number, no date, no way
to raise it. A blocked row with no way to clear it except reloading the page is the sort
of thing people work around rather than report.


IF RECHECK DOES NOT CLEAR IT
-----------------------------
Then the rates genuinely are not locked, and the message is right. Two things it
distinguishes between:

    "CR not set up"   no contracted rates on the project at all
    "CR not locked"   rates are there, the Lock has not been pressed

The second is the common one - rates uploaded and edited, but never locked, which is also
what stops them populating the contract value and budgets.
