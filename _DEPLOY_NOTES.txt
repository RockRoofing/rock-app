pkg448 - editing an activity date did not stick
===============================================

Deploy after pkg447. One changed file: pages/crm.js. No new files.


THE CAUSE - A RACE, WHICH IS WHY IT WAS INTERMITTENT
------------------------------------------------------
The Activities list refreshes itself every 60 seconds and whenever the window regains
focus. That refresh REPLACES the whole list with what the server currently holds.

Completing an activity was protected against this - it raises a "writing" flag, and the
refresh skips while it is set. EDITING one never raised that flag.

So the sequence was:

    1. change the date, press Save
    2. the write goes off to the server
    3. the 60-second refresh lands before the server has caught up
    4. the list is replaced with the OLD date

Whether it stuck depended entirely on where you happened to be in that 60-second cycle.
Which is exactly "more often than not it doesn't change, so I go in again" - and trying
again eventually worked because eventually you missed the refresh.

Editing now raises the same flag as completing.


AND A SECOND REASON THE VIEW DID NOT CHANGE
---------------------------------------------
For a MANUAL activity - one created in the CRM rather than imported - the edit updated the
deal record but never told the Activities table. The table reads its own list, so the row
sat there showing the old date until the next refresh brought it round.

It now updates both, so the row changes the moment you press Save.

Imported activities were already doing this, which is probably why the two behaved
differently.


ALSO
----
The due date is now written to both field names the store uses. It was writing only one
of them - harmless as things stand, since the reader checks that one first, but it would
have bitten the moment anything wrote the other.

And a failed save now says so with an alert, rather than only appearing in the browser
console where nobody looks. If a date genuinely will not save you will know immediately
instead of assuming it is the same intermittent fault.
