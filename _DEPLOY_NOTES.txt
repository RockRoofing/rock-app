ROOT CAUSE - PIPEDRIVE CHANGED THEIR EXPORT FORMAT
---------------------------------------------------
The mappers were built in July against exports whose columns were PREFIXED with the
entity name:

    Deal - ID        Organization - Name        Person - Email - Work

Your current exports drop the prefix entirely:

    ID               Name                       Email - Work

So detectExportType() matched nothing and every file was refused. Not just activities and
notes - deals, organizations and people had stopped working too, for the same reason. That
is why all five failed at once when three of them imported fine in July.

Nothing was wrong with your files. Every field still exists; they are simply named
differently.


THE FIX
-------
Rather than swap to the new names and break the old ones, every column is now looked up by
its full name FIRST and then by the name with the leading "<Entity> - " stripped. Both
formats map identically, and it will keep working if Pipedrive changes back.

Detection handles both too. The unprefixed exports all start with a bare "ID", so they are
told apart on columns unique to each - deals checked first, because a deals export also
contains an "Organization" column and would otherwise be mistaken for one.

notes afterwards.
