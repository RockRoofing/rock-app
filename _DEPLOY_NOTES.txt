pkg493 - the contracted rates lock was being silently reverted
==============================================================

Deploy after pkg492.

CHANGED FILES (replace)
-----------------------
  pages/api/project/[id]/settings.js     <- literal [id] folder
  pages/project/[id].js                  <- literal [id] folder

NEW FILES: none.


I WAS WRONG IN pkg492
---------------------
I said it was a stale screen. It was not - the lock really was being turned back off.


WHAT WAS HAPPENING
------------------
/api/project/[id] returns the WHOLE project record as "settings" - including
contractedRates and applications.

The Project Details form loads that, and on save posts the whole thing back. The settings
endpoint merges whatever it is given. So:

    1. lock the contracted rates            locked = true
    2. save Project Details from a page
       loaded before the lock               posts back its stale copy
    3. merge overwrites contractedRates     locked = false again

Applications then correctly refused to create one. The contracted rates page still SHOWED
them locked, because it was holding its own state - which is why it looked like the app
was wrong about a lock that was plainly there.

Anything saved from Project Details would do it: a date, the MCD, an estimator.


FIXED IN BOTH DIRECTIONS
------------------------
The endpoint now REFUSES contractedRates and applications whatever it is sent - they are
owned by their own pages. Everything else merges exactly as before.

And the form no longer sends them, so the situation does not arise.

Applications is on that list for the same reason and it is the more serious of the two: a
stale copy posted back from Project Details would have undone a certificate.


AFTER DEPLOYING
---------------
Go to Contracted Rates for that project and press Lock once more. The lock will hold this
time. Then the application will create.

Worth checking any other project that has refused an application recently - the same thing
will have happened to it.
