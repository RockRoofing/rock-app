1. "RECONCILE: ALL ACCOUNTS VS SHOWN" NOW STARTS TICKED
-------------------------------------------------------
It is the only thing policing the hide-accounts feature. Hide a row that still
carries money and the year-end total silently understates, with nothing on screen
to say so - which is exactly the sort of fault you only find months later.

Cheap to leave on: it computes from data already loaded, saves nothing, and adds
one line to the toolbar. And it is useless if it happens to be off at the moment
the problem appears.

  green + matching figures  ->  every hidden account projects to nil
  red + different figures   ->  a hidden account still has money in it, and the
                                totals on screen understate the year by the gap

Two limits worth knowing: it compares TOTALS, so it would not catch hidden
accounts whose positive and negative values cancel out (unlikely on overheads),
and it works off the displayed year, so an account hidden but only active in
another year will not register.


2. ALSO IN THIS PACKAGE - SWITCH TO ACTUAL (was pkg563)
--------------------------------------------------------
Budgets used to swap a month from forecast to Xero actuals the moment it rolled
over:

    const isComplete = (mo) => mo < thisMonth && availableSet.has(mo)

On the 1st, almost nothing is posted, so the figure collapsed and then crept back
up over the following weeks as bills came in.

Now a month uses actuals only when you say so. Once it has ENDED a "Switch to
Actual" button appears under its column heading and STAYS there until pressed, so
an un-switched month is visible rather than quietly still on forecast. Pressing
it turns the header green with a tick; pressing again goes back. Disabled with an
explanation if there are no Xero figures for that month yet.

This also fixes the forecast methods. Avg this FY, Last 3 mo, Last full month and
Avg last financial year all derive from "completed" months, so they were
averaging in a month that was one day old and 5% posted. They now only use months
you have switched.

ON FIRST LOAD NOTHING MOVES. The config key has never been written, so every past
month with data is treated as already switched - exactly the old behaviour. You
then un-switch anything you want back on forecast. Without that, every method
that averages history would have found no completed months and the grid would
have read zero on deploy.

null (never set) is deliberately kept distinct from [] (everything switched off on
purpose); an `|| []` would have collapsed the two and re-seeded the defaults every
time you switched the last month off.


NOT CHANGED
-----------
The two summary cards at the top - last 3 completed months' spend and average -
still read straight off Xero for any past month, switched or not. They report
actual spend rather than replacing a forecast. The same half-posted-month problem
applies to that average, so say the word if they should follow the switch too.
