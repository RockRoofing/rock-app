WHY THEY WERE ZERO
------------------
Not one cause. Three.

1. RECEIVED DATE WAS HARD-CODED NULL
   All three metrics are dated by the day a project first entered Received. The adapter
   set receivedDate to null for every deal, with the comment "not in the export". So all
   three filtered to nothing, every month. This was the main cause.

   Received date is not a field on a deal - it is a fact about a stage TRANSITION, so it
   only exists if something was watching when it happened. Pipedrive's webhook was
   watching for years. The CRM import was a snapshot: what each deal looks like NOW, not
   how it got there.

2. PROJECT SCORE WAS HARD-CODED NULL
   "Scored 5 or more" reads it. Even with the date fixed it would have stayed zero.
   The CRM has a project_score field, but the Pipedrive import never mapped it, so it is
   blank on imported deals.

3. THE "PRICED" RULE DID NOT MATCH WHAT YOU DESCRIBED
   Coded: received this month AND has a value now.
   Yours:  got a value for the FIRST time, dated by the month that happened.
   Those differ whenever pricing lags the enquiry - which is normally.


WHAT IS FIXED
-------------
Received date now comes from two places, merged:
  - DERIVED from CRM stage history - correct from the day the CRM went live. Takes the
    FIRST entry into Received, so a project that passes back through later is not
    re-dated.
  - SEEDED from the Pipedrive-era record - the years before that.

Project score now maps from the deal's project_score field, falling back to the seeded
value.

Glenigan priced rewritten to your definition: a value-change record where the old value
was zero and the new one is not, earliest such record only, counted in the month it
happened.

Your other two points were already right and still are: lead source and score are read as
they stand TODAY, so a project marked Glenigan or scored after it was received still
counts, dated by when it was received.


RUN THE SEED - NOTHING WORKS WITHOUT IT
---------------------------------------
The seed button now does BOTH jobs: value-change history and received dates/scores.

    fetch('/api/value-changes-crm',{method:'POST',headers:{'Content-Type':'application/json'},
      body:JSON.stringify({action:'seed'})}).then(r=>r.json()).then(console.log)

Returns counts for each. Safe to run twice.

Until you run it, historical months stay at zero - the CRM genuinely does not know when
those projects were received, and no code can invent it.
