WHAT WAS WRONG
--------------
The pop-out only ever looked at previous FORECASTS:

  const prev = (d.hypApps || []).sort(...).pop()

It never read the project's real applications at all. So on a live job that had
been applied for three times, opening a new forecast started every rate line at
0% - as though nothing had been built - and you had to key the whole position in
by hand.


WHAT IT DOES NOW
----------------
A new forecast seeds its percentages, MCD and retention from the latest REAL
application on the project. With no applications, it starts from the contracted
rates at 0%, as before.

The API now returns `latestApplication` - the highest-seq application on the
project record, trimmed to just the fields the seed needs (the full contractWorks
tree is large and none of the rest is wanted here).


ONE DECISION YOU MAY WANT TO OVERRULE
-------------------------------------
You said "latest application, else contracted rates". Taken literally that breaks
the second forecast on a project.

  Application 3 certifies at 40%.
  You forecast April -> 60%.
  You then open a forecast for May.

Seeding strictly from the application would drop May back to 40% and silently
undo April. So the rule I have built is WHICHEVER PERIOD ENDS LAST - the latest
application, or a later forecast if one exists. A tie goes to the application,
since that is the certified position.

With no forecasts at all - your case - it is exactly what you asked for.

Say the word if you want it strictly the application every time.


DETAILS WORTH KNOWING
---------------------
DRAFTS COUNT. The latest application is by seq, whatever its status. A draft is
still the most recent view of percentage complete and this is a forecast. The
banner names the application and its status so you can see which was used.

ROWS MATCH ON ID THEN CODE. A real application's rows come from the same
buildContractWorksFromRates() as the seed, so ids normally line up. If the rates
have been re-uploaded since, they will not - and the code is then the only stable
handle. Without that fallback every line would seed at 0% and look like a job
that had never started.

NEGOTIATED PROJECTS (N:<dealId>) are not in Xero and have no real applications,
so they still start from contracted rates. Unchanged, and correct.

The project record is now read ONCE for both the rates and the applications,
rather than the rates lookup fetching it on its own.


ALSO FIXED WHILE IN THERE
-------------------------
This modal closed on a backdrop click and had no Escape handler - against your
standing rule, and it holds a period, percentages across every rate line,
materials lines and payment terms. A stray click outside it threw the lot away.
Backdrop click no longer closes; Escape does.


ON SCREEN
---------
A line at the top of a new forecast says where the percentages came from:

  blue   "Percentages carried over from Application 4 (sent) - the latest
          application on this project."
  blue   "Percentages carried over from the previous forecast, which runs later
          than the last application."
  amber  "No applications yet - starting from the contracted rates at 0%."

Without it a seeded figure and one somebody typed look identical. It does not
show when editing an existing forecast, which loads its own saved values.
