WHAT THIS FIXES
---------------
This is the fix we agreed at the START of this session and I never shipped. I
described it, you approved it, then we moved to the P&L work and it was left.
Everything built since has been sitting on top of the flip.

The cash flow read receivables from dashboard:cache when that key existed, and
from bank:outstanding-receivables when it did not. Two sources, one number, and
which one you got depended on whether anyone had opened the Dashboard in the last
four hours. That is why the opening balance moved on its own and moved back on
its own.

The cache rows were built WITHOUT a type field. The guard downstream read
`i.type && i.type !== 'ACCREC'` - and an ABSENT type makes that test pass. So
every row went through, supplier bills included, counted as money in and swept
into "Overdue - brought forward".

NOW
---
Receivables come from bank:outstanding-receivables. Always. That store is a
direct Xero pull with Type=="ACCREC" inside the WHERE clause plus a defensive
post-filter, so it cannot contain bills.

dashboard:cache is still read, but ONLY to put a project name against a row.
Labels may improve when it is warm. No figure changes either way.

Guards inverted throughout: `i.type !== 'ACCREC'` now EXCLUDES an untyped row.
The old test let it through - it failed open, which is how this kept returning.
arrInvList and overdueIn had no guard at all; both have one now.

ABOUT MY EARLIER "STORE AUDIT"
-------------------------------
It reported zero supplier bills and I treated that as settled. It was a weak
test: 122 known bill IDs against 1,048 invoice rows. bank:outstanding-bills only
holds CURRENTLY outstanding bills and costs:bills only holds tagged ones, so any
paid or untagged supplier bill had nothing to match against. A negative from
that test meant very little and I should not have reported it as a clean bill of
health.

EXPECT THE LEDGER TOTAL TO MOVE - THIS IS THE FIX WORKING
----------------------------------------------------------
The two sources had different SCOPE, not just different type-safety:

  dashboard:cache            project-linked invoices only
  bank:outstanding-receivables   EVERY outstanding ACCREC, tagged or not

So the total should go UP by the value of outstanding sales invoices that carry
no project tag in Xero, and DOWN by any supplier bills that were wrongly in
there. It should now tie to Xero's Aged Receivables.

If it moves DOWN overall, that is worth telling me about - it would mean genuine
sales invoices are missing from the store, which is a different problem.
