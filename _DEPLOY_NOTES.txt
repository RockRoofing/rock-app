ROOT CAUSE
----------
An off-by-one in the table's declared width.

FIVE meta columns are drawn on every row - Employee, Company, Trade, Phone, Email - but
the width was calculated as if there were four:

    minWidth: NAME_W + META_W * 3 + columns.length * COL_W      (Employee + 3 metas)

With 36 training columns that declared 3,986px while the content actually needs 4,106px -
short by exactly 120px, one meta column.

The training cells still DREW past that point, because each cell has its own fixed width
and simply overflowed. But the ROW element itself stopped at the declared width, and the
row striping and bottom borders are painted by the row - so they stopped 120px early while
the cells carried on. That is the ragged right-hand edge in your screenshot.

The header looked fine only because each header cell paints its own orange background, so
the overflow still looked filled in. It was actually the same width all along.

FIXED: the width now counts META_W * 4, so the rows are as wide as their contents and the
striping, borders and hover area run to the final column.


ALSO FIXED - THE CELL EDITOR WAS BEING CUT OFF
-----------------------------------------------
Visible on the right of your screenshot: the date / "Does not expire" / Attach file panel
runs off the edge and the Save button is unreachable on the last columns.

It always opened to the RIGHT of the cell, which falls outside the scroll box on the last
couple of columns. It now opens to the LEFT for the final two columns, so the whole panel
and the Save button stay on screen.
