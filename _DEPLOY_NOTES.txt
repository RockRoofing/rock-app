pkg314 - New companies and contacts now reach the Companies / Contacts pages
=============================================================================

REPLACES pkg302 through pkg313. Deploy this one only.

CHANGED FILES
-------------
  pages/crm.js            creates the records, plus a catch-up for existing ones
  pages/api/crm.js        new upsert-org / upsert-contact
  lib/crmImportMap.js     unchanged since pkg305


WHAT WAS HAPPENING
-------------------
Both pages switch behaviour once an import exists:

    if (orgsData.length) { rows = orgsData.map(...) }    // imported list ONLY
    else { ...derive from deals... }                     // pre-import fallback

Before you imported, a new company on a project appeared automatically. After the import,
the imported lists became the source of truth and anything existing only on a deal was
invisible - so new business added since would quietly never appear on those pages.


NOW
---
1. CREATING A PROJECT. Everything typed into the "new contact" and "new customer" panels
   on that form is written as a proper record - company name, address, phone, website,
   email, registration number, supply chain approved; contact name, phone, email, job role.
   They appear on Companies and Contacts straight away.

2. EDITING THE PROJECT AFTERWARDS. Changing any of those fields on the deal keeps the
   master lists in step, so a phone number added later is not stranded on the deal. You
   asked for both, and the second is the one that would otherwise have been missed.

3. CATCH-UP FOR WHAT IS ALREADY THERE. Any company or person that currently exists only on
   a deal is now listed as well, with whatever details the deal holds. So anything added
   between the import and this deploy turns up without you doing anything.


MERGING RULES - THE IMPORTANT BIT
----------------------------------
Matching is on name, case-insensitive, so "wates construction ltd" updates the existing
"Wates Construction Ltd" rather than creating a duplicate.

A BLANK NEVER OVERWRITES SOMETHING ALREADY RECORDED. If a company has a phone number from
the import and someone creates a project leaving that box empty, the number stays. Without
that rule, a half-filled project form would quietly strip detail off an established
customer record - which would be much worse than the original problem.

Verified: existing phone kept when the new value was blank, new website added, matched
despite different capitalisation, no duplicate created.


WORTH KNOWING
-------------
Records created this way are tagged addedInCrm, so they can be told apart from imported
ones later if you ever want to - for example to review what has been added since cutover.

This also feeds the Activities tab: customer email and phone there are looked up from the
Contacts list, so a contact created via a project will now show its details rather than
dashes.

CAUTION AT CUTOVER: company and contact imports are still wipe-and-replace. Re-importing
either export will remove records created in the CRM. Once you have cut over from
Pipedrive that stops mattering, but until then, avoid re-importing those two after adding
projects by hand - or tell me and I will make those imports merge rather than replace.
