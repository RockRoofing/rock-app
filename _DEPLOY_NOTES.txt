pkg333 - Activities tab shows everything by default

REPLACES pkg302 through pkg332. Deploy this one only.

-------------
  pages/crm.js            default project scope
  pages/api/crm.js        unchanged since pkg332
  lib/crmImportMap.js     unchanged since pkg305


WHAT IT ACTUALLY WAS
---------------------
The project scope. Your activity was on a project marked lost, and the tab was only listing
open projects (pkg317), then open + won (pkg330). It was saved, it was in the right store,
the table built the row - and then a display rule dropped it before it reached the screen.

The tab now defaults to ALL PROJECTS. Narrow it with the dropdown when you want to - Open,
or Open + won - and the tab says which scope is active and how many rows that is holding
back.

The principle I got wrong: hiding rows by default cost far more than the noise it saved.
An activity vanishing looks exactly like an activity that failed to save, and there is no
way for the person looking at it to tell the difference.


WHAT WAS WORTH KEEPING FROM THE LAST FEW PACKAGES
---------------------------------------------------
Several were real faults, found while chasing this one:

  pkg321  hooks after an early return - crashed every deal and Add Project (React #300)
  pkg323  imported records being written back into the deal, inflating every save
  pkg325  a background load cancelling a pending save, losing the change outright
  pkg326  the whole 6.4MB deals list being sent on every save, over Vercel's 4.5MB limit
  pkg327  the baseline and payload disagreeing, so the first save still sent everything
  pkg331  activities in two stores
  pkg332  notes in two stores

Those all needed fixing. But none of them was the reason your activity was invisible, and
I should have separated "is it saved?" from "is it displayed?" much earlier. Your screenshot
answered that in one line - "Rows built: 1024, of which 1 added in the CRM" - and I kept
fixing the save path after it had already told us the save was fine.


NOTHING ELSE OUTSTANDING ON THIS
---------------------------------
Add an activity anywhere, on any project, and it appears in the tab. The one remaining item
on my list is the 6.4MB deals payload on page load, which is a speed matter, not a
correctness one.
