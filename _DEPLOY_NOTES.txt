pkg518 - fixes the Variation Builder crash
==========================================

Deploy after pkg517. One changed file: components/VariationBuilder.js. No new files.

URGENT - pkg517 broke the builder. This is the fix.


THE CAUSE
---------
I added raisedAlreadySent as a useMemo, and put it ABOVE the const it reads:

    const raisedAlreadySent = useMemo(() => {
      const v = (project?.variations || []) ...          <- project
    }, [project, editingVar])

    ...

    const project = useMemo(...)                          <- declared 700 characters later

useMemo runs its callback DURING RENDER, so `project` was still in the temporal dead zone
and every render of the builder threw a ReferenceError.

It compiled cleanly because nothing can know at build time that a const declared later
would be read earlier. Same class of fault as pkg474 and pkg495 - the build catches
neither.


FIXED
-----
Moved directly below `project`, where its dependency exists.

And I checked the rest rather than fixing the one: every useMemo in the file now sits
after everything it reads.

    projects (prop) -> project -> raisedAlreadySent -> existingVars
    -> nextSentNumber -> totals -> customerOptions

That ordering check is the one worth keeping. A memo reading something declared below it
is invisible to the compiler, invisible to the prerender, and only shows up when somebody
opens the page.
