FIX 1 - Weekly Labour Allocation showed an operative CODE (usr_...) instead of their name
Some operatives showed as "usr_1785..." on the weekly report. Cause: the report read names
from a legacy roster store where those operatives had no first/last name. It now resolves
names from Site App Users (the source of truth) first, falling back to the roster, then a
name field, and only using the code as a last resort. Those operatives will now show their
proper names (as long as they have a name on their Site App User record).

FIX 2 - Selecting an installer in the Planning filter threw:
"Application error: a client-side exception has occurred"
Cause: the filter assumed every day's allocation was a plain list, but some are stored as an
object ({entries, status,...}); calling .some() on the object crashed the page. The filter now
reads entries safely for both shapes, so selecting an installer works.
