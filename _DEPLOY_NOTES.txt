LIKELY ROOT CAUSE
The weekly report sends fine when you press Send (that path skips the schedule and just sends).
The SCHEDULED send runs from an hourly Vercel cron (/api/cron/weekly-report). The site's
middleware was gating ALL /api/cron routes behind CRON_SECRET: if a CRON_SECRET is set in the
environment and doesn't exactly match what Vercel sends, the middleware returns 401 and the cron
never reaches the send logic - every hour, silently. That would stop the scheduled send while
manual send still works (manual doesn't go through the cron).

FIX
The middleware now also trusts Vercel's own cron header (x-vercel-cron), which Vercel sets on
every scheduled invocation. So the scheduled crons run even if CRON_SECRET is mismatched or
rotated. (The existing CRON_SECRET / ?key= checks are kept as-is for manual/browser testing.)

HOW TO VERIFY AFTER DEPLOY
1) Confirm the schedule is set: Outstanding Invoices -> report settings -> pick the Day + Hour
   you want, and Save.
2) Test the LOGIC now (doesn't wait for the day/time): use the "Test schedule" button - it shows
   a diagnostic of what the scheduler sees (today's UK day/hour vs the wanted day/hour, and when
   it last sent).
3) Test an ACTUAL send immediately: open this URL in your browser while logged in -
      https://app.rockroofing.co.uk/api/cron/weekly-report?force=1
   It should send the report now and return JSON. (If you have a CRON_SECRET set and it asks for
   auth, add &key=YOUR_CRON_SECRET.)
4) Leave it until the next scheduled day/hour and confirm it arrives automatically.

IF IT STILL DOESN'T FIRE ON SCHEDULE

code. Check Vercel -> Project -> Settings -> Cron Jobs to confirm /api/cron/weekly-report is
listed and enabled, and Vercel -> Deployments -> Cron logs for hourly runs. Tell me what the
cron log / the ?force=1 URL returns and I'll take it from there.
