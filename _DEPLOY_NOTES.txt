1. WHY CERTIFIED STILL WAS NOT PULLING THROUGH - ROOT CAUSE
------------------------------------------------------------
The dashboard read applications from ONE settings record:

    const settings = allSettings[id] || allSettings[cp.jobNo] || {}
    const apps = settings.applications || []

Project settings are keyed by tracking option id OR by job number, and TWO records
can exist for one project. That line takes whichever matched first. Applications
written against the job-number record are invisible whenever an id record also
exists.

This is the identical fault that produced "V01 and V02 are not showing". It was
fixed for variations lower down the same file and never for applications.

It explains all three symptoms at once, and explains why they were intermittent:

  - Certified blank            (no latestSent found, so the box was never read)
  - Applied for not matching    (fell back to whatever was typed on the row)
  - Final Account from project details instead of the application

Applications are now read from BOTH records and merged. Keyed on the permanent
appNumber, then seq, then id. Where both records hold the same application the SENT
one wins, then the one carrying more contract works. Nothing is dropped and nothing
was lost - we were reading the wrong record.

This is the fix I expect to close the Certified item. If any row is still blank
after this, open the Applied for drill-down: it now reports how many applications
were found and how many are sent.


2. FINAL ACCOUNT AND GROSS AFA NOW PRIORITISE THE APPLICATION
--------------------------------------------------------------
retention.js line 652 read:

    finalAccount: e.finalAccount || x.finalAccount

so a figure typed once beat the application permanently - the same fault Applied
for had in pkg792. Both account columns now take the sent application first, and a
typed value is used only where there is no sent application.

  sent app exists, value typed on row -> application wins
  no sent app, value typed            -> typed value
  no sent app, nothing typed          -> project details


3. FINAL ACCOUNT - MCD NOW GOES WHERE PROJECT DETAILS PUTS IT
---------------------------------------------------------------
Your definition: Gross AFA including retention, less MCD, with MCD applied as set in
Edit Project Details - before or after variations and materials.

The register was doing:

    mcdValue = afaBeforeMcd * (mcdPct / 100)      // the WHOLE account

That is only right where MCD applies to everything. Where Edit Project Details says
MCD comes off measured works only, it over-discounted, and everything computed from
the Final Account came out low - Account Remaining, Total Due, and the retention
charged on the account.

On 800,000 measured + 200,000 variations at 2.5%:

    MCD on measured + variations   ->  975,000.00   (unchanged)
    MCD on measured only           ->  980,000.00   (was 975,000.00, out by 5,000)

Where there is a sent application the Final Account is now taken straight from it
(sentSum.finalSubTotal), so the register and the certificate cannot drift. lib/
applications.js already computed this correctly and simply did not return it - it
does now. Where there is no application, the same split is applied using the
placement flags from project details.

The drill-down shows which basis was used on every row.


4. APPLIED FOR - LOGIC CHECKED, ALREADY CORRECT
------------------------------------------------
Your definition: gross measured works less MCD, plus instructed variations and
materials - or gross measured works plus instructed variations and materials less
MCD - depending on Edit Project Details.

lib/applications.js implements exactly that:

    mcdBaseCur  = measuredToDate + (mcdOnVars ? variationsToDate : 0) + (mcdOnMos ? materialsOnSite : 0)
    afterMcdCur = (mcdOnVars ? 0 : variationsToDate) + (mcdOnMos ? 0 : materialsOnSite)
    netBeforeRet = (mcdBase - mcd) + after

and Applied for reads current.netBeforeRet. Instructed-only is enforced by
isInstructed(). No change needed - it was only ever failing because the application
itself was invisible, per item 1.

ONE THING TO BE AWARE OF, not changed here. The placement flags default differently
in two places: lib/applications.js treats a missing flag as TRUE (MCD applies),
while pages/api/applications.js stamps `project.mcdOnVariations === true`, so a
missing project setting becomes FALSE. An application created before these flags
existed therefore computes with MCD on everything. Changing that default would move
certificates that have already gone out, so I have left it - but if you have old
projects where the MCD looks wrong, that is the reason and it is a one-line change.
